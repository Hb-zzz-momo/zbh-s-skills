# 项目结束后的沉淀整理

目标是下次找得到、看得懂、用得上，并减少已证明多余的副本。不能只建空文件夹、写建议或再复制一份完整项目就宣布整理完成。

## 定位与边界

- 先核真实项目根、结束范围和落点；当前聊天目录、同名空目录、子项目不自动是同一个目标。活动结束不代表其中的开发项目也结束；仍在编辑/运行的单元留原位，先索引。已有归档先读其README/清单核验现状；只整理新材料，不嵌套生成“项目沉淀/项目沉淀”或重搬同一批资产。
- 使用 `project-structure-architect` 检查现有结构；活动档案不套科研/网站脚手架。按用户要求选择专用归档结构，说明适配理由并人工审计职责、唯一位置、依赖与入口。
- 历史只读恢复沿用已有记忆入口，不初始化新库。复用 `artifact-curator-zh` 的清理能力，不另写删除器；过程经验用已有反思技能接入同一份收尾记录。
- “整理/试用”覆盖任务内可恢复迁移；删除授权按当前指令和已适用授权单独判断。缺授权时先做到可审的精确清单，再问一次最终动作。不要重复索要已有授权。
- WPS/OneDrive 中移动、改名、删除可能同步到云端。只报告本次本地结果；不能声称云端也已完成，或把删同步文件当作仅释放本机缓存。

## 先盘点，再设计

运行 `scripts/archive_project.py scan --root <项目绝对路径> --out <项目外临时目录>/inventory.json`。输出目录先确定唯一用途，不覆盖已有报告；扫描包括隐藏文件、工程缓存、压缩包与空目录，不静默排除大目录。读取失败/重解析点明确列出，未覆盖的目录不能当空目录。哈希可能让云端文件下载到本地，空间不足时先报告，不能只扫小文件声称完整。Windows 深层目录报“找不到路径”时先核长路径读取限制，不能当作文件不存在；禁止为绕过失败而隐藏缓存目录、改系统设置或放松链接保护。

根据盘点形成一份 `plan.json`（格式见[执行与恢复](references/operations.md)），同时写下范围、分类、保留理由与验收标准。建议落点是项目根下唯一的 `项目沉淀/`；已存在等价目录则复用。下面是可裁剪的职责，不要求每个项目都有全部目录：

| 类别 | 放什么 | 不可混淆 |
|---|---|---|
| 01_交付成果 | 有验收/提交依据的成品、交付说明 | 依据不足用“交付候选_待确认”，列清来源和待定项 |
| 02_源码与工程 | 整个源码工程、环境/锁文件、启动说明、必要数据与许可证 | 不把程序的 DLL、资源、Unity `.meta` 拆进图片目录；不改工程内部布局 |
| 03_资料与模板 | 题目、要求、原始资料、授权、参考与模板 | 原件和修改稿区分，外链记访问/导出状态，不伪造离线副本 |
| 04_图片与设计 | 原始照片、Logo、可编辑设计与必要导出 | 设计源稿和印刷成品都有保留价值，格式不同不是重复 |
| 05_过程与版本 | 旧方案、非同字节版本、工作记录、原始评审与失败证据 | 不能用最新日期、final/v2/旧版字样裁决最终版本或可删性 |
| 06_复盘与交接 | 有来源的经验、决策、遗留问题、下次行动、接班入口 | 推测标建议；无证据的效果/责任人/截止日不补造 |
| 07_内部协作 | 报名/签到/志愿者、财务与内部协作材料 | 本地整理不授权公开；README 只写受限指针，不抄个人明细 |
| 99_归档记录 | 原清单、迁移计划/日志、路径映射、校验、独立评审与清理账本 | 不塞一份完整镜像、全量ZIP或可重建测试垃圾 |

根 `README.md` 写用途、快速入口、版本状态、源码启动/未验证边界、缺失材料、内部使用范围和恢复办法。已有 README 不覆盖。用**相对链接**让沉淀目录能整体搬走。

## 版本与占用取舍

1. 按主题建立 `版本说明.md`：现行/候选/历史/无法裁定，来源、差别、保留原因、是否已提交/已运行分别记录。相同后缀/近似文件名只用来找候选。
2. 同字节副本用 size+SHA256 分组，但仍检查用途、路径依赖、原始截图、证书、失败证据、交付引用与保留者。不得全项目逐文件去重工程依赖，或把同内容许可证删成“多余”。
3. ZIP 与解压目录不能只凭同名推断可互相替代。要清理其中一份，核对全成员、成员内容、隐藏文件、所需权限/格式和恢复入口；CRC 成功不等于与目录一致。巨大的非重复备份列精确审查项，不自动删。
4. 先迁移并核验保留集合，再按 `artifact-curator-zh/references/experiment-closeout.md` 构建精确清理计划，使用其 `closeout_artifacts.py` dry-run/apply。只有明确授权、消费者停用、保留者与证据通过时执行；受控执行器拒绝云盘重解析路径时保留候选，不能绕过改用递归删除。
5. 迁移同盘不释放空间。分别报告逻辑总大小、同字节重复候选、实际删除字节；没有测量不报物理空间节省。文件占的是磁盘空间，RAM 占用由进程决定。

## 迁移与恢复

- 先查文本引用、启动入口、索引和导入路径。完整工程、运行包与自包含设计单元整件迁移；无法处理依赖则留原位并建索引，不能假装整理完后还能直接运行。
- 冻结 `inventory.json` 与 `plan.json`，同一轮独立评价时不修改输入。预检源成员/指纹、目标碰撞、路径越界、嵌套移动与链接；消费者由执行者实际检查，计划里的布尔字段不是授权或检测证据。
- `apply` 逐件同卷重命名，不复制整份归档；执行前记录 intent，之后记录 done。失败保留 partial 日志，按日志核对实际状态后恢复，不盲重试。跨卷不支持该执行器，应另做经核验的复制迁移方案。
- 迁移后生成每个原文件的旧→新路径映射。更新当前导航和仍生效的可修改入口；历史证据不改写。无法修复的历史绝对路径列为已知限制，提供映射查询，不能声称旧路径都能直接打开。
- 用 `verify --plan` 对计划覆盖的冻结文件逐一回读哈希，检查 `files_outside_plan`；未移动项另按原清单核验，不能把部分覆盖说成全部原件通过。另检查新增导航的链接、空目录、真实源码/成品入口。哈希只证明内容完整，不证明程序已运行、排版合格、活动结果或平台提交。
- `rollback --journal ... --out ...` 可反向恢复迁移；新增导航/报告不自动删除。恢复后再校验原位数据。命令与限制见[执行与恢复](references/operations.md)。

## 验收与交付

按 `multi-agent-evaluation-zh` 安排独立评审；涉及大量真实迁移/删除、复杂依赖时追加独立复核。评审者只读冻结的技能、原清单、迁移映射和真实产物，可在隔离临时目录做行为测试，不复制整个项目。保留原始意见、真实代理身份、输入哈希及修订复验。

必验：范围正确；全部原文件有处置和回读依据；无覆盖/丢失；依赖单元未拆；最终版本有证据或明确待定；README 能找主要资产；复盘有来源与可执行行动；失败/回滚实测；重复候选与实际删除分开；敏感资料未公开。未验证内容列边界；未解决阻断不能凭自评覆盖。

最终直接说明整理入口、前后文件数量/逻辑大小、实际删除及保留版本、真实试用和独立评价结果、未验证项。给一句以后可直接说的调用语。技能制作/单测/一次试用分别报告，不能保证未来自动触发或长期效果。

设计来源与未采用方案见[来源与取舍](references/sources.md)，只在设计或维护时读取。
