# 记录格式、检索和合并

只在正式收录/修订时读取。已有经验库的编号、目录和证据状态优先；以下为自动化扩展字段。字段是助手的整理责任，不要求用户填表；初次最小记录允许未知，不要求等待根因才能保存。

## 最小事件

必需信息：稳定事件标识、当时目标、期望/实际、已知环境、错误脱敏摘要、来源定位和待验证问题。无可定位来源时标“仅会话描述/待核对”。发生时间未知就写未知；收录时间不能冒充发生时间。

事件标识优先使用宿主提供的事件/调用关联标识，并带来源命名空间。没有时首次记录生成唯一标识并沿用；同一个事件的多次尝试使用不同 `attempt_id`。根据同一来源位置识别重放，不能每次重新生成 ID 再累加复发。

## 完整经验卡模板

下面是格式模板，尖括号内容需据证据填写，未知保留未知；这不是已发生的案例。

```yaml
schema_version: 1
id: <沿用经验库的稳定编号>
title: <一句可执行的经验>
pattern_key: <工具类别.阶段.症状>
scope:
  portability: project  # project | personal | cross-project
  project: <非敏感项目标识或unknown>
  surface: <browser | desktop | cli | api>
  tool: <名称与版本或unknown>
  platform: <系统与版本或unknown>
  target: <脱敏域名/资源种类，不含令牌>
conditions: [<适用前提>]
exclusions: [<不适用条件与已知反例>]
source_status: pending  # pending | located | checked
cause_status: unknown  # unknown | hypothesis | confirmed
cause: <原因；假设明确标出>
original_fix: not-applied  # not-applied | applied-unverified | verified | failed
workaround: none  # none | applied-unverified | verified | failed
task_outcome: unknown  # unknown | completed | partial | blocked
rule_status: candidate  # candidate | active-scoped | needs-revalidation | disputed | superseded
first_seen: <发生时间或unknown>
last_seen: <最近独立事件时间或unknown>
last_verified: <实际验证时间或unknown>
review_triggers: [<版本/前提/依据变化或反例>]
supersedes: []
superseded_by: []
workflow_links: []  # 可选：Skill名称或旧流程ID/路径/版本或hash/章节步骤/支持或反例；旧卡缺省为空
```

卡片正文应包含：

- **来源与原始依据**：文件＋记录键/行号/小节，或当前对话可定位消息；必要的脱敏短摘录。来源为受限材料时不复制到公共目录。不能只写“我记得”。
- **事件与尝试**：`incident_id / task_id / attempt_id / observed_at`；当时目标、期望/实际；每次尝试的改变点、结果与验证来源。外部查询/提交若有可用幂等标识，保留非敏感关联方式，不保存凭据。
- **诊断**：事实、假设、已排除原因、未解决问题。恢复成功并不能证明某个根因。
- **下次检查**：条件 → 动作前检查 → 不满足时的处理 → 完成标准。说明该检查是防止、检测还是减轻错误影响。
- **验证**：原失败步骤或明确限定的验证对象、实际结果与对象关联、验证环境、证据范围。离线回放不能登记为真实网站验证。
- **未奏效的尝试**：保留导致相同失败的关键路径及当时环境，不写成永久禁用某工具。
- **使用回执**：当前 task_id、命中方式、采用/不采用理由、实际前置检查、观察结果；帮助程度为 `supported / harmful / unknown`，附证据，不凭自评打分。
- **流程关联（按需）**：对应通用/专用 Skill 的名称、权威路径、版本/hash、章节步骤，以及项目案例和关系；旧 WF 编号继续可用。私有关系不放公共 Skill，按 [流程联动规则](workflow-learning.md) 用私有索引维护。旧记录不强制批量迁移。
- **修订记录**：作者/代理身份、时间、改了什么、依据及替代关系；原始事实不被新解释覆盖。

本地经验库的“可复用”不等于验证通过；`active-scoped` 同样只表示证据支持限定条件下的规则。相关映射详见接入说明。

## 提炼成短检查

例如：“提交创建资源前，查询目标对象是否已经存在且满足要求；若存在，沿用现有对象；结果未知时先查证，不直接再创建。”

短检查必须链接经验正文。不可缺少的边界随短检查一起返回；不将“此账户/此版本下的一次结果”压成“所有环境都如此”。秘密、原始长日志与完整配置不进入短检查。

## 检索顺序

1. 对当前来源命名空间和可访问范围做过滤，避免混用别人的账号/项目记录。
2. 根据目标、工具、阶段、错误短语和别名找候选；再以版本、条件和反例核验。个人库中的跨项目机制可作为线索；源项目命令和资源值不能自动迁移。
3. 默认给少量相关卡；不足时扩展相关范围。陈旧、未知或争议候选要明显带状态，并核查当前事实后再决定采用。
4. 若多个候选冲突，回到当前工具文档和对象证据；无法裁定时保留冲突，仅采用已明确安全的只读诊断。检索不得把争议候选隐藏成无命中。
5. 日志/截图/缓存/配置/后台记录各自只证明对应层次。比较冲突证据时核对同一对象、同一次任务、时间和记录语义；不得设置“日志永远高于界面”等通用优先级。

索引保存卡片 ID、路径、关键词/别名、作用域、状态和一行检查即可。正文唯一；机器生成索引是可重建投影，不能与正文分别维护相反结论。

## 合并与计数

- `pattern_key` 是归类线索，不能独自决定合并。先确认前提、原因及结论相容。
- 去重可归一化随机 ID 和时间；保留 HTTP 状态、工具/系统版本、字段名及必要域名。同一短语但不同原因创建关联卡，不相互覆盖。
- 同一 `incident_id` 的重试增加尝试记录；独立事件数不变。同一事件被多 agent、重放或复核再次读到，不增加复发。
- 观察到的新独立事件才更新独立事件数；使用次数依据不同任务回执计。多个平行运行是不是独立事件要由来源标识和实际执行边界判定。
- 结论或适用范围改变时保留历史及双向替代关系；新证据不能静默删掉失败尝试。

## 并发、写入失败与隐私

已有存储支持单写者、事务或可靠锁时沿用其契约。当前 Markdown 库没有已验证并发原语，第一版由一个协调者写卡和索引，其他 agent 返回候选；记录前重读 ID 与现有内容，避免使用过期快照覆盖。无法保证单写者时暂存为候选并报告冲突，不能冒充已入库。

将完整新内容先写到同目录临时文件并检查后替换，可以降低单文件半写风险；这不构成卡片＋索引的跨文件事务。卡片保存后索引失败，报告“正文已存、索引待修”，下次按正文修复索引；不能重复造卡。WPS 两端同时改动时保留双方副本，指定单写者后再合并。本地写入不证明云同步完成。

索引、短规则及 GitHub 同步范围不得含秘密或可识别私人信息。自动脱敏不保证覆盖所有格式；无法确定的片段不写入，只保留最小摘要及受控指针。读取经验无权读取其来源时保留访问缺口，不尝试扩大权限。
