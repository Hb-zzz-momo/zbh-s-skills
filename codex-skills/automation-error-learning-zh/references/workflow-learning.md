# 经验与流程联合沉淀

用于一次反思同时处理经验与工作流程。两侧都检查，但只改有价值且有依据的内容。用户明确只处理一侧时从其范围；另一侧标本次不处理。没有新发现时保持不变。

## 先找已有流程和所有者

优先使用用户指定的权威文件，再查项目入口/本机配置中的 `workflow_index`，按任务目的、操作对象和前提定位已有流程。文件名、日期或路径相似不足以确认为权威。多个冲突版本无法裁定时保留分歧，不覆盖。

同目标、同前提的已有流程优先增量修订，不生成另一份“优化版”并让两份并行生效。没有对应流程且确有复用价值时，才在已选定位置新建。流程可以是项目 runbook、既有工作流文档或某个 Skill；路径和权限以实际所有者为准。

## 从同一事实得到两类产物

1. 先还原实际执行：步骤、输入/输出、跳转、重复、恢复、验证及未发生部分。实际执行与拟议顺序分区，不能把建议倒填为历史。
2. 经验保留“为什么、依据、适用/不适用条件”；成功、失败、未知均按证据记录。没有新经验也可以因旧经验未接入而修改流程。
3. 流程变更可为补前置条件、调顺序、合并重复、增加异常分支、移除已被证据否定的步骤或把稳定检查交给已有工具。说明变化如何减少问题；流程检查不是每次都加一步。
4. 已有规则被忽略时，先查它是否被加载、能否检索、是否在正确动作前触发，或是否缺执行证据。规则已有且充分时修入口/调用位置，不再复制规则。
5. 一次成功可形成限定范围的暂定流程；普遍化需另有证据。暂时绕路不得静默替换原强制步骤或降低原验收要求。

## 最小关联与变更记录

沿用既有编号。若没有约定，可使用 `WF-YYYYMMDD-NNN`，编号为收录标识而非发生日期。步骤 ID 稳定，调顺序不重编号；拆分/移除保留旧步骤到新步骤的映射。

经验新增可选的 `workflow_links`：流程 ID、路径、修订版、步骤 ID、关系（支持证据/反例/待验证建议）。流程步骤反向链接经验 ID 和来源，明确其支持范围。一个关联处记录一次理由，其他处引用，不复制整张卡。

修订最少写：

| 字段 | 含义 |
| --- | --- |
| workflow_id / target | 权威流程及目标文件 |
| base_revision / base_hash | 修改前读到的版本，写前重读核对 |
| step_ids | 修改影响的稳定步骤 |
| evidence_ids | 支持、反例和建议的来源；无证据说明缺口 |
| before → after / rationale | 最小可审核的内容差异及理由 |
| acceptance / rollback | 如何检验改变、哪些结果要求撤回或修订 |
| application | `unchanged` / `proposed` / `applied` / `partial` |
| verification | 实际做过的检查及范围；未执行就写未验证 |

`applied` 只表示目标文档已按预期写入，不表示新流程业务验证通过。`partial` 表示计划内只有部分写入/引用完成，必须列已完成与待修复项。流程被否定时记录来源和继任版本，不静默删除历史理由。

## 按已有授权落地

- 已绑定库中的经验、流程文档和索引：当前或持续授权覆盖时直接改并验证，无需逐条再问。
- 项目 runbook 或 Skill：仅当当前修改范围/适用持续授权覆盖该所有者时直接应用。已经授权的同范围工作不再询问。单独的 Git 同步授权只允许同步已获准的修改，不等于允许随意改任何 Skill。
- 范围外的目标：先保存精确的最小补丁及依据，标 `proposed`，不应用；可在获准库中完成经验和其他流程更新，不因这一项停掉整个闭环。
- 不借优化之名更换用户产品、删强制要求、绕过安全停止，或修改全局指令/凭据/系统权限。原任务未提供验收证据时，不用“更顺畅”的主观描述替代。

## 一致性、冲突和恢复

采用现有单写者/锁/事务契约。写前核对 base_revision/hash；变了就重读并重新核对，不覆盖他人的更新。无可靠协调时只产候选，由一个写入者合并。

先列本轮计划触及的目标和链接，再保存最少差异；双向关系和索引应在同一轮完成。多文件保存不是天然事务：若某一步失败，记录 `partial`、哪些文件已写、剩余动作及同一轮标识；下一次按该标识补缺，不重复造卡或新流程。不要回滚/覆盖已有的无关改动。

修改后检查实际目标内容、ID/版本、步骤与经验链接、索引可达性和原有必需检查。经验有效但流程相反，或流程变了却仍引用已否定证据时，保留冲突状态并停止套用该分支，先补权威依据。

必要时用脱敏夹具验证新顺序/异常分支，并保留旧流程仍适用的反例作回归。文字检查、隔离回放、真实业务验证和长期收益分别报告，不能为测试再次创建真实资源。

## 下一次如何使用

新任务从经验索引和流程索引检索，读到对应步骤的条件与证据后执行，并写采用/不采用及真实结果。未发现 workflow_index 的旧配置可继续检索原经验索引及已指定流程；新字段缺失不使旧经验失效，不要求重建库。

如果本轮两侧无持久化价值，就保留当前任务的简短处理结果；若只有一侧需要变，另一侧明确 `unchanged` 及原因。联合沉淀不是强制双倍文件或固定条数。
