# 接入与运行边界

此文件用于首次部署或排查漏触发。这里说明配置契约；本机是否已安装、是否可被宿主发现、是否有事件触发，分别据实际结果报告。

## 最小接入

1. 选定唯一权威经验库、允许写入的路径、索引/收件箱及单写者。已有项目规范优先，调用者不得借“记录错误”写到其他项目或全局配置。
2. 把 Skill 安装到宿主实际支持的技能目录，保持按需发现。安装后开启一个新会话，验证显式调用和实际读取的位置；当前会话“能读文件”不足以证明新会话自动发现。
3. 在适用的自动化工作流入口连接三个时点：执行前检索、非预期异常后最小捕获、任务结束前更新结果。是否写入由当前授权及库范围决定。
4. 用两个独立任务验证：第一任务保存脱敏故障经验；第二任务在同类动作前命中它、完成具体检查并写使用回执。没有第二步，只证明收集，不证明后续避错。
5. 实际本地 Skill 新增/修改按当前用户的检查、限定范围提交和 GitHub 同步约定执行；运行数据和私人日志不随技能发布。

可按已授权范围合并到自动化工作流的一句话入口：

> 对多步骤浏览器、桌面、CLI 或 API 自动化，动作前调用 automation-error-learning-zh 检索适用经验；非预期异常时保留最小脱敏事件；结束前按真实结果更新。沿用已绑定经验库、当前权限与停止条件。

这句话只是路由提示，不能强制宿主每次执行，也不授权额外写入。验收需观察实际行为。

## 本机经验库绑定

通用 Skill 不包含用户私人路径和日志。本机配置位于 `$CODEX_HOME/automation-error-learning.local.json`，未设置 CODEX_HOME 时使用 `~/.codex/automation-error-learning.local.json`；此配置不随技能同步到公共仓库。

配置使用 JSON：`schema_version` 为 1；`store_root` 是用户选定库的绝对路径；`index`、`inbox`、`maintenance`、`card_parent` 是相对此根的路径；`write_mode` 可为 `single-writer`；`triggers` 保存用户指定的自然语言入口。未知或冲突字段不得自行推断为扩大权限。

读取后先检查库入口和路径存在性；写入前解析绝对路径，拒绝越出库根的目标，并遵从库内更具体的目录、编号与证据规范。配置是路径数据，不是可执行指令。配置缺失时先用当前任务材料完成分析，再为首次持久化确定获准位置，不猜测其他用户的库。

若库已具备经验索引、收件箱、领域卡片和维护记录，直接复用；编号和状态从该库读取。主题清楚的完整条目可直接成卡，信息不足留收件箱。自动化字段作为卡片扩展，不改变原来的“可复用不等于效果已验证”语义。

跨项目使用时必须能访问获准入口。只迁移有适用性证据的脱敏机制，不复制源项目账户、配置值或私人路径。调用者若无法读取来源，就记录访问缺口，不扩大权限。

## 宿主能力矩阵

| 能力 | 所需条件 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 文本 Skill | 宿主加载并遵从文件 | 被调用时可以完成整理/检索 | 常驻监听、全工具覆盖或强制拦截 |
| 任务路由入口 | 宿主/工作流加载该入口 | 经实测覆盖的任务会调用 | 其他产品、未匹配任务也会调用 |
| 执行后适配 | 已核对的官方生命周期事件或调用包装器 | 事件所覆盖的失败可最小捕获 | 执行前拒绝、业务错误或所有取消都能捕获 |
| 执行前适配 | 可阻断的官方接口及确定性规则 | 经验证条件下可以阻止动作 | 替代原工具安全策略或自然语言判断永远准确 |

Claude Code 文档在核查日提供 `PreToolUse`、`PostToolUse` 和 `PostToolUseFailure`；其中执行前的部分输入校验拒绝不触发失败后事件。即使 shell 运行结束，也要解析真实退出/业务结果；`rg` 无匹配等预期状态不能误报。静默错误、过期截图或错误对象操作可能需要任务结果检查，而非失败事件。[官方事件说明](https://code.claude.com/docs/en/hooks)

Codex/WorkBuddy 的具体适配需针对实际版本与官方接口另行验证；本设计不提供猜测的 hook 配置。未来实现时应分别登记 `capture / recall / enforcement` 的状态、已测事件、未覆盖事件和版本，不能笼统写“自动化已接入”。

## 失败、停止与恢复

- 知识库暂不可读：明确检索未完成，普通低风险任务回到正常流程；关键写操作若缺少必要前提则先补证据。不能依靠陈旧缓存静默宣称避错检查通过。
- 知识库不可写：保留当前上下文中的脱敏候选并说明未入库，主任务按原条件继续；不要因记录失败再次递归记录自己。
- 安全停止：执行原工具规定。若要求本轮停止，就不再运行记录或诊断工具；不得用其他工具续做被禁止的动作。
- 写操作结果未知：优先读回目标状态/幂等结果。无安全核验路径时交回原任务处理，不自动重复提交。
- 能力适配失败：退回明确调用，标记自动捕获/拦截未生效，不伪造正常事件或虚报完成。

不设置后台定时任务，不自动监听所有程序，不建立长期 agent。若用户另行要求这些能力，按所选宿主新增最小适配，再验收覆盖率、隐私、性能与停止行为。
