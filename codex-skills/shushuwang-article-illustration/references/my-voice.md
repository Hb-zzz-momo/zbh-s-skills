# 文风基线（炒技鼠鼠王 / 炒基鼠鼠王）

这份文件是**改稿的最后一道校准器**。通用 humanizer 的规则是别人总结的；这里是**从你自己的稿件里量出来的**。两者冲突时，以本文件为准。

## 样本与口径（重要，别误读）

样本两篇，都是已发布/已通过的稿子：

| 样本 | 来源 | 字数 |
| --- | --- | --- |
| A | `2026-09-24-Harness与向量数据库/文章.md`（已发公众号） | 2191 |
| B | `2026-09-23-VPS部署教程/公众号-小白版正文.md`（已发布） | 2785 |

**口径**：这两篇都是「AI 辅助 + 你校对通过」，所以量出来的是**目标文风基线**，不是你原生手写的个人声音。样本只有 2 篇，只把两篇**都成立**的特征当硬规则；只有一篇成立的一律当参考。

复现命令：`python -X utf8 _voice_profile.py`（脚本在 `E:\project\自媒体\`，改完样本路径即可重算）。

## 硬规则（两篇样本都成立，改稿时逐条查）

| 维度 | 实测值 | 硬规则 |
| --- | --- | --- |
| 破折号 `——` | A 0 / B 0 | **不要用破折号**。想停顿就断句，或用冒号、句号 |
| 感叹号 `！` | A 0 / B 0 | **不要用感叹号** |
| 中文括号 `（）` | A 0 / B 0 | **不要用中文括号**；需要补充说明就另起一句 |
| 中位段长 | 42 / 57 字 | 段落控制在 40–60 字；超过 90 字必须拆 |
| 中位句长 | 22 / 29 字 | 句子 20–30 字为主 |
| 短句（≤15 字）占比 | 20% / 13% | 保持 13–20%：五到八句里插一个短句，不要连续堆短句 |
| 第一人称「我」 | 1.8‰ / 0.4‰ | **极低频**。每篇用「我」不超过 3–5 次，不要靠加「我」来做人味 |
| 冒号 `：` | 26 / 20 次 | 冒号是主要的解释工具：先给判断，冒号后给内容 |
| 问号 `？` | 6 / 4 次 | 设问用来开场或转场，全篇 3–6 次 |
| 数字密度 | 95 / 103 个数字字符 | 每千字 35–45 个数字字符：多用具体数字，少用「很多、大幅」 |

## 与通用 humanizer 建议的冲突点（以本文件为准）

1. **第一人称**：很多中文 humanizer（和 `zh-humanizer-literary` 的"作者存在感"）建议增加"我"来做出人味。**你的实测是每千字 0.4–1.8 次，属于极低**。照那个建议猛加"我"，会立刻偏离你自己的稿子。作者感靠**判断和数字**体现，不靠"我"。
2. **破折号**：`literary-lift.md` 的节奏示范里大量使用破折号。**你两篇样本的破折号都是 0**。不要把破折号当成"更像人写"的标志加进去。
3. **短句制造戏剧感**：通用规则允许"连续短句强调"，但样本里短句是**散点**（13–20%），不是成串。

## 单篇差异（只是参考，别当规则）

- 段长：A 中位 42 字、B 57 字 —— 技术论证篇偏短，教程篇偏长。
- 句式：A 用设问开场（"去年还在强调语义搜索，今年怎么开始用 grep 了？"）；B 是教程，直接进入步骤。
- 结尾：A 落在**边界说明**（"登录代码为教学示例，选型部分为建议。"），不是升华；B 落在操作收尾。共同点是**都不喊口号、不上价值**。

## 用法

1. **写稿时**：先按上表的硬规则约束段落与标点，再写内容。
2. **改稿时**：过完 `humanizer-zh` 与 `zh-humanizer-literary` 之后，**再用本表查一遍**，尤其是"是不是被加进了破折号/感叹号/中文括号/多余的『我』"。
3. **重新校准**：每积累 3–5 篇已发布稿件，就把路径加进 `_voice_profile.py` 重算一次，刷新本文件。样本越多，"目标基线"越接近你真正的声音。

## 为什么用"目标基线"而不是"伪装成真人"

目的不是让文本躲过 AI 检测器，而是让**你自己认可的那些稿子**成为标准：读起来像你、判断像你、标点克制得像你。检测器会变，你的稿子不会。
