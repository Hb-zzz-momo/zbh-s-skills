### 「有逻辑但死板」的分界：逐项量同账号那篇 vs 我们的模板稿

用户 2026-09-26 指出：模板太一致只适合教学，技术分享 / 信息分享要更灵活。把同账号那篇量了一遍，差别是可数的：

| 指标 | 那篇《Harness…》 | 我们的模板稿（机制设计） |
| --- | --- | --- |
| 正文 | 2633 字 | 约 2500 字 |
| 小标题 | 6 个，带序号 | 8 个，带序号 |
| 图片 | **4 张，分布在 6 节中的 4 节**（另 2 节纯文字） | **6 张，几乎每节一张** |
| 图片来源 | Cursor / Anthropic 的**原始截图与图表**，脚注标 `[1]…[7]` | 自制模板卡 4 张 + 官方截图 2 张 |
| 底色引用框 | **0 个** | 6 个 |
| 行内加粗 | 24 处 | 较少 |
| 代码 | 3 个深色代码块 + 4 处行内代码 | 无 |
| 来源处理 | 脚注编号 + 文末「资料与图片来源」一节 | 每张图下写来源 |

结论：**"不死板"来自图与文的密度不均、形态随内容变、重点靠行内加粗而不是靠框**。模板化的代价是把这三样都拉平了。所以定成两层——底层（字号/行高/图注/代码/表格/框）统一，上层（张数、形态、重心、来源方式、节奏）每篇按题材重定。

- 两端对齐；段首不空两格。
- **每段不超过 2–3 行**：电脑端看到 2 行，到手机上约 4 行。中文长段控制在 60–80 字以内断开。
- 正文字号 15/16/17；行间距 1.6–1.75；字间距 1；两端缩进 8（想更宽用 16）。
- 全文颜色不超过 3 种且固定，不刺眼；金句用主题色或加粗。
- 小标题加粗并带 1234 序号。
- 发手机预览再检查：结构完整、图片与正文缩进一致、错别字、行距留白、文末多余空行。
- 作者的结论是"少一点设计感，多一点阅读感"，排版服务阅读，不追求花哨。

## 三、易读性工具箱

按"读者在哪一步会卡住"选工具，不是每篇都全用：

| 工具 | 用在什么时候 | 硬要求 |
| --- | --- | --- |
| 短段落 | 默认 | 60–80 字断开；一个段落只说一件事 |
| 重点加粗 | 结论、易错点、关键数字 | 加粗的是判断，不是名词堆砌；一段最多一处 |
| 比较表 | 两个以上对象要对比 | 表头写清口径；窄屏能读，不超过 4 列 |
| 流程图 / 路径块 | 有先后顺序、分支或回路 | 方向明确、节点可分辨；文字版用等宽框，图片版按手机宽度核对字号 |
| 文末逻辑链路卡 | 每篇课程 / 教程的最后一节 | 蛇形走位（上排左→右，下排右→左），4 列 2 行；格内 3–6 字；1080×484 最省空间（见 SKILL 的专节） |
| 命令框 / 公式框 | 命令、代码、公式 | 公众号必须用 section 底色框，不能靠 `<pre>` 的底色 |
| 结论先行 | 长文、教程、复盘 | 开头一两段说清解决什么、覆盖什么、方法是什么 |
| 术语先定义 | 面向零基础 | 首次出现给用途，再给必要的类比 |
| 自测 / 检查清单 | 教学类 | 答案紧跟题目之后，别让读者翻页找 |

图解 **不能替代** 解释，也不能只放情绪化插画充数。

## 四、引流规则

样本里反复出现、且符合平台规则的套路：

1. **标题写"读者得到什么"**：一看就懂、看这一篇就够了、全程不踩坑、了解买卖时间。保留主题词，不写"零基础秒懂、永久稳定"这类承诺。系列文章用固定前缀（如"基金投资第 N 课"）。
2. **首屏三件事**：一句核心结论、一句适用对象、一条阅读路径。样本里的高赞内容普遍把结论放在最前。
3. **每节有小标题和序号**，让读者能跳读；长文再给目录，区分"从头读"和"直接操作"。
4. **留具体钩子**：给出下一步、自测题或"下一课讲什么"。样本里普遍在文末留学习路径，而不是只喊"记得关注"。
5. **平台原生格式优先**：知乎吃表格和图；公众号吃无链接正文和 section 框；雪球是投资社区，AI 生成内容必须勾选标识；东方财富走财富号/股吧。
6. **合规是引流的前提**：金融内容不荐具体产品、不承诺收益、不诱导站外；小红书社区规范把"投资理财产品"列入违禁清单且禁止导流，不作为主发渠道。
7. **发布时间和标签**按平台自己填，不编造"最佳时段"结论；标签用真实主题词。

不采用的做法：标题党、虚构亲历、编造数据、诱导分享、买量承诺。

## 五、图片策略

优先级从高到低：

1. **自制机制图 / 数据图**：解释一个读者靠文字难以建立的路径、边界或差异。这张图是内容的一部分，必须能被逐字读懂。
2. **官方或权威来源的网络图片**：政府、行业协会、交易所、官方文档、机构博客的原文图。用时保留原图，不裁掉来源信息，图注写明"来源：机构，日期"和这张图证明了什么。
3. **装饰性插画**：Logo 角色出场，控制尺寸，不抢正文。

网络图片的硬约束：

- 只引用公开可访问、允许引用的页面配图；不下载付费墙内内容，不使用带他人水印的商业素材。
- 引用前打开原页面确认这张图确实在那里、日期和结论一致；不能只看二手转载。
- 数据类图片不重新绘制成"看起来更漂亮"的版本，避免改变数值和坐标含义。
- 找不到合适且可引用的图时，宁可不放，也不拿无关库存图充数。

## 六、发布前验收清单

### 平台转换实测（2026-09-26 补充）

- **雪球**：编辑器会把 Markdown 表格整段拍平（实测 `tables=0`）、相邻列表项并成一行、**段首全角空格被删**（`indented: 0`）、**分隔线也被丢掉**（`hr: 0`）。所以雪球只有两个可用手段：少字、多图。表格转图片、关键数字在正文再写一遍、序号用 ①②③、每项独立成段；目录在这种站上留着只是多七行字（没有页内锚点），可以不写。
- **知乎**：表格、图片、引用块、分隔线（`hr`）都保留；但**段首缩进不可靠**（同一篇里首段会被抹掉），而且 **`---` 渲染出来的间距很大，会把文章切得很割裂**（用户 2026-09-26 明确反馈）。知乎版的做法是：不用缩进、不用分隔线，靠小标题分层，关键结论用 `>` 引用块。
- **东方财富**：与雪球同源，按同样方式处理；本轮未登录，未做平台内复核。
- **知乎**：表格、列表、正文图都能正常保留（草稿内实测 `tables=4`），按普通长文写即可。
- **微信公众号**：不能用 `<pre>` 底色，改用 section 框；正文不能放外链，资料以纯文字网址附在文末。该站后台被浏览器策略封锁，只能由用户在编辑器里做最终核对。

### 图注：用各平台自己的位置（2026-09-26 定稿）

“图 N｜标题”**不要**写成正文段落，也**不要**烙进图片里（用户明确否掉了这两种）。按平台分别处理：

- 知乎：填进图片自带的“图片注释”字段（编辑器里图片下方那行小字）。WechatSync 不写这个字段，改 alt 也没用，必须在编辑器里补。**可靠动作链（2026-09-27 修正版，逐条做过刷新复核）**：① 点 `figcaption.Image-caption`（第 N 条按序号 `nth(N-1)` 取）→ 该位置出现 `.Image-captionInput textarea` 并自动聚焦；② 对这个 textarea 用 `pressSequentially(文本)` 键入——**不要用 `fill()`**，React 不提交，值写进去了但图注仍是占位符；③ **提交要点正文元素**（某个 H2 或正文段落）让它失焦，`figcaption` 的 `is-placeholder` 类消失即成功；④ 一条一条来，每填一条就点正文失焦一次。

  **上一版写错了**：原文说“点下一条图注即失焦提交上一条”。实测只保住了第 1 条——三条图注在 DOM 里都显示正确文字，**刷新页面后第 2、3 条全退回占位符**。原因是通过下一张图注切换时，只有第一次 blur 触发了提交。所以：不要点下一张图注提交，改点正文；并且**改完必须 `reload()` 复核**，三条图注在刷新后依然是三条才算数（这是唯一能证明写入服务端的检查，DOM 里显示正确不算）。**Esc 会取消而不是提交**（会退回占位符）。别按占位文案定位，那会把多条文字都塞进第一张图的注释。
- 公众号：没有注释字段，在图片下方加一行 13px 灰色小字（内联样式），视觉等价。
- 雪球 / 东方财富：没有注释字段，也不保留富文本格式；在图片下面另起一行短句作图注（加粗行，前后各留一个空行，避免被并进相邻段落）。

**一条硬规则**：排版改进不是单平台的——任何一处“这个平台变好看了”的规则，都要在同一轮里落到其它平台（逐平台核对：图注落位、分隔线、表格、引用块、字号层级）。只改一个平台、其它平台留旧样式，等于没改。

### 封面字段在草稿阶段往往没写进去（2026-09-26 实测）

`wechatsync sync --cover <本地图>` 在本机没有把封面写进知乎和雪球的草稿：知乎的发布设置仍显示「添加文章封面」，雪球的封面区刷新后仍显示「上传封面」。雪球手动选文件后弹出的「剪切图片」弹窗，点「确认裁剪」也没有落库（刷新后封面仍为空）。所以：

- 别把 `--cover` 当成“封面已设好”的证据；发布前必须逐平台打开编辑器确认封面区有没有图。
- 封面里的品牌名只能靠本地图保证正确，改完图要重新渲染并肉眼确认。

规律：**每一轮的价值不在“这次改好了”，而在“下次自动挡住”**。只改不补断言，等于下节课重新犯错。

用户提出“优化排版 / 更容易读 / 更好看”类要求时，走这五步（2026-09-26 与用户反复确认后定稿）：

1. **找参照**：挑 2–5 篇同题材同平台的高质量样本，读到正文而非摘要；记录可迁移机制（标题、开头、段落长度、图注位置、用表还是用图）与互动量，来源写进编辑记录。优先复用本文件的样本与参数，不为小修反复检索。
2. **量现状**：用脚本量最长自然段、图数、表数、加粗数、字符数；改完再量一次，前后对比写进自检。
3. **一平台 → 全平台**：任一改进同轮落到所有会发平台，逐平台处理受限项（见下表）。
4. **平台内核对**：本地渲染不算；能在编辑器核对就核对，核对不了就标明“待用户确认”。
5. **沉淀**：把平台丢弃的样式、踩过的坑写回本文件，下一篇直接避开。

### 编辑器内怎么核对（可复制）

- 知乎：打开 `/edit` 页，在控制台量 `document.querySelectorAll('figcaption')`（图片注释数量与内容）、`hr`（应为 0）、`table`、`blockquote`。
- 雪球：量 `.ProseMirror` 下的 `img` 数量、`hr`（应为 0，也不会变成文字）、`figcaption`（应为 0，说明必须另起一行）。
- 公众号：后台域名被浏览器策略封锁，只能本地渲染 + 让用户在编辑器里确认，报告里写“待确认”。
- 填知乎图片注释：先等草稿同步完成（编辑器不再显示“草稿保存中”、右下角出现“刚刚 · 草稿”），再按 `figcaption` **序号**定位 → 点击 → 对出现的 `.Image-captionInput textarea` 用 `pressSequentially` 键入 → **点正文标题失焦提交** → 一条一提交。全部填完后 **`reload()` 复核**，三条都还在才算成功。踩坑：`fill()` 无效、Esc 是取消、保存中键入不生效、**点下一张图注提交只保住第一条（刷新后丢）**、重复粘贴会叠字、退格清空可能连带删掉整张图片；按占位文案定位会把多条文字堆进第一张图。键盘不行时再退回“点击后粘贴”的老办法。

- 雪球草稿核对：**in-app 浏览器未登录雪球**，必须借本机 Edge（扩展所在的浏览器）打开 `mp.xueqiu.com/write/draft/<id>`；页面 AX 快照可能在内容异步加载前就返回“请输入正文”，要等几秒后读 `[contenteditable="true"]` 的 `innerText` 与 `img` 数量才算数。

### 图片自检的硬指标（2026-09-26 定稿）

卡片是给手机看的，画布再大也要按“手机等效字号”验收：

- 等效字号 = 图内字号 ×（375 ÷ 卡片宽度）。关键文字（标题、数字、结论）≥12px，说明性小字 ≥9px。
- 画布建议 1080px 宽、正文 28–30px、标题 46px、图内数值 40px；1600px 画布配 20–26px 字号在手机上只有 5–6px，等于不可读。
- 必须查：内容是否溢出卡片、标签是否压住柱子/线条/数字、柱状图的方向与高度是否和标注一致、有没有缺字方框。
- 脚本能查几何和字号，查不出“看着别扭”；渲染完仍要自己整张看一遍。
- 复用模板：`assets/figures-card-template.html` + 本目录示例的 `figures.html`、`render_figures.cjs`、`check_figures.cjs`。

小节之间**不要画分隔装饰**（`---` 间距不可控，“· · ·”被用户否掉太丑）。改用小标题自身的上留白分区：公众号给 h2 加 `margin:34px 0 14px` 一类行内样式，知乎靠 H2 层级，雪球什么都没有只能靠段落短。另外，标签后的冒号并进加粗里（`**5 秒看懂：**`），否则中文换行会把冒号甩到下一行行首。

结论：成品稿不能只在一处验收。发之前先在各平台自己的编辑器里看一遍，表格、图片、包裹样式是否还在。
