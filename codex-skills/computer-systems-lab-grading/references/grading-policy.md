# 当前程序评分政策 v1.0.0-draft

用户最新要求为更宽容、分布中心尽量85；见[尺度校准](scoring-calibration.md)。本页描述当前已实现档位，不能把它误作新宽容尺度已落地。新档位方案实施前不得以提示词或总分平移绕过JSON；本轮skill更新保留历史规则。

这套标准来自所提供16份实验标准答案中的题面、表格和代码图片。原资料没有详细数值评分表；各项分值是本次按用户确认的“每实验100分”设计。当前可用于试批和教师审阅，不宣称已经测得公平性或模型准确率。

## 分数如何产生

每个实验按自己的学习目标分配100分，例如实验1重安装链条，实验8重受限算法及边界，实验12重调用时点与栈帧，实验16重重定位。16个实验均保留5分具体心得，心得不按字数计算。题面中的选做内容不扣分、不额外加分。未给定迟交政策，不自行增加迟交罚分。

评分项固定四种状态：`full`为满分；`partial`为本项写明的固定部分分（设部分档的项为一半，允许0.5分；实验15身份比对项不设部分档）；`zero`为可证实错误或完整检查后的缺答；`unresolved`为无法判断。章节部分分等于各项相加，不凭总体印象调整。一个复杂问题拆成代码、执行、分析等不同目标，不能在这些规定分值以外再追加“代码错扣10分”。

满分锚点优先于部分分锚点。只满足部分锚点时才能给部分分；不足以满足部分锚点才给零。可核实的小笔误不损害该项核心目标时视为等价表述。处于两个档位之间且标准未覆盖的真实答案应进入复核，教师记录裁决，并在下一规则版本为全班统一处理；不能临时给某个学生一个任意分数。

## 材料与证据

| 情形 | 处理 |
|---|---|
| 代码正确，未提供题目要求的运行记录 | 保留代码项分数，运行项按锚点评；不连带扣解释分 |
| 截图存在但提取失败/无法辨认 | unresolved，补提取或复核，不是缺答 |
| 全部材料完整可读，确定未答 | zero，记录已查位置和缺失内容 |
| 一张截图覆盖多个步骤 | 允许用于多个独立目标，不按图的张数给分 |
| 不同工具/正确等价实现 | 目标与语义满足即可，不按字面相似度 |
| 运行地址、寄存器分配、文件路径不同 | 根据环境与语义核对，不要求复制示例 |
| 模板预填“95分”、教师答案或题面截图 | 不能证明学生完成；从学生证据中排除 |
| 文件名/封面/名单不一致或多个版本未选定 | 阻止发布，明确选择版本；不得按目录顺序猜测 |
| 自述“运行成功”但无可核实输出 | 不等于真实运行证据；知识解释仍可独立评分 |
| 疑似抄袭/AI生成 | 不自动扣分，只整理可核查线索供教师处理 |

原报告必须只读，衍生文件另存。保留报告页/段/图片索引与SHA-256；模板和答案作为题面来源，与学生证据分开。图像提取数量核对只能发现一部分问题，浮动对象、OLE、扫描页还要对照渲染结果。只看到正文时不能宣布没有代码。

## 错误传递与题面冲突

如果早先算错一个值而后续方法正确，在后续有方法评分项时保留方法分；最终数值项依据该项标准处理。禁止为了“同错不重扣”把所有错误结果都当正确，也禁止额外叠加整卷罚分。已有分值以外不添加格式、字数、截图美观、文风、用户名、内存大小等扣分。

发现标准答案有误，以题面和可验证技术语义为依据。各实验JSON列出已发现的笔误和变体，例如实验10第8条存在两种版本。能识别学生使用的版本并自洽时正常给分；无法确定版本时待复核。对整班有影响的变更要升级规则版本，并对受影响提交重评，不能无记录改变同一批的规则。

## 不确定性与正式成绩

严格结果中待定项仍以[0,该项满分]计入区间；不能取中点冒充确定结果。工作台另给按冻结档位计算的具体recommendation，允许轻微错判并标明推定项目、原理由及重点；不把推定改写成已核实证据或确认缺答。教师明确接受推定后才保存复核，身份/提取/版本阻塞必须处理。`final_score`仍为空，正式成绩由独立发布记录产生，详见[导入与重点复核](intake-and-priority-review.md)。

先用每实验至少5份覆盖高/中/低完成度和图片质量差异的报告，由教师独立逐项标注。争议样本二次裁决形成基准。比较模型逐项档位、总分误差、待复核率、对不同排版/等价代码的一致性；同时纳入留出的未调参报告。建议初始验收目标为总分平均绝对误差不超过3分、至少90%报告误差不超过5分、严重误判清零、关键证据引用可复核。**这些是拟定验收门槛，不是现有实验结果。** 样本不足时只作为探索指标，不宣称已通过。

同一模型重复批阅不代表独立教师意见；两次相同也不能证明正确。不要取多次结果中的最高分或最接近期望的一次。模型、提示词、规则或解析器发生版本变化后重跑固定基准；偏差扩大就停止自动形成最终成绩。
