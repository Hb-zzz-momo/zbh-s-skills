# 文件优先导入与重点复核

2026-10-08用户要求：先导入报告，由系统判断班级、实验及学生，再检查；先给具体建议分，允许一定程度错判，只把严重影响结果的少数判断留给教师。

## 文件先行

第一步只选择Word/PDF或文件夹。不以页面当前分组或实验作为默认识别结果。服务端在intake保存原字节并生成独立凭证；此时未登记作业、未计分、未调用模型。

文件夹上传须将multipart文件名显式设为File.name。Chromium省略该参数时可能发送webkitRelativePath（含所选文件夹及子目录），会被服务端的文件名检查拒绝。原文件名和字节不改写；目录只用于选择文件，不能作为服务端归档路径。后端仍拒绝包含路径的上传名，不靠放松路径检查处理此问题。识别失败由教师点击重试，排除格式/大小本地无效文件，仅请求尚未识别的失败项，已识别凭证及手工修正保留；此重试只做识别，不发评分模型请求。

DOCX直接读原始正文封面；PDF读首页；旧DOC通过只读Word转换取得结构副本。识别范围在“实验目的/内容/步骤”等正文起点截止，避免“使用实验1安装的系统”干扰实验二归属。封面转换失败保留提示，仍可检查文件名/名单识别，不冒充已完成封面核对。学生完整学号优先、姓名唯一匹配补充，按名单原班级归属；汇总分组仅为视图。实验按文件名编号、封面编号或已知实验标题识别，支持中文编号1—16。一批可有不同班级和实验。

文件名与封面冲突、多个班级归属、未知学生或实验不猜测，相关字段留空或提示，教师补选。修改识别需填写依据。实验编号误写可以明确修正，不能通过改名覆盖原件。确认时重新验证原件指纹、当前名单成员与班级，凭证重复提交去重；确认后走原有归档/版本逻辑。失败文件保留，已成功导入不重复上传。

## 删除、名单外学生与最终报告（2026-10-09）

导入检查页每个文件都有删除入口，失败项可一键全部删除；只移除当前批次，可以撤销，不删除电脑源文件。识别/格式无效的报告不登记作业、不生成零分。已登记的失败、未匹配或未发布的待处理报告通过 delete 操作进入已删除列表，普通查询、学生作业统计及导出排除该列表；restore 校验原件指纹后恢复，并重新核对有效版本。保留数据库、原件、旧评分与任务日志；运行中/排队任务及已发布成绩不能通过此入口删除，旧修订仍拒绝。

文件名及封面身份字段可为名单外学生预填学号/姓名，冲突时留空提示核对，不自动建学生。教师点击加入名单、检查学号/姓名/原班级后明确确认，调用同一花名册导入接口，再对应报告。同学号身份和成员关系去重，同学号异名拒绝，汇总成员从原班级派生。已保存的待匹配报告也提供加入名单入口，明确核对后可修正普通班级归属；汇总归档仍限定来源班级。新增名单和正式成绩发布是不同操作，新增不调用评分模型。

同一原班级、学生和实验，以不同内容指纹作为提交版本。文件名的“新/新版/最新/修订版/更新版”及封面明确版本字段、报告标题中的新版标记提供可追溯依据；不搜索实验正文中的普通“新”字，不以姓名包含“新”、下载后缀 (2)、-1 或导入顺序判新版。唯一明确新版优先成为最终报告，其余保存为历史。新旧导入顺序相反时结论一致；多份不同内容的新报告或多份无明确新标记报告需教师选择。教师已明确选择和已发布当前报告优先保留，后续版本不能静默切换正式成绩。相同字节以新文件名上传时去重并记录新版标记，不重写原文件名；重导同一已删除原件恢复原记录，不生成重复学生或提交。教学数据库与评分引擎的有效版本同步，自动选择不新建评分任务或发布成绩。

工作台执行该自动版本政策；独立 CLI 的 select 仍须明确调用并记录操作者/理由。不能把选定最终报告说成已经重新评分，更不能用最高分代替新版标记。

## 具体建议分

严格模型结果与区间仍保留。recommendation是另外的可审查建议：已确认项沿用原档位；未决项参考同绑定原始判断、可读作答与评分锚点选择full/minor/partial/zero，不取区间中点。事实冲突或both缺一种证据时不自动恢复满分。没有明确作答支持的建议零分必须标为推定且missing=false，不能描述成已完整检索的缺答。身份项不推定。

每项保留原判断/理由、建议档位/分值、依据编号和estimated标志；总分为各建议档位之和。建议可以误判，不能声称已经证明公平或已完成教师核实。提取失败、缺项模型响应、错误绑定仍不产生建议。身份/实验/版本阻塞必须处理，不能随轻微提示折叠。

## 少量重点

按建议档位到本项极端档位的最大可能变化计算影响。默认单项影响达到6分或同类累计达到10分进入重点，按影响排序最多显示3组。其余提示折叠、可全部展开；不删除原始评分项。Configuration.review_policy可调item_points/group_points/max_groups（1—5组），只影响顺序与显示，不改变评分档位或已保存成绩。

教师可检查重点后勾选“接受其余AI建议（含推定）”，一次保存复核。后端只对与自身同绑定建议档位、证据引用一致的项目接受推定；任意修改不能借此跳过校验。接受项目在review.result.accepted_estimate_items逐项留痕。改判、重新复核仍检查修订号；发布另行显式执行。自动化验收不能替教师接受真实学生成绩。

## 分布口径

工作台可展示具体建议分的分布，注明推定样本数。严格结果的区间可展开查询；不把中点混入统计。自动章节权重建议仍使用完整无未决样本，至少20份，不拿推定样本冒充教师校准。不保证正态分布，不为中心85改个人分数。

## 接口

- POST /api/imports/inspect：只上传file，返回ticket_id、prediction、reasons/conflicts/warnings。
- POST /api/imports/{ticket_id}/confirm：group_id、experiment_id、student_id或defer_match、actor和reason。凭证由服务端持有，不接受任意文件路径/客户端指纹。
- GET /api/reports/{id}：suggestedScore为具体建议；verifiedSuggestedScore和result是严格原结果；recommendation包含推定、重点与提示；reviewScore、publishedScore独立。
- POST /api/reports/{id}/review：决策及修订号，accept_estimates=true表示教师明确接受合法推定项目；不能提交自由总分。
