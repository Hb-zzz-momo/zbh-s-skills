# 状态观察接入

只在确有重复检查需求时读此文件。脚本观察本地文件，不执行项目代码、不检索历史、不创建目录。

## 一次接入

1. 延续项目结构规则与已有入口。没有等价位置时，可在任务范围内创建 `.context-cache/`；已有 `docs/project-entry` 则用其下的 `context-cache/`。不搬原件，不覆盖已有地图。运行命令的根必须是项目的本机目录；路径含云端占位/重解析点、UNC 或设备路径时不使用本脚本，改用领域流程。
2. 参考 [地图模板](../assets/maps.md) 创建/补齐 `code-map.md` 与 `evidence-index.md`，或者在 manifest 中列现有等价文件。将 [示例清单](../assets/manifest.example.json) 复制为选定缓存目录的 `manifest.json`，替换 scope 和所有示例内容。
3. 清单逐个列原文件，不支持通配符和目录递归。含义：`path` 为项目根相对路径，`kind` 为 code/evidence/requirement/report/environment/map，`field` 为变化项归属，例如 report_section_4。需要短路的范围必须包含适用规则、验收标准、相关代码与测试、报告/证据与环境配置；任务外文件不用收录。新文件不会自动出现，须与实际变更清单交叉核对。
4. `scope_id` 绑定项目、任务及身份，不能把不同学生或实验复用为同一范围。`current_status`、`last_verified_at` 是助手依据真实核验填写的状态；`open_issues` 保留所有待办/风险，`external_dependencies` 列当前目标依赖的进程、平台、期限等。不得为取得无变化而清空它们。`max_age_hours` 允许缩短到 0–24 小时之间（不含 0），默认24；失效后重新核验相关事实。
5. 真实读取、分析与必要验证之后再 `record`；它生成 `state.json`，自动填内容哈希、观察时间和变更归属。第一次 `check` 无基线返回 CHANGED；既有基线坏了则 UNKNOWN，先调查损坏原因并保留原件，不自动修复/重置。

命令示例（在本机 PowerShell；`$projectRoot` 须替换成当前项目绝对路径）：

```powershell
$snapshotTool = 'C:\Users\zbh\.codex\skills\context-budget-guard-zh\scripts\context_snapshot.py'
$projectRoot = 'D:\示例项目'
python -B $snapshotTool check --root $projectRoot
# 实际分析、必要验证和地图更新后，才执行：
python -B $snapshotTool record --root $projectRoot
```

使用已有入口时，两条命令都加 `--cache-dir 'docs/project-entry/context-cache'`。脚本不会写地图、manifest、原件或全局记忆；只在 record 时创建同目录短期锁、临时文件并原子替换 state.json。`check` 不写基线。发现遗留锁先调查任务/进程，不自动删锁。

Windows 用真正的 ChangeTime 辅助读前、读后及整批结束复查，不把创建时间当修改时间；不对输入加拒写锁。record 仅支持本机 Windows，会在写入期间持有缓存及其祖先目录的句柄，暂时阻止这些目录被删除/改名或替换为链接，同时允许目录内正常读写；结束即释放。正在重组目录时不 record。UNC、映射网络盘、重解析点或无法固定的目录均降级 UNKNOWN；不改权限、不清锁、不等待重试。

## 结果决策

| 状态 / 退出码 | 含义 | 下一步 |
| --- | --- | --- |
| UNCHANGED / 0 | 已列文件与有效基线相同、无登记待办/外部依赖 | 仍需核对本轮是否纯观察、有无新指令/到期动作/必做验证；符合才一行“无变化”结束本次观察 |
| CHANGED / 1 | 首次观察、文件/清单/根/身份变化 | 定向读原件与影响范围，真实处理后再 record |
| REVIEW_REQUIRED / 1 | 基线超过有效期、时间异常、待办或外部依赖 | 走正常核验，不能跳过任务 |
| UNKNOWN / 2 | 路径/权限/上限/读取中变化/损坏/锁等错误 | 优化失效，保留现有基线与原件，继续正常定向读取 |
| RECORDED / 0 | 新文件观察基线已保存 | 只证明文件观察完成，不表示分析、测试或验收通过 |

每次单行 JSON，UNCHANGED 的 message 为“无变化”；不输出文件内容。`changed_fields` 依据清单声明，不解析 Word 的章节差异；报告文件变了需用领域工具定位变化，不能声称已自动识别哪一段。

`evidence_hash` 是清单原始内容哈希、根路径、scope 和各文件 SHA256 的组合摘要。它适用于偶然变更检查，不是防篡改签名或跨设备同步证明。更换根路径会失效；必须核对身份后重新观察。文件观察不是整个项目同一瞬间的事务快照，运行中有持续写入时不依靠它短路。

预算固定：64 文件、8 MiB/文件、32 MiB 合计、128 KiB/控制文件、2 秒协作式读取预算；按内容每次重新哈希。没有“mtime 相同就跳过”的快速路径。预算不计 Python 启动及无法中断的 OS I/O；不要将它宣传为严格实时上限。若本机无可用 Python，跳过脚本，不为本技能自动安装环境。

## 保守场景

- 报告只有措辞调整：先以变化文件定位段落，保留数字、引用、身份与模板原文；按课程要求进行必要渲染和复核，不能因结果文件未变跳过报告验收。
- 文件无变化但截图仍待人工复核：保留 open_issues，返回 REVIEW_REQUIRED；继续取得人工/独立核验，不能“一行结束”。
- 文件无变化但用户要求重跑、测试到期或实验仍在运行：正常执行已授权工作并查真实进程/日志；不得以缓存中“已完成”否决当前请求。
- 模型权重或数据集超过预算：由领域流程在适当阶段核验大文件、运行环境与真实结果，保留完整证据入口。本清单若不足以覆盖当前监控目标，则放弃短路，不用小摘要冒充大文件新鲜度。
- 规则、测试、身份、引用路径变化：读取相关原文并更新影响范围，不只是压缩变化摘要。外部网页事实需要时重新查权威来源。
- 三位评审：各给完整目标/验收约束、相同冻结版本、分配维度及对应原证据；可读更多材料，各自初评后再交流。禁止只给作者的摘要，也不因包精简删掉原有必评项。
- 任务收尾：确有新增稳定规则才记录短候选；不调用全局记忆写接口、不启动后台进程。停用只需不调用此技能。
