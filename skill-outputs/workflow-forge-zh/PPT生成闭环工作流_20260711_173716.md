# PPT 生成闭环工作流

> 将材料和模板转化为可编辑 PPTX、渲染证据、修复记录与最终交付包。

## 前置条件

- 已读取主题、材料、数据、图片、品牌规范、模板和交付要求。
- 已选择 A 仅规划、B 从零创建、C 基于模板、D 修改已有中的一个主分支；数据任务叠加 E。
- 每阶段只有 1 个主 Skill、最多 2 个辅助 Skill。

## 步骤

### Step 1：Intake 与 Gate

- 输入：用户材料与交付要求。
- 输出：`brief.md`、材料清单、缺失信息、PASS/CAUTION/BLOCK。
- 完成标准：关键输入和禁止越界均已记录。

### Step 2：证据链

- 输入：材料清单。
- 输出：`sources.md`、`claim-evidence-map.md`。
- 完成标准：事实可追溯，推断/建议/示例已标记。

### Step 3：叙事与逐页契约

- 输入：简报与证据链。
- 输出：`storyline.md`、时间预算、`slide-spec.json`。
- 完成标准：一页一个结论，证据 ID 可解析。

### Step 4：视觉系统

- 输入：Slide Contract、品牌和模板视觉。
- 输出：`PRESENTATION_DESIGN.md`。
- 完成标准：颜色、字体、网格、组件、布局家族、母题和反模式均可执行。

### Step 5：三页纵向切片

- 输入：叙事与视觉契约。
- 输出：封面、最复杂机制页、数据/总结页及渲染图。
- 完成标准：Taste Gate 通过；否则只返工三页。

### Step 6：Build

- B：`pptx-builder-zh` 从零生成原生可编辑 PPTX。
- C/D：`pptx-template-editor-zh` 先分析和映射，再另存修改文件。
- E：数据页阶段追加 `ppt-data-storytelling-zh`。
- 完成标准：PPTX、源码、依赖锁与构建检查齐全。

### Step 7：Render QA

- 输入：PPTX。
- 输出：PDF、逐页图片、Montage、文本/几何/图片检查。
- 完成标准：真实 Office 后端完成渲染，阻断问题已登记。

### Step 8：Fix Loop

- 输入：自动检查与人工视觉问题。
- 输出：修复后的新 PPTX、`fix-log.md`、新一轮渲染。
- 完成标准：至少一轮修复复验，受影响页和全局 Montage 均复查。

### Step 9：Ship

- 输出：PPTX、源码、素材、简报、来源、叙事、逐页契约、视觉契约、渲染图、Montage、QA 报告。
- 完成标准：全部文件属于同一版本，命令、后端、风险和路径已说明。

## 检查点

- [ ] 未一次加载全部 PPT Skills。
- [ ] 未编造数据或来源。
- [ ] 未覆盖用户原始模板/PPTX。
- [ ] 首次渲染没有直接交付。
- [ ] 真实渲染、自动检查与人工视觉检查闭环。

## 异常处理

| 异常 | 处理 |
|---|---|
| 缺主题、关键数据或模板文件 | BLOCK，补问或降级为仅规划 |
| 缺 LibreOffice | 自动尝试 PowerPoint/WPS；都缺失则 BLOCK |
| 构建器写出失败 | 保留错误、源输入与日志，停止后续 QA |
| 模板关系不明 | 默认不删除，先报告再人工确认 |
| 首轮自动零问题 | 仍执行 Montage 与代表页人工找缺陷 |

## 可迁移建议

- 长期维护可追加计划中的 `pptx-ci-zh`，但本轮不创建该 P1 Skill。
- 品牌案例图应放入独立参考库并登记许可，按页面类型按需加载。
- 回归示例固定保留“首轮问题 → 修复 → 复验”证据，避免 QA 退化为空命令。
