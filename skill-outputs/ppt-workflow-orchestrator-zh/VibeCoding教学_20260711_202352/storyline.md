# 故事线

## 核心矛盾

Vibe Coding 追求速度，但正式交付要求可解释、可验证、可维护。真正的能力不是“让 AI 写得更多”，而是让反馈循环更短，同时不放弃人的判断。

## 章节

1. 重新定义：Vibe Coding 是快速协作方式，不是放弃工程责任。
2. 识别风险：模糊目标、上下文缺失和跳过验证会让速度变成返工。
3. 掌握方法：用 Goal–Context–Constraints–Done 组织提示，以小步闭环推进。
4. 课堂实践：从一个微型功能完成提示、生成、测试、修复和复盘。
5. 行动收束：AI 负责候选实现，人负责目标、边界、验证和发布。
