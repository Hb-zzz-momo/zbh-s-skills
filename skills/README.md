## Global Defaults

- ``knowledge-digest-zh`` is a user-level global skill and is auto-invoked at task completion via ``~/.agents/.instructions.md``
- ``project-docs-knowledge-log-zh`` is a user-level global project-docs skill and can write the key reusable Q&A knowledge point into the current project ``docs/knowledge/`` via ``~/.agents/.instructions.md``

## Skill Routing Protocol

- For any "which skill should I use" or multi-skill orchestration task, start with ``skill-router-zh``.
- For course experiments, follow the matching experiment-specific skill first; global skills come second and fill only unspecified requirements. Without an experiment-specific skill, load course rules before the general lab workflow. Current user instructions take precedence; do not override prescribed steps, code, output, or format with general defaults.
- Before claiming completion of execution or artifact work, inspect complete raw outputs and warnings; verify correctness, required visual review and final-package versions separately. Unreviewed diagnostics or missing required evidence block full completion. Read [verification and completion rules](course/course-lab-workflow-zh/references/verification-completion.md); a zero exit code or meta-skill tests alone do not establish acceptance.
- Before any workflow initializes or restructures a project, or creates/moves applications, services, packages, modules, pages, APIs, research steps, experiments, pipelines, tests, documentation, or multi-file artifact trees, use ``project-structure-architect`` for detection, one justified path, and structural audit. Skip repeated routing only for pure content edits whose path is already uniquely fixed.
- For engineering tasks, use the ``agent-skills-ao`` lifecycle: Define -> Plan -> Build -> Verify -> Review -> Ship; for complex engineering, multi-solution implementation, architecture changes, engineering Gate, or technical spike, start with ``engineering-skill-flow-zh``.
- For strict plans, contest prompts, fixed requirements, or user-specified boundaries, add ``plan-faithful-execution-zh`` before implementation.
- Load the minimum useful set: usually one primary skill plus one verification/review skill; avoid loading the whole library.
- Full routing handbook: ``SKILL_ROUTING.zh-CN.md``.

- **制作或优化宣传文案、活动预告/回顾、结果公示、参赛手册，或校对官网与文稿、借鉴其他活动格式、按意见定点修改。不用于单纯发布操作、个人文风润色或无事实材料的凭空创作** -> `publicity-content-workflow-zh`

## Common Features

All skills support:

1. **Self-iteration mode** - give feedback after use to trigger optimization
2. **YAML frontmatter** - standard name / description fields
3. **Markdown deliverable** - substantial skill outputs must also be written to Markdown file(s) or a dedicated output folder in the current workspace; project-knowledge notes may explicitly target ``docs/knowledge/``
4. **Project document ownership** - place documents in their owning project or competition by purpose; reuse established docs/reports/paper conventions, never default to skill-output(s) or producing-skill buckets. Maintain stable topic names and a real reading index.
5. **Line limit** - every SKILL.md < 500 lines
