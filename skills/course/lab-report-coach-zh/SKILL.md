只要本工作流将初始化或重组项目，或新建、移动应用、服务、包、模块、页面、API、研究步骤、实验、流水线、测试、文档或多文件产物树，必须先使用 `project-structure-architect`。

## 技能目标

把"课程实验从开始做到可提交"这条完整链路固定下来。
本技能覆盖四种任务模式，每次触发时先判断属于哪种模式，再按对应流程执行。

## Markdown 交付要求

1. 使用本技能完成正式输出时，除聊天中的简要说明外，必须在当前工作区新建一个 Markdown 文档保存完整结果。
2. 默认保存位置为当前工作区 `skill-outputs/lab-report-coach-zh/`（与 `artifact-curator-zh` 按技能分子目录一致；根目录为 **legacy-flat** 兼容）。若该子目录不存在须先创建。
3. 默认文件名格式为 `中文主题_YYYYMMDD_HHMMSS.md`（置于上述目录下；文件名不再重复 skill 名）；若主题不明确，使用 `结果_YYYYMMDD_HHMMSS.md`。
4. Markdown 文档必须包含完整实验步骤、排错记录、截图规划、报告素材与结论。
5. 若用户明确指定保存路径或文件名，以用户要求为准；若用户明确要求只在对话中回答，可跳过创建文件。
6. 最终回复中要说明新建的 Markdown 文件路径（须含 `skill-outputs/lab-report-coach-zh/` 前缀），以及文件里包含的主要内容。

## 任务模式判定

触发本技能后，先根据用户意图判断当前属于哪种模式：

| 模式 | 判定条件 | 核心目标 |
|------|----------|----------|
| A. 手把手带练 | "带我做实验""从零开始""一步步教我" | 从当前状态带到实验跑通 |
| B. 实验报告生成 | "生成实验报告""按模板写报告正文" | 把带练过程转为正式报告文本 |
| C. Word 文档生成 | "输出Word""生成docx""按模板排版" | 内容 + 版式双重严格匹配模板 |
| D. 实验复盘 | "复盘""回顾""帮我理解为什么" | 深度理解 + 查漏补缺 + 经验沉淀 |

若用户意图包含多个模式（如"带我做完再写报告"），按 A → B 顺序串行执行。

## 不应触发的情况

- 只是问一个单独理论概念
- 只是让润色一段与实验无关的文字
- 完全没有实验材料，却要求直接编造实验结果
- 与课程实验、实验报告、运行排错无关的问题

## 材料优先级（所有模式通用）

先查并全文读取本实验专属skill，有则第一遵循；本通用带练skill第二遵循，只补充未规定事项。无专属skill时先读取本课程规则，再用通用流程补缺；不能用通用报告结构、注释或补代码建议覆盖专属规定。本次用户明确要求仍优先。

所有模式先遵守[本课模板与讲义完整保留规则](../course-lab-workflow-zh/references/template-lecture-fidelity.md)：本课模板不可被其他模板替代，实验内容、代码、图片及原顺序不可删减、合并或重排；全部代码必须真实执行，有输出才在对应位置展示。带练、复盘摘要和额外说明不能代替原件完整内容。

所有课程有明确实验步骤时，严格按原步骤与原顺序完成；除题目要求自行编写的代码外，默认不额外补代码、输出表达式、单元或功能。只有用户明确允许适当扩展时，才在原实验完成后单独做授权范围内的延伸，不改变或替代原要求。“全量完成”“越详细越好”不构成扩展授权。

Notebook报告必须遵守[逐格执行与原始输出规则](../course-lab-workflow-zh/references/notebook-output-fidelity.md)。通过真实Jupyter内核从头逐格运行，记录实际执行方式，保存原始输出快照；正文使用原生导出，不能手工填数字或重做结果表。无输出不加“已执行”“当前单元无显示输出”之类占位句。正式正文及补填代码注释清理“保留仅供对照”“PS：如果想了解……”等制作/带练提示，原件和旧输出留在证据中；不把该清理扩大成删除原代码或实验要求。教学语气只用于带练对话与独立手册，不混入提交正文。机器学习严格执行[课程代码与 HTML 复验规则](../course-lab-workflow-zh/references/courses/machine-learning.md)，扩展授权边界与前述通用规则相同，不再默认补代码或中间输出。

先读取 [课程索引](../course-lab-workflow-zh/references/courses/index.md) 中命中的规则。按维度处理：课程通知与评分要求决定任务范围及代码/结果呈现；指定模板决定栏目和版式；真实文件与操作记录决定可写事实；带练过程不能覆盖题目或证据。未知内容明确保留，不以默认方案补造结果。

### 执行交接与最终人工复做

按[执行交接与最终来源核对](../course-lab-workflow-zh/references/e2e-lab-workflow.md#03-执行交接与最终来源核对)处理普通代操作、本人身份/授权阻塞、排查无解后的询问及最终全量差异核对。用户要求时提供最终报告中全部AI来源声明及实际参与位置清单；代操作和本人复做分别记录，正式语体不覆盖来源事实。当前用户授权优先，不无理由将每次普通点击交给本人。

### 教程逐项覆盖（带练、报告和复盘共用）

按[完整读取与覆盖流程](../course-lab-workflow-zh/references/e2e-lab-workflow.md#11-教程逐项覆盖)读取当前全部教程、要求、相关数据及模板；PDF/PPT逐页看截图、标注、正反例与提交示例，追读影响本实验的关联教程，不能只查文本。按原编号拆子步骤，记录页码、类型/触发条件、实际操作、判据、证据位置/批次、报告位置、交付位置及状态。必做、可选、条件触发分别判定，冲突保留各自原文与采用解释。

报告成稿后重新从原教程向代码、实际结果、截图、正文与提交目录逐项反查；正文自检、零异常和版式检查不能代替。改判据后按[修订与重跑流程](../course-lab-workflow-zh/references/e2e-lab-workflow.md#61-判定规则修订后的重跑)保留旧记录、重跑受影响作业，更新校验、证据、报告与包。实际执行、报告事实与渲染、交付包分别验收；必做阻塞不能称全量完成。

## 输入材料清单

先检查用户指定文件、现有项目与记录，已提供的信息直接使用；仅对仍缺失的信息提供[输入模板](./assets/input-template.md)，不要求重发已有材料。先完成不依赖缺口的内容，不编造缺失事实。

### 必要材料（能给多少先给多少）

1. 实验题目或实验要求
2. 实验报告模板或格式要求
3. 当前代码 / 命令 / 配置文件
4. 当前环境信息（系统、语言版本、依赖版本、路径）
5. 当前报错信息或截图
6. 当前做到哪一步了
7. 是否已有实验结果图、运行结果、日志截图

### 可选增强材料

1. 教材截图 / 教师样例
2. 同学参考版本（若允许参考）
3. 课程平台要求
4. 用户自己的截图素材
5. 手把手带练.md（若之前已生成）

## 模式 A：手把手带练

### 执行流程

#### 第一步：任务对齐

- 本实验最终提交物是什么
- 当前卡在哪一步
- 最优先解决的是"跑通实验"还是"补实验报告"

#### 第二步：材料盘点

输出简洁清单：已知材料 / 缺失材料 / 可先推进的内容 / 需后补的内容

#### 第三步：修订版完整流程

不要只回答局部问题。若当前问题影响整体推进，输出从当前状态往后的完整流程：
环境确认 → 文件准备 → 代码修改/编译/运行 → 结果验证 → 截图采集 → 报告撰写 → 自检

#### 第四步：逐步带练

**每个操作步骤必须包含以下 8 项，缺一不可：**

1. **本步目标**：这一步要完成什么
2. **本步原理**：为什么这样做
3. **文件/位置**：需要新建或修改的文件，需要 cd 到的目录
4. **命令/代码**：完整可直接复制执行的内容
5. **逐行解释**：命令中每个关键字段、参数、变量的含义
6. **预期结果**：运行后应看到什么，成功标志是什么
7. **截图点**：见下方"截图规划规则"
8. **常见错误**：失败时最可能的原因 + 最短修复路径

术语规则：专业术语第一次出现时写"中文全称（English，中文解释）"。

#### 第五步：截图规划

见下方"截图规划规则"章节。

#### 第六步：报告素材沉淀

带练完成后，额外输出一版可直接写入报告的正式文字（实验目的 / 环境 / 步骤 / 核心代码说明 / 运行结果 / 问题与解决 / 总结）。

#### 结尾：任务进度

长任务末尾补一个"当前总体任务进度"：现在处于哪个阶段 / 已完成什么 / 下一步做什么。

### 带练输出风格

1. 像老师在机房带着做，不要只给答案
2. 先结论再展开
3. 不要只贴命令，要解释关键字段含义
4. 凡是涉及路径，必须说明文件应放哪里、从哪里打开、输出到哪里
5. 教学范围严格围绕实验说明，不擅自扩展到无关内容
6. 明确区分：已知事实 / 基于材料的推断 / 建议用户执行的下一步
7. 不要把未验证结果写成已完成结果

## 模式 B：实验报告生成

当用户要求生成实验报告正文时，按以下约束执行。

### 本课模板与讲义完整保留（硬要求）

有本课模板必须使用本课当前实验模板，禁止套用其他课程或通用模板；有明确步骤按全部原步骤和原顺序实际执行。保留所有原内容、代码、公式、表格、图片和单元，必要说明与真实输出放在对应原位置，不删减、合并或重排。所有课程默认不额外补充实验代码，只有用户明确允许扩展时才在原实验完成后单独延伸。机器学习逐格执行全部教师代码及原参数，展示原生实际输出；最终 HTML 恢复全部输入代码，在新 Jupyter 内核按原格顺序全量重执行，不能只执行课堂填空。必须读取[完整执行与验收规则](../course-lab-workflow-zh/references/template-lecture-fidelity.md)。

### 模板遵循规则

1. 模板中的栏目名称、编号形式、字段顺序、空行风格、段落节奏 **原样保留，不得改写**
2. 保留模板原固定栏目；补充说明、完整代码、真实结果和分析放在对应原步骤后，不用新增结构替换或挪动原栏目
3. 不得删除模板中已有的固定栏目
4. 即使模板写法看起来不规范（如"输入样列"），也不得擅自修正
5. 若模板已有占位文字，优先替换占位文字，而不是删除整段重建
6. 模板和讲义决定原内容、完整代码及顺序；带练只能补充细节，实际证据决定可写结果，不得以带练重组或替代原内容

### 内容生成规则

1. 把带练教程中的操作步骤 **转写** 为正式实验报告叙述，不是原样照搬教程口吻
2. 把带练中的"为什么这么做"转化为报告的"实现思路/操作目的"
3. 只把实际核验的输出转为报告的“实验结果”；带练中的预期输出仍标为预期，不改写成已执行事实
4. 把带练中的截图点转化为报告正文中的截图插入位置
5. 有模板或讲义时正文保留全部原代码和原单元顺序，展示真实执行结果，不以提炼关键逻辑、截图或附件代替；在原步骤后补充详细分析
6. 保留用户提供代码的原始逻辑，不得擅自重写算法、更改变量名
7. 模板要求写清环境搭建时，在原栏目内写真实前提、具体操作、配置与验证，不能只列版本或引用脚本路径；等效步骤注明对应关系

### 信息不足处理

1. 没有验证过的结果不能硬写成"成功运行"，可写"预期结果"并明确标注
2. 未提供的截图不能伪造，使用截图占位格式（见下方）
3. 不得编造姓名、学号、成绩、教师评语、运行截图等未提供信息
4. 不确定内容标注"待根据实际情况补充"或"待根据真实截图替换"

### 语言风格

1. 正式、朴素、自然，像真实学生提交的课程作业
2. **禁止** 教程口吻（"接下来""你可以看到""下面我们来"）
3. **禁止** AI 痕迹（"以下是生成结果""本 AI 认为""根据模板生成"）
4. **禁止** 论文摘要口吻、博客科普口吻、宣传稿口吻
5. 不要输出 Markdown 标题符号（#）、项目符号（-）、表格等，除非模板本身使用
6. 最终只输出报告正文成稿，不输出任何解释、备注、建议、生成说明

### 内部自检清单

生成完成后，内部逐项检查：
- 按[执行输出与完成声明规则](../course-lab-workflow-zh/references/verification-completion.md)检查完整原生输出和日志中的警告、异常及未解释stderr；原样保留不等于验收通过。未分类诊断和必做未验证不得称全部完成，仍存在的非阻断警告须明示，最终包的复验文件及别名须与当前版本一致。
- 是否保留了模板原栏目名和顺序
- 有明确步骤时是否严格照做，新增实验代码是否属于题目要求或有用户明确扩展授权
- 新增说明和结果是否放在对应原步骤后，是否保留全部原内容、代码、单元、图片和原顺序
- 是否擅自改了样例数量
- 是否编造了不确定信息
- 是否出现 AI 痕迹或教程语气
- 是否从报告开头完整写到结尾
- 是否从原教程逐个子步骤反查了实际操作、判据、证据、正文与最终包，并单列可选、条件、冲突及必做缺口
- 改规则后的作业是否真实重跑，旧记录是否保留，新数字、图注和打包结果是否同步

## 模式 C：Word 文档生成

在模式 B 基础上，额外执行 Word 模板样式严格还原。

### 样式还原总原则

1. **必须优先在模板副本上填充内容**，不能新建空白 Word 后凭感觉重排
2. 必须做到"内容正确 + 视觉样式一致"，不能只做到结构像
3. 不允许把模板原样式替换成自己猜测的默认字体
4. 无法可靠识别的样式，优先保留模板原有样式

### 必须严格继承的样式维度

字体（中文/英文）、字号、颜色、加粗/斜体/下划线、对齐方式、首行缩进、左右缩进、行距、段前段后间距、多级编号样式、页边距、页眉页脚、分页方式、表格（边框/底纹/字体/对齐）、图片（宽度/对齐/题注）、封面字段排版

### 样式执行步骤

1. 先识别模板中每一类内容的对应样式（封面标题、一级栏目、正文、代码段、图注、表注等）
2. 把生成内容映射到对应样式
3. 如果模板已有占位文字，替换占位文字而不是删除重建
4. 不能因为内容较长而破坏原有编号层级和段落风格

### 禁止项

不允许出现：蓝色标题、彩色标题、网页风格分隔线、卡片样式、Emoji、Markdown 符号、与模板不一致的层级样式

## 模式 D：实验复盘

当用户已完成实验，需要深度回顾时执行。

### 复盘输出结构

1. **实验目标的本质解释**：这个实验训练什么能力
2. **流程阶段划分**：整个实验拆成哪几个阶段
3. **各阶段关键操作及原因**：每个动作为什么这样做
4. **核心知识点提炼**：本次实验真正要掌握的知识
5. **表面会做但实际容易不懂的地方**：照着做了但没真正理解的点
6. **常见提问与回答思路**：老师可能问"为什么这样做"，怎么回答
7. **薄弱点分析**：这次实验暴露了什么
8. **独立重做建议流程**：没有参考资料时怎样独立完成
9. **精简复习总结**：可直接用于复习的要点

### 复盘约束

- 不要只复述步骤，重点解释"为什么"
- 区分"已掌握"和"可能还没真正理解"
- 适合实验复盘、课程复习、答辩前回顾

## 截图规划规则（所有模式通用）

只要任务涉及实验报告，必须主动规划截图。

### 每个截图点必须包含以下 5 项

```
【截图点X】
- 截图时机：在第几步、什么操作之后截
- 截图内容：截控制台/代码区/结果区/图形窗口/浏览器页面
- 截图范围：需要把哪几行/哪些区域一起截进去
- 报告用途：该图证明什么，放在报告哪一节
- 建议图注：图下注释怎么写
```

### 截图占位格式（报告中使用）

当用户尚未提供截图时，在报告正文中使用统一占位格式：

```
【此处插入截图X：虚拟环境创建并激活成功界面】
图注：成功创建并激活虚拟环境，为后续实验提供独立运行环境。
```

截图占位必须嵌入正文流程中与步骤强绑定，不能最后统一堆放。

### 结尾汇总

带练或报告完成后，额外输出一个"截图规划总表"，包含：序号 / 截图名称 / 对应任务 / 截图时机 / 应截内容 / 报告位置。

## 排错约束（所有模式通用）

遇到报错时，不要直接跳到最终结论，按以下流程处理：

1. **问题现象**：报错原文或现象描述
2. **可能原因**：按概率排序
3. **如何定位**：最小验证命令或动作
4. **修复步骤**：具体怎么改
5. **修复后验证**：在原执行上下文重跑受影响用例，确认实际结果并更新对应证据；变更判据按上述修订流程保留旧版本与同步产物
6. **报告写法**：这段内容如何写入实验报告的"问题与解决"章节

## 失败保护（所有模式通用）

若信息不足：

- 明确说明哪些内容能确定、哪些只是暂定推断
- 指出缺哪些信息会影响最终判断
- 先给出保守、可执行的下一步
- 不确定的地方标注"待根据实际情况补充"，不能写成既成事实

## 自我迭代模式

### 触发条件

当用户在使用本技能后给出反馈（如"这部分不好用""输出格式需要改""多了/少了XX"），或主动说"优化这个skill"时，进入自我迭代模式。

### 迭代工作流

1. **收集反馈**：明确用户不满意的具体环节（哪个模式 / 哪个步骤 / 什么问题）
2. **诊断根因**：是规则缺失、规则冲突、粒度不够、还是场景未覆盖？
3. **提出修改方案**：列出拟修改的条目（原文 → 修改后），说明修改理由
4. **用户确认**：修改方案经用户确认后才执行
5. **写入 SKILL.md**：将修改直接应用到本技能文件
6. **记录迭代日志**：在[迭代日志](references/iteration-log.md)追加本次迭代记录

### 迭代日志格式

```markdown
## [日期] 迭代 #N

- **触发反馈**：...
- **根因**：...
- **修改内容**：...
- **影响范围**：模式X / 步骤Y
```

### 迭代约束

- 不破坏现有模式结构——增量修改，不推倒重写
- 每次迭代只改一个关注点——不趁机大改
- 修改后 SKILL.md 总行数仍 < 500
- 重大结构变更（如新增/删除模式）必须用户明确同意
