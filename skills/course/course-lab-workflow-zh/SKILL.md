# 通用实验课工作流

## 1. 目标与边界

将一次实验组织为可执行、可理解、可复现、可核验、符合本课程模板的交付过程：

**材料核对 → 环境适配 → 分模块带练 → 证据验收 → 按模板成稿。**

同时维护三条链：学习链解释为什么，执行链说明怎么做，证据链证明实际做到了什么。不能用篇幅、截图数量或“程序未报错”替代验收。

默认中文，首行给结论或当前动作。教学用生活例子，正式报告用客观、简洁语言。专业术语首次出现时给英文全称和中文解释；产品名没有公认全称时不编造。数学公式用 LaTeX。

只处理本次请求所需阶段，不把单点报错升级为整份报告，不为纯教程额外制作 Word，不把科研、竞赛和社会实践项目自动归入实验课。

## 1.1 本课模板与讲义完整保留（硬要求）

有本课模板必须使用本课当前实验模板，禁止套用其他课程、通用模板或自创章节。所有课程实验只要有明确的实验步骤，就严格按原步骤、原内容和原顺序完成，不删减、合并或重排。除题目要求自行编写的代码外，默认不额外补充代码、输出表达式、代码单元或功能；“完整完成”“越详细越好”不等于允许扩展。只有用户明确说“可以适当扩展”或同等授权时，才在原实验完成后单独做授权范围内的延伸，不用扩展替代或改变原要求。机器学习允许并尽可能补充仅展示已有数据或计算结果的代码，具体边界见课程规则；该例外不授权其他新增代码。制作提示与旧输出的清理例外见下文。

机器学习实验逐格保留并执行全部教师单元及原参数；允许并尽可能在对应原格之后用独立单元添加 `.head()`、`shape`、已有数组切片或 `print(已有结果)` 等纯展示代码，不改变原单元。除此之外不额外添加诊断逻辑、随机种子、预处理、模型、指标计算、交叉验证或绘图代码。原格和展示格有实际输出时紧跟代码展示，无输出不占位。不能只填课堂练习或只跑替代脚本。最终 HTML 必须恢复全部输入代码，在干净 Jupyter 内核按格全量重执行；规则及最小修复边界见机器学习课程规则。

执行或编写任何有模板/讲义的实验前，必须读取[模板与讲义完整保留规则](references/template-lecture-fidelity.md)。本规则优先于本技能内提炼、重组或按依赖调整顺序的旧建议；用户明确限定的局部修改仍守住该边界。

Notebook及其导出报告还必须读取[逐格执行与原始输出规则](references/notebook-output-fidelity.md)：通过真实Jupyter内核从头逐格执行，正文使用原生输出，有输出才展示，无输出不加占位说明。正式报告清理制作/带练提示及相应注释；讲义旧结果在原件备份保留，正文默认以当前实测输出替换。此清理例外不授权删实验步骤、考核要求、理论或原代码。发现旧规则冲突时向用户说明来源和采用方式。

## 2. 选择模式与按需读取

| 当前请求 | 执行范围 | 需要读取 |
|---|---|---|
| 端到端代做（执行＋取证＋成稿＋小白手册） | 材料核对→环境适配→执行方案→逐步执行与记录→证据链→按模板成稿→验收 | [端到端代做流程](references/e2e-lab-workflow.md)、[任务卡](assets/task-card.md)、[报告与证据规则](references/report-evidence.md)、[课程适配器](references/course-adapters.md)、[验收清单](assets/acceptance-checklist.md) |
| 梳理实验/制定方案 | 需求映射与依赖顺序 | [任务卡](assets/task-card.md) |
| 从零带练/讲解命令代码 | 当前模块或明确要求的完整教程 | [教学与工程规则](references/teaching-engineering.md)、[模块模板](assets/tutorial-module.md) |
| 报错/结果不对 | 定位、最小修复、原用例复验 | [教学与工程规则](references/teaching-engineering.md) |
| 生成报告/按模板排版 | 证据审查、母版继承、文档交付 | [报告与证据规则](references/report-evidence.md)、[实验记录模板](assets/lab-record.md) |
| 只修改指定章节 | 锁定修改边界并验证其他内容 | [报告与证据规则](references/report-evidence.md) |
| 复盘/归档/沉淀新经验 | 总结适用条件、限制和验证办法 | [项目依据与迁移](references/project-basis.md) |

端到端代做是指用户要求“直接把实验做完”而不是逐步带练：可以省略教学对话轮次，但不能省略材料核对、执行方案、逐步验证、证据采集与成稿。该模式默认交付两份产物：供本人理解和复现的小白教学手册，以及按课程模板撰写的正式报告；手册与报告中的每条材料、命令、结果和结论都要能指向真实文件、命令输出或证据编号，无法追溯的写“未核验”，不编造版本、路径、报错或数据。

**执行纪律：完成已授权工作，真实阻塞即时交接。**普通实验界面操作可以由代理代执行；是否由本人亲手操作，以本次用户要求和课程明确条款为准。本人身份、登录、授权、教师许可、外部材料等确实无法代办的前置条件，在发生处暂停依赖步骤并显示具体指导，不统一拖到最后。问题先独立定位并查阅相应版本的可靠资料，修复后在原流程复验；仍无解时询问用户，禁止擅自跳过必做项、降低判据或以替代演示宣布完成。不依赖缺口的工作继续推进。具体交接与最终人工复做见[执行交接规则](references/e2e-lab-workflow.md#03-执行交接与最终来源核对)。

识别课程后只读[课程适配器](references/course-adapters.md)中的相关小节，不把全部技术栈同时加载。新课程使用通用流程，不虚构已有课程规则。

阶段自检使用[验收清单](assets/acceptance-checklist.md)。需要机器检查实验台账时使用[证据台账模板](assets/evidence-register.json)和[检查脚本](scripts/validate.py)。修改此 Skill 后参考[行为验收用例](evals/cases.json)及[测试说明](tests/README.md)。

## 2.1 通用与课程路由

先查本实验是否有用户指定或材料目录、skills库中与当前课程、实验编号及版本匹配的专属skill；有则先全文读取。**本实验专属skill第一遵循，通用/全局skill第二遵循，仅补充专属skill未规定的事项。**没有实验专属skill时，先读 [课程索引](references/courses/index.md) 中命中的课程规则，再由通用流程补缺。通用模板、输出结构、追加代码或默认流程不得覆盖专属规定；本次用户明确要求仍优先。历史运行状态留在课程目录，不写死进通用skill。

评分复核按“评语原文 → 扣分证据 → 修订项 → 实际复验 → 剩余缺口”闭环。没有官方评分程序时只报告有依据的内部评估，不编造精确教师分数；必做项缺证据时，不能靠其他项加分宣布 A+。评论率、代码行数、图片数只作诊断，不用无意义注释、冗长代码或重复图片刷分。

注释验收必须检查最终交付的报告正文和源文件两处。课程有比例条款时记录原文、统计范围、分母和逐模块缺口；不能只检查存在一个注释，也不能让大量短SQL注释掩盖测试、业务逻辑的零注释。注释解释参数、设计原因、执行顺序、边界或断言意义，正文另写操作、预期、观察和原因。六个逻辑要素等结构要求须在原模板内有可识别的子标题，不能以隐含覆盖代替。没有可复现的评分算法时，用通过项、缺口与风险替代精确内部总分；撤回已被新证据推翻的自评分并同步交付说明。

## 3. 不可突破的规则

1. **材料先读，结果有据。**先检索当前上传、用户指定的旧文件或项目，不能用文件名、搜索片段或旧记忆冒充全文核对。版本号、路径、端口、成绩、报错、截图和运行结果均须有来源。
2. **按维度处理冲突。**实验内容与评分条款以本课程最新要求为准；版式结构以当前明确指定模板为准；事实以本次可追溯证据为准；历史报告只作样式或方法参考。用户提出偏离课程要求时说明差异，不能擅称教师已经认可。
3. **课程与实验隔离。**以“课程＋实验名称/编号＋版本”识别任务；同为“实验七”不代表同一项目。旧日期、学号、主机、代码、图片、模型名及成功状态不能自动带入新实验。
4. **只做已授权的操作。**读取和检查优先；修改前看差异、影响范围和可回退方式。不得擅自删除数据、格式化存储、重置仓库、开放端口、改共享主机全局设置或提升权限。
5. **报告叙述按用户执行口径。**课程的“知识点疑问/解答”等固定栏目按原字段写课程内容与实际验证。用户表示已亲自完成或重新执行后，报告正文按其执行记录撰写：删除AI说明与间接说明（含间接暗示），减少“本人”，不写提交/上传/打包/审阅安排、制作与截图过程说明、免责式否定等状态元叙述。规则与例子见[报告叙述归属与措辞](references/report-evidence.md#8-报告叙述归属与措辞)。成稿后交独立agent自检措辞是否自然、与个人撰写无异；实际操作来源、交接与复做差异只记内部过程记录，不写进报告正文。
6. **证据不足仍有可用产物。**先完成可核实内容，输出待补充版、操作指南或最小复现；不反复追问已知信息，不把建议写成已经执行，也不承诺后台继续工作。

## 4. 阶段一：材料核对

完整读取当前实验的题目、全部教程、评分要求、指定模板、相关数据与源码；参考报告只在获准范围内使用。PDF/PPT须逐页检查截图、标注、表格、脚注、正反例和提交示例，不能仅凭文本提取宣称读完。检查影响本实验的关联外部教程及对应版本；失效链接与缺失材料记录实际核查结果，先查已有材料再向用户索取。具体动作见[教程覆盖流程](references/e2e-lab-workflow.md#11-教程逐项覆盖)。

建立[任务卡](assets/task-card.md)，至少明确：本次目标、课程身份、当前阶段、输入与输出、已有材料、缺失项、禁止改动项、验收要求。已知项直接填写；未知但不阻断的项写“未核验”，不能为了填表猜测。

建立需求映射：

`教程原编号/子步骤＋来源页码 → 类型/触发条件 → 实际操作/实现 → 独立验证条件 → 证据位置/批次 → 报告章节/页码 → 交付位置 → 状态`

每个子步骤单独一行，不用“环境、运行、结果”几个概括项代替全文覆盖。依据原文与用户本次范围区分必做、可选、条件触发；冲突单列原文、来源、采用解释与待确认状态，不把自行解释冒充教师要求。先完成必做及已纳入范围的选做项。下载地址、兼容性和参数查对应版本的官方资料，不能上网替代读取用户文件。

**本阶段出口：**清楚要完成什么、用什么材料、怎样算完成，以及哪些信息仍会影响执行或提交。

## 5. 阶段二：环境适配

只检查会影响本任务的环境项：操作系统、机器角色、Shell（命令解释器）、账号权限、当前目录、源码版本、语言/组件依赖、输入数据、监听端口和必要网络条件。

必须区分本地 Windows、Linux/WSL、虚拟机、远程服务器、容器及应用内交互终端。每次切换机器、用户或解释器都重新说明；不同环境路径不得混写。

已有可用环境优先复用，不默认重装或升级。用户偏好 Hadoop 3.x、清华镜像等仅在课程未锁版本、来源可用且相互兼容时采用。课程指定版本优先。

替代环境建立“原要求—替代操作—可覆盖目标—未覆盖目标—认可状态”对照。远程 Linux 可以支持部分命令和联网目标，但不能自动证明完成了虚拟机安装或全部 host/guest 功能。

给出最小验证动作，区分预期结果与实际输出。不能仅凭版本命令、进程存在、端口开放或网页可见，推断业务链路已通过。

**本阶段出口：**下一步在何处、以谁的身份、使用哪种终端、操作哪些文件已经明确；阻断问题已定位或显式保留。

## 6. 阶段三：分模块带练与实现

先给总体链路；有讲义按原步骤顺序带练，无讲义才按依赖安排。单批操作原则上不超过五步，每步一个主要动作；完整教程可包含多个批次，不因五步限制遗漏实验内容。

每个模块遵循[模块模板](assets/tutorial-module.md)，保留七项：

1. 目标与前置输入：本模块接收什么，服务哪个实验要求。
2. 生活例子与工程定位：先直观理解，再解释所在系统层次。
3. 执行上下文：机器、账号、终端、工作目录、依赖文件。
4. 实际操作：可复制命令/完整必要代码，首次语法拆解，解释怎么做和为什么。
5. 检查与证据：预期行为、实际观察、成功标准、截图/日志位置。
6. 知识点与易混点：只讲本模块必需概念，可配一道自测及答案。
7. 逻辑链路与知识点集合（**每个模块末尾必写，缺此项视为模块未完成**）：先用一句话串起"上一模块输出 → 本模块输入 → 处理 → 本模块输出 → 下一模块用途"，再把本模块知识点按这条链路顺序收成集合（概念 / 命令 / 参数 / 判据 / 易错点各归其位，不散落正文）；有依据时补一个旧项目关联，没有真实关联就省略，不编造。

代码分析遵循“模块职责 → 调用前提 → 输入输出 → 关键变量 → 核心分支 → 上下游 → 设计理由”。普通工程优先复用基础组件；课程要求实现的核心算法或内核模块不得用现成库替代而绕过考核。

对现有仓库先读取约束与代码，再最小修改；不另起一套项目，不无故重构，不覆盖用户未提交改动。写明修改文件、配置生效范围、启动次序、验证命令及结果保存位置。

排错顺序是：**位置与现象 → 证据检查 → 原因/候选原因 → 最小修复 → 原用例复验 → 关联回归**。未经验证的原因只能写成推断；“建议修复”不等于“已经修复”。

**本阶段出口：**教学能从已有输入执行到可检查输出；代码、命令、文件路径和证据标识相互一致。

## 7. 阶段四：证据与验收

验收前读取[执行输出与完成声明规则](references/verification-completion.md)，检查全部原生输出和完整日志中的警告、异常及未解释 stderr；原样保留输出是来源要求，不等于结果合格。未分类诊断阻断完成声明，已证实非阻断且仍存在的警告须降级并明示，题目要求的预期异常有依据才可验收。

用[输出检查脚本](scripts/audit_run_outputs.py)检查真实快照及完整运行/驱动/导出日志，再分别核对结果正确性、模板覆盖、必要的应用/视觉验证及最终包中的全部正式入口和别名。退出码0、零异常或Skill单测通过均不能代替这些核验；必做项缺当前证据不得称全部完成。

使用[实验记录模板](assets/lab-record.md)记录真实尝试；自动检查时建立 JSON 台账。台账将“执行状态”与“证据状态”分离：

- 执行状态：未开始、已尝试、通过、失败、阻塞、不适用。
- 证据状态：已核验、用户自述未复核、材料待复核、示例、缺失。

证据应对应课程、实验、阶段、运行批次及代码/配置。判定规则、代码、输入或配置变化时，先保留旧版本与原始结果，再按[修订与重跑流程](references/e2e-lab-workflow.md#61-判定规则修订后的重跑)重执行受影响作业，更新校验、截图、报告及打包结果；不把新结果倒填为旧运行。未受影响证据须注明仍有效的依据。预期报错测试写清意图和实际结果。

截图须证明对应要求；保留命令/操作、关键输出、必要身份或任务标识。姓名/学号使用课程要求允许的真实标识；不得通过换水印把他人截图变成本人结果。保护密码、令牌和私钥。

“编译通过”“本地样例通过”“用户环境通过”“官方评测通过”“报告可提交”分别判断。数据实验验证内容、数量、字段、条件及结果一致性；只有界面图片不足以证明计算正确。

**本阶段出口：**每项必做要求有明确状态和可追溯证据；未通过、未复核和缺失项单列，不用整体“完成”掩盖。

### 7.1 每个实验结束时必须留的两份过程记录（硬要求）

报告只回答"做出了什么"，过程记录回答"怎么做的、怎么写的"。**实验一结束（无论是否已成稿）就要在交付目录各留一份，缺一份不算收尾**，用途是让教师、下一个 AI、未来的自己都能顺着记录复核，也用来防止 AI 事后编造步骤、命令、报错或数据。两份都写进[实验记录模板](assets/lab-record.md)，不另建平行文档：

1. **实验操作流程记录**（lab-record §2、§2.1）：按真实时间顺序写清每一步——执行位置与目录、输入、具体命令或操作、预期、实际输出、退出码或报错原文、结果保存路径、对应证据ID。命令要可复制；报错保留原文，不事后美化；中途放弃、重做、试错的尝试也要留痕并标注执行状态。
2. **报告撰写流程记录**（lab-record §2.2）：逐栏目说明该栏目的事实来自哪条证据或哪个文件（报告栏目 → 证据ID → 原始材料路径）、哪些文字由 AI 起草、人工改了哪里、数字与图表题注如何核对、成稿用了什么工具链（母版、脚本、导出步骤）以及版式实测值。**报告里出现而在本记录中找不到来源的内容，一律按未核验处理并从报告中移除。**

两份记录要能互相对上：报告里的每个数值、图号、结论，都要能在操作流程记录里找到对应的那次真实执行，或明确标注为推算、假设。

## 8. 阶段五：成稿、局部修改与交付

先读取[报告与证据规则](references/report-evidence.md)。有指定 Word 时以原文件副本为母版，继承版式和固定栏目；其他报告只能在明确授权范围内提供字体等视觉参考。

有模板或讲义时按原章节、原步骤和原单元格顺序填充全部内容、完整代码、真实结果与分析，不另造“实验目的/原理—实现方法—关键代码—结果”的结构替换原件。仅在没有模板和讲义时才自行安排结构。正式报告不保留“小白理解”“你现在”“成功标志”“当前总体任务进度”等带练/聊天表达。

证据呈现先读取课程规则，分别决定核心代码、配置、命令和运行结果的形式。课程要求可复制代码时，正文必须保留真实源码与有效注释，截图不能替代；课程要求运行截图时，必须配真实结果图。未指定时允许文字代码与真实结果截图/日志组合，不把某课程的截图偏好泛化。附件不能代替正文的方法、关键实现与分析。无截图时按模板预留规范图位，缺失材料集中管理。

本次课程模板决定章节、编号、字数、文件名和是否需要 AI Report；不得把某课七大栏目、80 字心得、8000 字正文、附录 A/B/C/D 等变成所有课程的硬规则。

仅修改指定章节时锁定其他内容；检查标题、正文、表格、图片、页眉页脚和样式差异。修改引起分页流动时如实说明，不能声称文件字节级“原封不动”。

根据用户要求生成真实 `.md`、`.docx` 或其他文件。需要文档工具时先读当前平台对应的文件技能；工具不可用时给可用替代物并说明限制，不能把纯文本改扩展名冒充 Word。

成稿后重新打开原教程与要求，按原编号反查代码、实际结果、截图、正文与最终交付目录；正文自检、零异常统计和格式检查不能替代该反查。模板要求写清搭建步骤时，正文写实际前提、操作、配置和验证，不能只列环境版本或脚本路径。再渲染检查封面、正文、表格、长代码、图片、附录及必要的全部页面；未能渲染标“视觉未复核”。必做项或证据缺失时交付“待补充版”，不得称“可直接提交”。

最终回复只给产物、关键缺口及必要用法，不再粘贴整份报告。长任务在聊天末尾补“当前总体任务进度”，不写进正式报告，也不编造百分比或时间估计。

## 9. 继续任务与经验归档

用户说“继续”时先读该实验状态记录，恢复最近已核验步骤和当前阻塞点，不能从头重装。源材料或配置变化时更新受影响需求、教程、测试与报告。

归档经验写成“触发条件—适用前提—操作—验证—风险—反例”，不把偶然成功的命令固化为万能解法。依据[项目迁移规则](references/project-basis.md)关联知识，但不迁移历史结果。

可选工作目录为 `lab-work/<course>/<lab>/`，下设 `materials/`、`outputs/`、`evidence/`、`report/`；已有课程仓库保持原结构，只添加不冲突的记录文件。

**交付位置优先放在课程文件夹。**课程实验的正式产物（报告、证据、站点源码、说明）写入该课程自己的文件夹（例如课程云盘下的“实验/<实验名>/”），不要把最终交付物只留在临时会话工作区或 ChatGPT 工作区里。会话工作区只作为临时草稿与工具目录；任务收尾时把最终文件回写到课程文件夹，并核对回写后的文件能打开、页数与版式与工作区版本一致。用户已指定过课程材料根目录时按其指定的位置，不再另建平行目录。

正式目录里只保留一个最终文件名：中间版本写到临时目录，确认后覆盖正式文件；不要留下 `-v2/-v3` 之类的副本，避免用户拿错版本。保存前先确认目标文件没有被 WPS/Word 打开（同目录会有 `~$` 锁文件），被占用时先提示关闭，不要反复重试覆盖。多课程同时进行时，用[课程登记表](assets/course-registry.md)记录每门课的材料根目录、模板、实验地点与命名规则，避免每次重复询问。

## 10. 自检出口

每次实验报告自检及交付必须执行[2号独立审查、3号独立评分与至少五轮循环](references/independent-report-review.md)：1号主代理制作/修改，两个不同的真实subagent分别审查与评分，原件逐项反查、截图完整及重点红框、顺序/要求、详细程度和版式美观都在独立审查范围。默认至少五轮或有完整依据的满分；不能由作者模拟独立检查或自评满分收尾。用户已持续授权本实验报告范围的子代理调用，其他任务不因此自动委派。

核对[验收清单](assets/acceptance-checklist.md)。核心检查是：需求有没有漏、环境有没有串、命令能否复制、模块有无解释与链路、结果有无证据、报告有无套旧内容、模板有没有被破坏、叙述口径是否符合、文件能否打开、完成状态是否准确。

Web报告必须执行[教师踩分点与注释核验](references/courses/web-app.md)：当前原材料中的功能、代码质量/注释、实验深度、结果、结构、心得及提交条款逐项回填；阶段名称不能替代全部踩分点及各自证据。

交付前还必须补齐五项：

1. **未完善项清单**：把未提供的材料、未核验的信息、未覆盖的目标、待教师确认的规则逐条列出，写明影响范围与补齐办法；不能用整体“已完成”盖住缺口。
2. **全量自检**：从原教程逐个子步骤核对“来源/类型 → 实际操作 → 判据 → 证据/批次 → 报告位置 → 交付位置 → 状态”，包括模板提示与提交目录示例。分别给出实验执行、报告事实与渲染、交付包完整性三类结论；所有本次必做项及必要核验闭环才可称全量完成，可选未执行、条件未触发、必做阻塞及未提交分别记录。
3. **内容正确性与文风核查**：数字、版本、端口、路径、图表题注与结论互相对得上，前后不矛盾；正式报告按[报告与证据规则](references/report-evidence.md)第 11 节做措辞清理。去AI痕迹只改表达，不改事实、不删真实问题记录；清理后按第 8 节复核归属、状态元叙述和措辞自然度，不再生成AI声明位置清单。
4. **格式全量自检**：按[报告与证据规则](references/report-evidence.md)第 12 节的版式清单逐项核对——版心与页面设置、封面字段是否落在模板空格内且单行显示、字体字号、图片宽度与居中、表格是否超出正文框、图表编号与跨页、空白页与页面利用率、页眉页脚、残留占位标记、文件能否打开与导出。结论要写实测值（例如正文文字 x 范围、图片宽度、每页墨迹占比），不写“看起来没问题”。
5. **措辞归属与自然度自检**：报告正文AI说明与间接说明为零、无“本人”过度强调、无状态/流程/不确定性元叙述；交独立agent复核措辞是否自然、与个人撰写无异，结论记内部记录。实际参与来源留在过程记录，正文与提交包保持同一版本。

版式测量与修正用现成脚本，不要每次现写：[版式自检](assets/scripts/check_layout.ps1)、[版式修正](assets/scripts/fix_docx_layout.ps1)、[母版填充骨架](assets/scripts/fill_docx_report.ps1)、[窗口截图](assets/scripts/capture-window.ps1)、[截图裁剪](assets/scripts/trim-shots.ps1)。截图宽度小于 8cm 时在交付说明里提示打印可读性风险。

**验证记录不要手抄。**修订本 Skill 后先运行[检查脚本](scripts/validate.py)并把输出覆盖到 `tests/results/`，再在[验证记录](VALIDATION.md)里引用该结果，不要凭记忆写行数、链接数或用例数。

脚本只辅助检查文件结构和台账逻辑，不能认定截图真实、程序正确、教师认可、版式完美或模型一定会遵循本 Skill。任何自动检查通过都不得替代对应人工/工具核验。


## 截图、完整性与美观的联合验收

证据呈现先读取课程规则，分别决定核心代码、配置、命令和运行结果的形式。课程要求可复制代码时，正文必须保留真实源码与有效注释，截图不能替代；课程要求运行截图时，必须配真实结果图。未指定时允许文字代码与真实结果截图/日志组合，不把某课程的截图偏好泛化。附件不能代替正文的方法、关键实现与分析。

每个必做小题逐项覆盖：要求与目标 → 实际操作 → 符合课程呈现规则的关键实现 → 实际结果截图 → 结果解释与结论。只给行数、文件路径、成功一句话或截图堆砌均不算详细完成；附件不能代替正文对关键步骤与结果的说明。篇幅以覆盖全部要求为准，不为凑页数重复内容。

截图必须来自真实应用，不得用绘图、排版工具或合成页面伪造编辑器、终端或运行结果。代码节选须标明源文件与范围；仅排版的副本须说明，不能当执行证据。已保存日志在编辑器中的截图须标注“原始日志”，不得声称为本次新运行。保留原图和来源，裁剪不得删除失败信息、改值或更换身份。截图前隐藏或把Computer Use的发光指针、控制浮层和鼠标指针移出截图区域，截后逐张放大检查；发现即重截，不得涂改遮盖。

继承课程模板，统一标题、段落和图注；正文左对齐，图片等比例居中。按最终打印尺寸逐张检查代码与结果是否可读；过长内容分段截取并说明范围。逐页渲染检查，消除图片截断、图注孤立、标题落页尾、挤压和无意义空白。内容完整性与渲染版式都通过后才可称完成；无法核验项明确保留。
