# 执行输出与完成声明验收

用于需要真实执行、结果验证或制品验收的任务；纯问答不套用本流程。专属任务规则决定要验证什么，本规则补充如何检查证据和限制完成声明，不授权增加实验代码、修改教师参数或扩大任务。

## 判定前必须检查

1. 从本次用户要求和当前原材料列出必做验收项。执行完成、结果正确、源码/原生输出一致、内容覆盖、必要的应用/渲染核验和交付包一致性分别判定；某一项通过不代表其他项通过。
2. 检查完整原始 stdout、stderr、Notebook 每格的全部 outputs，以及构建、导出、驱动、渲染日志；不能只看退出码、最后几行、连续执行编号或 `output_type=error`。截断日志或缺失日志是未核验，不能按无警告处理。数值、预测条数、图像和收敛等正确性用任务自身判据验证，不靠异常计数替代。
3. 每条诊断保留原文、来源/单元、依赖环境、证据哈希、原因、影响、处理及复验依据。来源真实与结果合格是两项检查；原样保留警告不等于警告已获验收。
4. 使用 [输出检查脚本](../scripts/audit_run_outputs.py) 检查 Notebook/完整文本日志；警告即使不在 stderr 也检查。脚本未覆盖的二进制、应用界面、图像或特殊日志另用实际工具核验。脚本只能发现常见诊断和校验声明一致性，不能证明结果正确、原材料覆盖充分、截图真实或教师认可。

## 警告与异常的处理

| 情况 | 判定与动作 |
|---|---|
| 未分类警告、未解释 stderr、异常影响待确认 | BLOCK：先诊断，不得声明全部完成 |
| 收敛失败、拟合失败、无效指标、非预期异常或错误结果 | BLOCK：修复并按原入口真实复验；警告也可能影响结果 |
| 已核实不影响当前结果、仍存在的弃用/环境/性能警告 | CAUTION：记录原因和依据，交付时明示；不得称零警告、无问题或全部验收通过 |
| 题目明确要求触发的警告/错误、正常 stderr 进度 | 有原要求或明确用途、实际结果符合判据且有复核证据时，可记为预期；仍保留诊断原文和实际数量 |
| 当前批次已解决诊断 | 以新执行的原始输出为准；不能给旧快照填“已解决”而继续把它当新版证据 |

优先用与原代码匹配的隔离环境解决版本冲突，并记录真实内核、解释器、依赖和工作目录；不默认升级、不擅自全局降级。不得用过滤警告、删除输出、调低日志级别或更改目标来制造通过。严格保留教师代码时，非填空修正仍遵守已有授权边界；预期报错不是修改原要求的理由。

## 最终版本与声明

- 修改代码、数据、内核、依赖或验收判据后保留旧批次，重跑受影响流程。新版源文件、输出、报告及复现说明必须属于同一批次；未受影响旧证据注明仍有效的依据。
- 验收最终交付入口：需要时从最终 HTML 回读代码重跑、用实际评测入口或打开最终文件。交付包解包后逐一核对正式文件、复验文件及其别名、依赖和数据的哈希；不能只检查 ZIP 可打开或 CRC 正确。历史证据单独标识，不能留在当前正式入口。
- 全部本次必做项和必要核验有当前证据、诊断已处理或按原要求验收，才能 PASS 并称全量完成；有已知非阻断问题为 CAUTION；必做项未验证、失败或证据缺失为 BLOCK。BLOCK 只禁止受影响的完成声明或动作，不要求停止无关的已授权工作。
- 交付时先说准确状态，再说具体产物、实测结果和剩余缺口。分别说明内部自检、真实应用/内核验证、教师官方评测和平台提交；不能把静态渲染写成浏览器验证，也不能把替代复验写成官方评分通过。
- Skill 结构检查和单元测试只证明各自覆盖的规则或代码分支；不能据此宣称模型以后必不漏检，或任何具体实验已完成。

## 脚本用法与门槛

先以 `--diagnostics-only --notebook <原始执行.ipynb> --expected-code-cells <实际原格数>` 检查运行输出；完整驱动、导出或渲染日志分别用 `--log` / `--stderr-log` 追加。未知的 stderr 必须审阅；日志输入须为完整文件，缺失或截断状态不得伪称完整。

完成判定另传 `--checklist <本次验收JSON>`，其中 `requirements_basis` 指向本次要求证据，`checks` 逐项包含 `id`、`required`、`status` 和 `evidence`。每条证据包含 `path` 和实际 `sha256`；ZIP 内证据另加 `member`，哈希按该成员的原始字节计算。必做项须全部列入；脚本不替人判断要求是否摘全。

诊断审阅使用 `--reviews <审阅JSON>` 的 `reviews` 列表：按脚本生成的 `finding_id` 填 `decision`（`expected` 或 `nonblocking`）、`reason`、`impact`、`basis` 和有哈希的 `evidence`。预期异常须能指向原要求；仍存在的诊断不能填“resolved”获得放行，旧哈希的审阅也不能用于新版。

审阅与验收 JSON 内的相对证据路径，分别从该 JSON 所在目录解析；输入 Notebook/日志的相对路径从命令工作目录解析。不要混用路径基准造成误读旧文件。

退出码：PASS=0、CAUTION=1、BLOCK=2。`--diagnostics-only` 即使为0也只证明此次诊断检查通过，`can_claim_full_completion` 仍为 false；不传完整验收清单不得获得总体 PASS。
