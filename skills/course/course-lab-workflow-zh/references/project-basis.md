# 项目依据、覆盖范围与迁移

## 1. 依据范围

本 Skill 于 2026-09-15 根据当次可检索的课程文件、历史偏好和当前用户要求整理。它是覆盖已有主要实验类型的通用工作流，不是“所有历史实验已经逐个复跑”的证明，也不保证历史文件库已经穷尽。

为避免泄漏和环境误用，未将历史服务器地址、登录账号、个人路径、口令或旧运行状态写为默认配置。姓名、学号、班级、日期等由每次实验任务卡提供。

## 3. 历史记录中需要隔离的问题

### 3.1 实验编号混用

历史偏好文件在 RUCBase 段落附近同时出现“实验七”与 Hive。仅凭这段文字不能确认课程归属。因此通用 Skill 不绑定“RUCBase实验七=Hive”，也不直接继承“实验五/六通过”的测评结论。以当前指导书和原始测试记录确定。

### 3.2 替代环境并非自动合规

Linux 报告采用远程服务器方案，说明存在适配需求。通用规则保留按目标适配的方法，但要求明确虚拟机安装、host/guest功能或双机操作中未覆盖的要求，不能写成所有要求天然等价。

### 3.3 不继承危险的临时修复

历史报告中出现的扩大用户组权限做法不能提升为通用排错步骤。通用规则改为按最小权限检查身份、资源和授权，再选择必要修复，不默认提权或改全局配置。

### 3.4 报告中的“成功”不是一级证据

历史材料同时可能有占位说明和成功表格。需要核对原始截图/日志和对应任务，不能只拷贝表格状态。示例运行输出、旧截图和预期结果不能变为当前结果。

### 3.5 AI 说明必须真实

保留模板中的 AI Report 栏目和图题样式，但不继承固定模型名称或“仅辅助”的结论。每条记录一个具体知识点疑问与解答，配问答截图和真实验证；未确认模型版本不猜测。

## 4. 可迁移关联

| 当前知识点 | 可关联旧项目 | 共同原理 | 不能照搬 |
|---|---|---|---|
| 用户/目录/网络 | Linux → 大数据组件 | 明确执行位置和资源边界 | 服务器地址、账号、固定端口 |
| 逐层输入输出 | RUCBase → 数据管线 | 每层具有输入、处理与输出契约 | 执行器的调用方式与消息推送语义 |
| 数据模型与持久化 | NoSQL/Java → OpenDigger缓存 | 先写入，再独立读回确认 | 不同数据库的事务与查询语法 |
| 图表正确性 | 日志可视化 → OpenDigger | 原始数据、聚合、图表相互可核对 | 健康度权重与日志字段 |
| 页面结构与请求链 | Web → 全栈可视化 | 页面、数据与交互各自验证 | 纯HTML任务无需全栈架构 |

每次关联只用于帮助理解或复用方法，不将“旧项目具备这个能力”写成“当前项目已完成”。科研、竞赛或其他项目只有在确有帮助且用户允许时作为旁例，不写入课程实验清单。
