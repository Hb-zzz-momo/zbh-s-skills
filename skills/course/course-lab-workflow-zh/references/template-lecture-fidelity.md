# 本课模板与实验讲义完整保留规则

适用于所有课程中有明确实验步骤、课程模板或实验讲义的实验执行、报告生成与修订。保留本课原模板、全部原内容、代码和步骤及其顺序，默认不额外补充实验代码；只有用户明确允许扩展时才做延伸。“只允许增加”的旧要求不再构成默认扩展授权。正式正文清理制作/带练提示、无输出占位句和对照提示，并展示Jupyter原始执行输出；按[逐格执行与原始输出规则](notebook-output-fidelity.md)处理该例外，原件及旧输出留在备份，不借此删除实验要求、理论或原代码。其他模板修改仍仅在用户明确授权范围内处理。

## 1. 模板来源与结构

- 有本课模板就必须使用本课、当前实验的模板副本。禁止套其他课程模板、历史通用模板、满意成品的章节结构或模型自行设计的结构；不得因其他模板更美观而替换。模板缺失时先查已有材料，不用其他课模板冒充本课模板。
- 保留原题目、身份字段顺序、栏目、编号、段落、公式、表格、图及题注、代码和单元格的原顺序。模板为 Markdown、Notebook、HTML 时也按原件继承，不能只继承封面而重写正文结构。
- 实验内容不得删减、概括替代、合并或调换。重复示例代码、数据预览、理论解释和中间步骤仍需保留；仅清理制作/带练提示，旧示例输出默认由当前实测输出替换并在原件备份保留。“核心要求已覆盖”不等于全量完成。
- 在对应原步骤后写足必要说明、真实输出和结果分析；详细解释不授权增加代码或另做实验。题目要求自行编写的作业代码照常完成，不属于扩展。默认不新增诊断、显示表达式、代码单元、模型、评价或绘图代码；原要求已有这些内容时照常全部执行。
- 只有用户明确说“可以适当扩展”或同等授权时，才在完成原步骤后单独做范围内的延伸，记录授权与扩展项，并真实执行、展示结果；不改写、插入原代码内部、合并或替换原步骤。“全量完成”“越详细越好”“尽量有输出”均不等于扩展授权。全文源码附件不能替代正文原代码。

## 2. 讲义步骤与真实执行

- 全文读取本次讲义，按原编号、原步骤、原单元格顺序执行并成稿，包括讲解示例、演示代码、课堂练习和中间操作；不能只运行学生填空或提炼后的自编脚本。准备依赖可在正式步骤开始前完成，不擅自重排原实验步骤。
- 每一步保留原内容、完整代码、实际输入、操作、执行结果、原步骤要求的图片，以及足够详细的说明和分析。原有理论公式和适用条件不能因不影响程序运行而省略。
- 执行仍须遵守当前权限与授权范围。前置条件缺失、代码报错、API过时或原讲义存在错误时，保留原位置与原文/原代码，记录真实失败与原因，在已授权范围内于原处作最小修复并保留修复后真实结果；机器学习明确要求原代码不变而必须修复教师非填空代码时，先真实复现并说明冲突，取得修复授权后再改原格；不能静默跳过、删格、改名或换算法来假装原代码已执行。条件步骤未具备条件时列明阻塞，不能伪造执行。
- 细节应充分而有据：优先完整内容、完整代码和真实图片，不为篇幅短或排版美观删内容，也不以无意义重复、虚构日志或合成截图充数。

## 3. 机器学习与 Notebook

- 逐格保留所有 Markdown 单元、代码单元及原顺序，包括导入、读取、`.head()`、`.describe()`、形状、初始化参数、代价计算、训练、预测、评价和绘图；不得合并、拆分、移动或删除原单元。原有函数名、变量名、算法、参数和原绘图流程保留；填空只在原空缺处完成。
- 在可复现环境中从干净的Jupyter内核按原顺序执行全部代码单元，不能只运行末尾练习，不能只运行替代脚本后填入数字。记录每格执行状态及实际输出；无显示输出的导入、赋值或函数定义也必须实际执行并在台账中记录，正文不加“已执行”“无显示输出”等占位句。
- 输出紧跟对应单元，采用Jupyter原生显示/导出：表格、标量、数组、模型信息、日志、警告、真实错误及全部生成图。不手写、改写或重新拼装原始输出；不能沿用模板旧的 `Out[...]` 或旧图充当新结果。旧输出在原件与备份保留，正文默认替换为当前原始输出；课程明确要求示例对比时另按要求展示。
- 所有有明确步骤的 Notebook 实验默认不增加代码或补充单元；机器学习除讲义作业要求外完全按教师代码执行，不额外添加 `.head()`、`.describe()`、`shape`、`print()`、随机种子、标准化、模型、评价指标、交叉验证或图表，不更改教师参数。已有显示表达式原样执行，无输出的原格只在台账记录执行，不加正文占位。用户明确允许的扩展按第1节单独处理；该默认边界优先于旧的“尽量追加中间输出”及通用允许补充代码的建议。
- 图前保留实际产生该图的完整代码，图后保留原图题及分析；每个原绘图单元单独执行、展示其全部输出，不用一张合并图顶替原图。导出 HTML 时内嵌真实输出及图片，确保单文件可查看，不用只引用外部源文件或模块调用替代原单元代码。

## 4. 全量验收

建立逐项对照表：`原步骤/单元序号 → 原内容及完整代码 → 执行状态 → 实际输出/图片 → 报告对应位置 → 新增内容/修复说明`。无编号的单元按原出现顺序编号用于台账，不改教师正文编号。

对照原件检查原单元数量、类型与相对顺序、原代码、理论、表格、输出和每个绘图结果；新增实验代码或单元必须有明确扩展授权，单独核对其范围、位置与真实结果，不能凭“只能追加”的旧规则放行。允许清理的提示逐项记在证据中。按原始输出规则比对执行快照、每格输入/输出哈希与原生导出，空输出不加正文占位。机器学习还从最终 HTML 恢复全部输入代码，按原格及顺序在新 Jupyter 内核全量重执行，并核对源码和输出有效性。再核对结果可追溯、图片无遗漏、导出与渲染可读。局部修订只验收并修改已授权范围，报告全量状态仍按实际覆盖情况说明。

只要存在原步骤/单元/代码/理论/图表/必要结果被省略、合并、重排或尚未执行，就不能声称“与原题完全一致”“全部包含”“可直接提交”。逐项列明缺口，不用算法结果相近、图数够多或结构检查通过替代全量验收。
