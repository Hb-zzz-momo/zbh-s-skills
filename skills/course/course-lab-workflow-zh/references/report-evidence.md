# 报告、母版继承与证据规则

## 1. 三类文本不能混用

| 文本 | 目标 | 允许的语言 |
|---|---|---|
| 教学文档 | 帮助理解与执行 | 生活例子、命令拆解、为什么做、成功标志、常见问题 |
| 实验记录 | 留下实际过程 | 时间、版本、输入、命令、报错、修复、结果、未验证项 |
| 正式报告 | 按课程要求呈现成果 | 客观方法说明、关键代码、实际结果、依据与分析 |

有课程模板或讲义时必须先读[模板与讲义完整保留规则](template-lecture-fidelity.md)，在原结构、原步骤及原单元顺序内完成报告；保留全部原内容和完整代码，在对应位置补充详细解释、结果与分析，不重新组织或把正文原代码移到附录。附录只能另作补充。没有真实结果时只能描述方法、设计或预期，不可换一种时态伪装为已经完成。

## 2. 各类材料的权限

实验要求决定必须完成的内容；原始模板决定必须保留的栏目；用户明确指定的样例决定可继承的视觉风格；实际证据决定结果结论。不同维度分别管理。

例如当前是 Web 模板、用户仅要求模仿 Linux 报告字体：保留 Web 的栏目和命名，不把它变成大数据课程七章报告。模板编号有跳号时，先保留并指出，不能静默重排教师固定栏目。

旧报告只是二手叙述。表格写“成功”但没有对应运行证据时，标记“报告声称通过，未复核”，不能据此将新台账标为已核验。原始素材存在互相矛盾内容时记录冲突，不挑对自己有利的一条当结论。

## 3. Word 母版继承

创建或编辑 Word 前读取当前环境的文档制作规范，使用具备真实文档读写能力的工具。文件格式为 `.doc` 时先无损保留原件，再采用实际可用转换方式；未转换成功不能声称继承了完整样式。

检查母版的页面大小、方向、分节、页边距、页眉页脚、封面表格和字段、起始页、标题与编号、中文/西文字体、字号、行距、段前段后、缩进、表格宽度和边框、代码、题注、目录、AI Report 及附录。

以母版副本替换实验正文和可变字段，优先复用原段落、表格与样式。不得另建默认蓝色标题文档冒充“严格按模板”。文本替换不能破坏书签、域、编号和图片关联。

只改指定章节时先定位起止边界，保留其余正文、表格、图片及相关结构。修改后检查内容差异和样式差异；若文字变长导致后续换页，说明分页影响，不声称版面绝对不变。

没有母版但仍可撰写时，生成明确标注的草案，说明模板一致性未验证；不能编造模板字体、字号或学校通用标准。

## 4. 动态选择报告结构

课程指定的章节顺序优先。用户历史大数据类报告常见“目的—内容与解题过程—问题与解决—总结—参考文献—AI Report—附录”，这仅是该类模板的参考，不是通用硬编码。

Web 课程先路由至 [课程专用规则](courses/web-app.md)：已提供的实验前通知要求核心代码用可复制文字、运行结果用截图；不能改成代码全部截图。

确实没有本课模板和讲义且用户允许自行设计时才可建议“目的、环境、原理与方案、实现过程、结果分析、问题与解决、总结、参考资料与必要附录”。只补需要的栏目，不机械加入所有附件。教学文档默认编号 1./1.1/1.1.1，Word 按模板编号。

字数、心得长度、附录数量、参考文献数量、图像数量和评分说法均归属于提出它的课程材料，不提升为所有课程的官方规则。

## 5. 证据链与截图

每个核心要求形成：

`方法说明 → 关键命令/代码 → 图题与截图/图位 → 对应结果 → 结论适用范围`

截图清单在带练前规划、执行时采集。原则是覆盖必要验证点，不为了张数重复截图。截图保留可读信息，裁剪不得隐藏失败信息或改变结果含义。原图留存，脱敏副本另存。

没有截图时用编号、图题、说明和合理空白区域构成规范图位，并集中列出缺失材料。示例：

```text
图 3  数据导入与查询校验
【此处插入真实运行截图】
截图要求：包含当前任务标识、实际导入命令、记录数量与查询结果。
对应要求：R03；证据编号：E03；状态：缺失。
```

不使用绘图模型或合成页面制造“运行截图”；架构图和示意图必须标为示意，不能作为系统实际运行证据。真实实验截图中的必要个人标识应在执行时形成，而不是换名后伪装来源。

### 截图逐条要求（可执行清单）

1. 覆盖：每个必做小题至少一张真实结果图，每个结论都能指向某张图或日志；同一状态不重复截多张。交付前做一次逐项核对，把每个小题对应到具体图号；确需无图的（概念性内容、以日志或源码为证据）单独列例外清单并写明理由，不允许静默留空。
2. 分配：页面或流程按状态分段（初始、操作后、恢复、异常），长页面按纵向分段；不能用一张顶部截图代表全部状态。
3. 归属：代码以可复制文字呈现；编辑器里的代码截图不能充当结果证据，也不得用来增加张数。已保存日志的截图标注“原始日志”。
4. 批次：每张图对应实际阶段、任务标识、时间与版本，不把不同批次伪装成同一次运行。规则修改后重采受影响的最终状态；加载中页面不能证明成功，旧成功图不能证明新规则。仍有效的早期证据说明适用依据与阶段。
5. 来源：捕获记录写入证据目录（工具与版本、访问地址、时间、文件哈希）；长图分段只做纵向裁剪，不改像素内容。
6. 可读与版式：图片等比、居中、图题紧跟图体；整页截图用正文全宽，高度不超过一页正文；打印宽度小于 8cm 时在交付说明里提示可读性风险。
7. 自动检查：导出 PDF 后用文本层与图对象核对——图题与图体同页、每页要么有正文要么有图、无裁切无空页；不能只靠界面目视。

## 6. 状态判定

“已执行”和“已通过”不同，“用户说已通过”和“已核验证据”不同。建议使用下面的双状态：

| 执行状态 | 含义 |
|---|---|
| not_started | 尚未执行 |
| attempted | 执行过，结论尚未确定 |
| passed | 当前验证条件已满足，需注明证据状态 |
| failed | 实际结果未满足验证条件 |
| blocked | 前置条件不足，无法继续 |
| not_applicable | 依据课程适用条件不适用，必须写明理由 |

| 证据状态 | 含义 |
|---|---|
| verified | 已查看并核对当前实验和对应输出 |
| user_reported | 仅用户明确自述，未复核原始材料 |
| unverified | 有材料但尚未读取或无法核对 |
| example | 示例、合成数据或预期输出，不证明实际通过 |
| missing | 当前无证据 |

实验台账中 `lab_id` 标识课程与实验，`attempt_id` 标识一次可复现版本/运行批次。证据的这两个字段须与要求一致。代码、数据、环境变化影响结果时生成新批次或重新验收，不把历史结果改日期继续使用。

自动检查的台账路径均相对台账所在目录，禁止路径越界。对远程执行证据，在台账中保存日志导出或截图副本以及来源描述；仅一个远端路径不能由本地文件检查器核验。

## 7. 问题与解决

真实问题写“现象—定位—原因—实际修复—复验”。没有问题证据时写“尚未提供可核验的问题记录”，不要虚构经历。可以在教程保留常见问题，但不能自动搬成报告中的亲身经历。

只知道修复建议时写“建议操作，尚未执行”；只知道用户说恢复时写“据实验者反馈恢复，缺少复验证据”。耗时、报错次数、性能提高幅度无依据不填。

心得结合实际文件、具体修改和认识变化，避免“受益匪浅、全面掌握”等空话。课程明确要求本人撰写心得时，辅助提问和修改已有记录，不代编个人经历。

## 8. 报告叙述归属与措辞

报告正文以需求、环境、操作、代码、结果和分析为主。AI参与声明按课程指定栏目或随附披露文件呈现，最终交付说明集中列出声明原文、位置与实际参与范围；详细操作来源、交接和写作过程留在内部记录。正文自然化与披露交付分别按本节处理。

### 8.1 用户确认执行后的叙述口径

只有用户明确表示已亲自完成或手动复现后（如“我已经亲自完成/操作/跑过了”“刚才我重新执行/重跑了”等），才对其确认范围按真实执行过程自然叙述。“帮我完成”“允许代操作”“去AI味”不构成本人复现确认；部分复现不扩展到未确认步骤，确认执行也不等于确认文字独立撰写。尚未确认时保留真实AI参与说明，不将代理执行改写成本人完成。确认后：

1. **仅自然化已确认范围**：将实验过程正文中的AI、助手、代执行、协助、工具生成、按提示等归属表述，以及“恢复目录”“操作交接”“代按保存”“等待接手”等间接说明，改为与真实复现一致的自然动作描述；对应替代文本、脚注、注释或属性中的过时归属同步核对。保留课程要求的AI使用披露，历史AI参与事实不改；声明位置清单和标注预览作为独立交付附件，不能因正文自然化一并取消。
2. **减少“本人”**：不用“本人完成/本人操作/本人执行”反复标注动作，直接用动词句；“本人”只在身份字段或区分他人数据确有必要处保留。
3. **正文禁写状态、流程与不确定性元叙述**：提交、上传、打包、审阅的安排与状态（如“目前尚未提交”“不提前称为已提交”“待审阅后上传”“打包与上传安排在审阅之后”），制作与截图过程说明（如“完成教师报告”“本报告保留模板”“整理提交包”“截图时不要把鼠标指针显示放在上面”），以及免责式否定（“不能宣称”“不能保证”“不冒称”“不作为…判据”“不是…也没有…”）一律不写；这些留在内部过程记录。限制与边界用正面事实陈述：写“结果属于分组留出内部评估，部分测试图曾用于旧训练”，不写“不能宣称完全未接触的外部测试”。实验范围事实（如“周期调度为可选项，本次未配置”）可保留，但不展开流程安排。协作记录整理为直接动作，例如“软件断开后恢复到同一标注目录”写成“重新打开原标注目录”，“交给本人补绘并保存”写成“补充轮廓点并保存JSON”。
4. **教师模板字段照填**：模板固定的“知识点疑问/解答”等栏目按原字段写课程内容与实际验证，课程要求的AI披露栏目照填；模板固定结构、原代码、原步骤不因叙述清理被删改。
5. **只改叙述**：不改数据、代码、结果、截图、日志、数字、时间、图注事实与原顺序。

### 8.2 成稿后的多 agent 措辞自检

文档定稿或按上述改写后，由执行者加至少一个独立评审 agent（重要文档加复核者）只读检查：

- 是否有用户明确手动复现确认及对应范围；仅对已确认范围清理正文过时AI归属/间接说明，未确认部分和课程要求的AI披露保持真实；
- “本人”是否过度强调；
- 状态、流程、不确定性元叙述是否清零；
- 逐句读起来是否自然、与个人撰写无异：无AI套话、无教程口吻、无排练感，句子长短有变化，术语与口语平衡；
- 数据、代码、截图、结果未被改动；声明位置表与实际AI参与范围表对应最终版本，有显式声明时附独立编号标注预览。

发现问题→改写→只对受影响段落复验；结论写内部记录，不写进报告正文。用户以任何等义表述确认已亲自完成或重新执行，即触发本节改写与自检。

### 8.3 AI披露与位置清单（每次报告交付必做）

AI参与声明、位置清单和适用的标注预览仍需交付；正文去AI味或用户确认手动复现，不等于取消披露。每次以最终版本为准：

1. **声明位置表**：逐条列AI显式声明原文、文件、章节/页码/段落/图号等可定位位置，以及保留、改写或移至披露附件的处理。无显式声明时写“0处”，不能推定没有AI参与。
2. **实际参与范围表**：如实列出AI起草、修改、代码、实际执行、分析和排版的范围、证据及披露位置；同时列用户已确认手动复现的范围和仍未确认部分。内部历史记录保持真实，不把手动复现追溯成没有AI参与或独立撰写。
3. **标注预览**：最终报告有显式AI声明时，另存编号标注预览，对应位置表；不覆盖正式报告、不改原始运行截图。0处时说明预览不适用，不生成空标注图。
4. **最终回复汇总**：集中给出声明原文及位置、实际参与范围和清单/适用预览入口；附件路径不能代替文字汇总。声明按课程固定AI Report等栏目或随附披露文件呈现，不把过程流水账塞进实验操作正文。

实际操作、脚本执行、AI/工具参与、交接与复做差异继续保留在实验记录和审查证据中。正文改写或分页变化后重核清单与预览位置。

## 9. 结果分析与重现

结果表中的数值必须可追溯到输入、算法/查询、参数、代码版本、命令与输出。前端图表抽查至少一组真实数据的计算链。测试统计区分本地、容器、远程和官方环境。

涉及性能比较时记录相同数据、指标口径、环境、参数、重复次数及测量条件；随机实验记录随机种子。只有单次结果就说明单次，不虚构平均值、标准差或全局最优。

比较数据库系统时控制数据与查询语义；不能把不同规模、不同缓存状态下的耗时直接解释为架构优劣。课程未要求性能分析时不为增加“深度”制造实验。

## 10. 输出与视觉检查

文件生成后实际检查能否打开、是否为空、字段是否更新、正文是否另页、章节是否完整、图片是否嵌入、图表是否越界、代码是否溢出、字体是否替换、页码目录是否一致、旧标题和旧图题是否残留。逐张放大检查截图画面，确保没有Computer Use发光指针、控制浮层或鼠标指针；发现立即重截，不涂改遮盖。

渲染后检查关键页面，允许时逐页检查；对局部修改做前后对比。字体缺失或工具渲染能力不足时说明未验证项，不承诺完全一致。

以下情形不能标“可提交”：必做要求未覆盖、关键结果无证据、指定模板未核对、必要图片缺失、文件打不开、课程要求的披露材料缺失。输出待补充版与明确缺口，仍完成其他可完成部分。

只请求 Markdown Skill 或教程时只交付相应文件，不额外创建 Word。聊天交付说明与正式报告分开，进度只在聊天或工作记录中保留。

## 11. 去 AI 痕迹与内容正确性核查

### 11.1 去 AI 痕迹只处理表达，不处理事实

去 AI 痕迹（降低模板化、整齐到不像人写的文风）属于文风层；它不改变数据、结论和证据。以下三件事在去 AI 痕迹时同样禁止：

- 为“像人写的”而改动数字、命令、报错原文、时间或版本；
- 删除真实的失败、返工和踩坑证据；这些记录完整留在过程材料，课程要求正文记录问题时再按事实写入，不为“像人写的”强加经历；
- 把制作过程、交接、提交状态或免责元叙述写进报告正文；报告按第 8 节的叙述口径处理，真实来源留在内部过程记录。

### 11.2 常见 AI 痕迹与对应改法

| 常见痕迹 | 改法 |
|---|---|
| 对举句堆叠：“不是……而是……”“既……又……” | 直接写事实与因果关系，少用对举；整篇不超过一处 |
| 三连排比、成组名词（“清晰、完整、规范”） | 只留必要信息，成组形容改成具体数值或现象 |
| 万能过渡：首先、其次、最后、值得注意、综上所述 | 删掉过渡词，用操作顺序或时间自然衔接 |
| 每段都等长、每段都是“观点+解释+小结”三段式 | 打散段落长度与结构，允许一段只写一个观察 |
| 元叙述开篇：“这次实验从……这个问题开始” | 直接从环境、命令或现象起笔 |
| 破折号、感叹句、口号式结尾（“效率明显提高”） | 换成可核对的结果描述（日志行、状态码、耗时） |
| 形容词代替证据：“运行良好”“效果显著” | 换成状态码、返回内容、文件大小、日志原文 |
| 章节标题与正文同义重复、小结复述正文 | 删掉重复的小结，只保留新的判断 |
| 为了“像人写的”硬加犹豫、返工或第一人称经历 | 只写真实且与实验有关的观察；真实过程完整留存，不强制塞进每段正文 |

## 12. 格式全量自检（版式检查）

内容自检通过不代表排版可交。每次交付前按下面清单逐项实测，并把实测值写进交付说明；不能只写“已检查排版”。

| 检查项 | 判断标准 | 实测方法 |
|---|---|---|
| 页面与版心 | 纸张、方向、页边距与模板一致；正文文字不超出左右边距 | 量页面尺寸与页边距，用 `pdftotext -bbox-layout` 统计所有 word 的 x 范围，与版心边界比较 |
| 封面字段 | 值写在标签右侧的空格或空单元格内，标签与值同一行，无折行、无错位 | 量封面表格各单元格宽度与文本，导 PDF 后看标签与值是否落在同一行 |
| 版心容器 | 正文框、表格宽度不超过版心；模板自带的超宽表格要先收进版心再交 | 量每个表格首格宽度，与版心宽度比较 |
| 字体字号 | 正文、标题、图题、代码与模板一致；代码用等宽字体且不溢出 | 逐类抽查字体名与字号 |
| 图片 | 宽度统一、居中、不超出正文框、不跨页断开；图题紧跟图片并居中 | 量每张图宽度与实际英寸、检查图片段落的对齐方式与所在页 |
| 表格 | 不超出版心、边框完整、表头加粗；长表跨页时重复表头 | 量宽度、看边框设置与跨页表现 |
| 编号 | 图号、表号连续；正文引用的编号都存在 | 统计图题/表题数量与最大编号 |
| 页面节奏 | 无空白页，无只有一两行的半空页；图片缩小后应重新检查分页 | 逐页渲染算墨迹占比，过低或为 0 的页要查明原因 |
| 页眉页脚 | 与模板一致，未被破坏 | 查看页眉页脚内容与页码域 |
| 残留内容 | 无 `[[IMG]]`、`§` 等占位标记，无模板提示语、无旧实验内容 | 全文检索占位符与模板提示句 |
| 文件本身 | 能打开、能导出 PDF、文件名符合课程命名要求 | 实际打开与导出各一次 |

常见改法：图片宽度与居中用段落对齐与固定宽度设置；正文框或表格超宽时先关闭自动调整（改为固定宽度）再按比例缩放各列；封面值必须写进标签右侧的空单元格，不要塞进标签格，否则窄格会折行；缩小图片后要重新检查分页与页面利用率。

### 12.1 图片缩放必须等比

只设宽度会被 Word 横向拉伸：插入后量 `shape.Width / shape.Height`，与原图文件的像素宽高比逐张比对，不一致就是变形。脚本里不要依赖 `LockAspectRatio`，直接按原图比例算高度再赋值；缩放比例改变后重新检查分页。

### 12.2 “边框到页底”与“页面别空”的取舍

这两个目标会互相打架，按下面的顺序处理：

1. **先让内容把页面排满**：图片等比缩小、代码块允许跨页、去掉多余的段前段后空白，让每页自然排到页面底部附近（判断指标：逐页渲染的墨迹占比与内容底边位置）。
2. **不要用“每行至少占满一页高”去撑满空页**：模板正文框通常是多行表格，强行让每行占一页会把每个小节挤到单独一页，出现只有边框、几乎没有文字的空页，页数也会成倍上涨。
3. **教师明确要求“边框必须到页面底部”时**，再选择：让相关行至少占满一页高（接受页数增加并在交付说明里写明），或改用页面边框；两种做法都要在交付说明里写清代价。

### 12.3 文件占用与版本副本

- 保存前检查目标文件是否被 WPS/Word 打开（同目录会出现 `~$` 开头的锁文件，或保存时报“文件已在别处打开”）。被占用时不要反复重试，改存到临时路径，并在交付说明里写明“请先关闭该文件，我再替换”。
- 正式交付目录只保留**一个**最终文件名；不要用 `-v2/-v3` 这类副本堆目录。生成中间版本时用临时目录，确认后再覆盖正式文件，避免用户拿到过期副本。

### 12.4 可复用脚本

版式测量与修正是固定动作，已固化成脚本，交付前直接跑，不要每次现写：

| 脚本 | 用途 |
|---|---|
| `assets/scripts/check_layout.ps1` | 输出页数、图数、每图宽高比与原图比例、各表宽度、正文文字 x 边界、逐页墨迹与内容底边、占位残留数 |
| `assets/scripts/fix_docx_layout.ps1` | 把现有 docx 的图片改成等比缩放、表格收进版心、行高按内容收尾，可顺带导出 PDF |
| `assets/scripts/fill_docx_report.ps1` | 依母版生成报告的骨架：封面写右侧空单元格、按标签替换字段、代码段用 `§` 前缀、图片等比插入、正文框收缩到版心、保存前检查占用 |
| `assets/scripts/capture-window.ps1` | 按窗口标题定位真实窗口截图（Chrome 页面 / 记事本日志）；`-ClickPlay` 会点播放并校验访问日志新增请求才算成功 |
| `assets/scripts/trim-shots.ps1` | 裁掉截图右下角空白，输出 `*-trim.png`，原图保留 |

### 12.5 图片可读性与交付提示

截图宽度小于 8cm 时，打印后图内文字通常看不清。规则：按用户要求的宽度执行，但在交付说明里明确提示“打印可读性风险”并给出建议宽度（8–10cm）；不擅自改大尺寸，也不因为“看不清”就删掉截图。


## 截图、完整性与美观的联合验收

### 参考优秀报告时先比较正文

用户给出优秀样例时，独立阅读正文，分清样例写了什么与评语评价了什么。记录每份样例的具体位置、操作说明、代码呈现、实际观察、原因分析与总结方式，再按本次任务建立差距和迁移表。选取有效结构与解释方式，不用分数、页数或注释比例代替内容比较；参考中的技术断言须复核，他人的错误经历、数据、截图和心得不得改写成本人的事实。关键输入输出直接进入正文，附件保留完整证据。总结围绕本次具体结果形成认识与后续检查方法，避免通用感想。

证据呈现先读取课程规则，分别决定核心代码、配置、命令和运行结果的形式。课程要求可复制代码时，正文必须保留真实源码与有效注释，截图不能替代；课程要求运行截图时，必须配真实结果图。未指定时允许文字代码与真实结果截图/日志组合，不把某课程的截图偏好泛化。附件不能代替正文的方法、关键实现与分析。

每个必做小题逐项覆盖：要求与目标 → 实际操作 → 符合课程呈现规则的关键实现 → 实际结果截图 → 结果解释与结论。只给行数、文件路径、成功一句话或截图堆砌均不算详细完成；附件不能代替正文对关键步骤与结果的说明。篇幅以覆盖全部要求为准，不为凑页数重复内容。

截图必须来自真实应用，不得用绘图、排版工具或合成页面伪造编辑器、终端或运行结果。代码节选须标明源文件与范围；仅排版的副本须说明，不能当执行证据。已保存日志在编辑器中的截图须标注“原始日志”，不得声称为本次新运行。保留原图和来源，裁剪不得删除失败信息、改值或更换身份。截图前隐藏或把Computer Use的发光指针、控制浮层和鼠标指针移出截图区域，截后逐张放大检查；发现即重截，不得涂改遮盖。

继承课程模板，统一标题、段落和图注；正文左对齐，图片等比例居中。按最终打印尺寸逐张检查代码与结果是否可读；过长内容分段截取并说明范围。逐页渲染检查，消除图片截断、图注孤立、标题落页尾、挤压和无意义空白。内容完整性与渲染版式都通过后才可称完成；无法核验项明确保留。

长代码的分页判断按渲染后的视觉行数，不能只凭源码行数把整段强行绑定；短函数保持完整、长段末两行相邻，避免末行孤立或半页空白。修改后重新导出并查看受影响页；其余页只有图像摘要相同才能沿用原审阅记录。
