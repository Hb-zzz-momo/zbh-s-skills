# 课程适配器

这里只提供识别线索和需要补充的检查。是否属于用户已经完成的实验见“项目依据与迁移”；出现组件名称不代表用户已完成对应实验。执行前必须重新读取本次指导书与实际项目。

## 1. Linux、系统基础与网络

适用任务：系统环境、用户、文件与权限、文本编辑、打包、远程连接、文件传输、多机连通。

教学链：`执行身份与环境 → 个人工作区 → 文件与权限 → 远程操作 → 连通性 → 多机协作`。

重点区分 root、普通用户和具有特定 sudo 授权的用户；组名不能直接代替授权判断。无权限不意味着要扩大所有人的权限。共享服务器保留全局配置，优先个人目录和任务标识。

环境适配逐条对应教师要求：有现成服务器只能说明使用了服务器，不能替代虚拟机安装过程的证据。需要两台主机时核实两个不同主机与实际传输方向，不能用单机回环测试冒充双机互通。

验收覆盖当前身份/版本、文件内容、权限预期、归档恢复、双方文件内容和必要的连接证据。用于解释的地址、用户名、端口全部参数化，禁止复制历史服务器配置。

可关联：后续 Hadoop/Spark 所需的用户、路径、通信和进程基础；不由此宣称后续集群已经部署。

## 2. RUCBase 与数据库系统原型

适用任务：查询处理、存储、缓冲、记录、索引、事务等内核模块，或指定 RUCBase 实验。

先读取当前分支目录、构建配置、接口约定及测试；确认实验真正要求实现的模块。不得根据“实验五/六/七”直接套固定任务。

讲解时分开查询控制链与数据访问链：

```text
SQL输入 → parser → analyze → optimizer/planner → 执行计划/执行器
执行器 → 记录/索引访问 → 缓冲与存储 → 底层文件
```

上述是定位框架，实际类名与控制流以源码为准。SQL（Structured Query Language，结构化查询语言）语法也以当前项目支持范围为准，不能假定完整兼容 MySQL。

涉及火山模型时解释父执行器按需向子执行器取记录的思路，并区分初始化、取记录、推进、结束条件。接口名称和生命周期依当前实现核对，不混用不同框架约定。

需要演示连接查询且源码支持时，可使用：

```text
ProjectionExecutor
└─ NestedLoopJoinExecutor
   ├─ SeqScanExecutor(t1)
   └─ SeqScanExecutor(t2)
```

配套写明示例 SQL、每层输入输出、左右输入如何组合、过滤位置和执行器树与实际代码的对应关系。没有源码证据时只标“示意”，不声称为当前实际执行计划。

验收分层：编译、模块测试、查询样例、边界数据、关联回归、官方评测。记录数据集、查询、输出与版本；没有测分证据不写通过分数。追加“框架定位”，解释本次改动属于哪个内核层。

## 3. NoSQL、关系数据库及 Java 接口

适用任务：Redis、MongoDB、MySQL、Java API 等课程材料明确要求的数据库操作。

教学链：`服务 → 客户端连通 → 创建/写入 → 查询 → 修改/删除 → 程序接口 → 一致性检查`。

NoSQL（通常解释为 Not Only SQL，非关系型数据管理方式）下的不同系统具有不同数据模型；键值、文档和关系记录的语义先讲清，再做比较。CRUD（Create, Read, Update, Delete，增删改查）每一项都需实际验证。

核对实例地址、数据库/集合/键前缀、认证和客户端驱动版本；不在报告里保存明文密码。使用实验命名空间，删除只作用于本实验对象。

Java 接口实验需核对 JDK（Java Development Kit，Java 开发工具包）、构建文件、依赖、入口类和连接参数。命令行操作成功不能替代 Java 程序运行证据。

教学默认尽量使用 MySQL/PostgreSQL 说明通用关系数据库语法；课程指定 Hive 或 RUCBase 时使用其实际方言，不用一般偏好覆盖课程。

## 4. 大数据组件与数据管线

适用线索：Hadoop、HDFS、Hive、HBase、Kafka、Flume、Spark。只启用本课程明确出现的组件，版本和启动命令以实际部署模式及对应官方文档为准。

公共链路：`输入来源 → 采集/导入 → 传输/存储 → 计算/查询 → 结果消费/展示`。

| 分支 | 必须讲清 | 必须验证 |
|---|---|---|
| Hadoop/HDFS | 本地文件与分布式文件路径、服务角色 | 运行角色、目标文件内容和必要读写 |
| Hive | 数据文件、表结构、元数据与查询 | 元数据服务条件、建表导入、实际查询结果 |
| HBase | 行键、列族、单元格与操作语义 | 服务条件、建表、写入、扫描与目标值 |
| Kafka/Flume | 采集源、缓冲通道、输出端及消息传递 | 输入消息经过指定链路在最终消费端出现 |
| Spark | 驱动端与执行端、提交方式、输入输出 | 实際任务提交、计算结果、日志与输出位置 |

HDFS 是 Hadoop Distributed File System（Hadoop 分布式文件系统）。涉及 Flume 时可用 Source—Channel—Sink 说明组件职责，但实际绑定名称来自配置文件。Kafka 不同部署模式、Spark 不同运行模式不能混合套启动命令。

集群进程全部存在不等于任务完成。为测试数据设置可追踪任务标识，核对记录数量/值和输出。不要重复格式化已有存储、删除元数据或重置主题来“修复环境”。

用户历史偏好 Hadoop 3.x 不代表某个小版本已安装或一定兼容。指南中的版本示例不得当真实环境版本。只为当前任务查询兼容矩阵，不预装整套生态。

## 5. Python 日志分析与跨媒体数据可视化

历史项目线索：实验八、`system_logs.csv`、`timestamp/level/message/source/user`、Pandas、Streamlit、Matplotlib。文件和字段只是历史线索，先读本次数据确认。

教学链：`虚拟环境 → 数据加载 → 字段检查 → 清洗 → 筛选/统计 → 图表 → 交互验证`。

核对解释器、虚拟环境、实际启动入口、文件编码、时间格式、缺失值和列名。不能把文件路径错误笼统当缺少依赖。空筛选、无匹配、非法时间等边界按题目选择测试。

图表说明“横纵轴是什么—统计口径是什么—回答什么问题—能得出什么—不能得出什么”。例如按日志等级计数，抽查某一等级记录数与图表是否一致。

历史虚拟环境名不是必需名，历史 Python 3.8+ 也不是对今天依赖兼容性的保证。按课程与当前依赖声明选择环境，不盲升到最新。

## 6. OpenDigger/OpenRank 数据分析与可视化系统

历史项目链路：`项目配置 → 外部指标采集 → 清洗 → SQLite缓存 → 指标计算 → 后端接口 → 前端图表`。这里用于复用分析框架，不保证历史启动命令在当前仓库仍有效。

定位 Python 的课程价值：采集、清洗、数据结构、统计、缓存与接口，不能只展示 Vue 界面。涉及 Flask、SQLAlchemy、Vue、ECharts 等时对照实际代码追踪一条端到端请求。

综合健康度中历史 0.5/0.3/0.2 是该项目的配置或设计选择，不是官方通用标准。需说明归一化、稳定性定义、数据时间窗、缺失值处理和权重依据；不自动复用到其他任务。

对排行榜、趋势图、热力图等至少抽查一条数据从来源、数据库、计算到图表的对应。将真实采集数据、缓存、演示数据和算法推断结果分开，不把存在函数等同已完成数据同步。

课程报告字数与附录结构从本次要求读取，不把此课程的大作业长度要求泛化到小实验。

## 7. Web 应用开发

适用任务：HTML 基础、表格/表单、CSS/JavaScript、后续前后端应用，以当前实验指导书为准。

HTML 是 HyperText Markup Language（超文本标记语言）。基础 HTML 任务优先保留教师代码骨架与 TODO 范围；不擅自引入 Vue、构建系统或后端，使任务偏离评分点。

公共链路：`需求/页面清单 → 资源路径 → 语义结构 → 样式/交互 → 浏览器验证 → 截图与关键代码`。

正式报告中的源代码、SQL、配置、命令及实际结果，凡可由真实界面截图呈现的，必须采用清晰截图，不得整段粘贴文本代替。完整可复制源码、配置和复现命令另存随附文件。截图不能替代方法、操作步骤、实现逻辑与结果分析。页面能打开不代表表单、链接、媒体或交互全部可用；按题目逐项操作。需要打开新标签、播放资源或填写表单时验证具体行为，而非只截静态外观。

课程要求个人信息时，在页面或测试数据中合理展示真实标识；不用其他人的截图。源代码、截图和报告命名规则逐课读取。

若是完整 Web 项目，再核对浏览器请求、后端接口、认证、数据库和错误分支。不能把 HTML 页面实验自动扩展为 CRUD 全栈项目。

要求“在局域网中另一台机器访问”时，优先使用第二台真实设备（手机、另一台电脑）在同一网段验证。只有一台设备时，可用同一台机器的另一网络命名空间（例如 WSL2 的 Ubuntu）访问本机局域网 IPv4 地址，并按下述结构写明：原要求（另一台机器访问）／替代操作（另一个网络命名空间访问局域网 IPv4 地址）／已覆盖目标（服务器绑定在非回环地址、外部主机能建立连接并取回页面）／未覆盖目标（真实物理设备的无线链路与路由路径）／认可状态未核验。不得用 127.0.0.1 或 localhost 的回环访问冒充局域网访问，也不能只写“局域网访问成功”而不说明是哪一种。

静态站点实验有一个常见误判：静态文件交给服务器默认 Servlet（如 Tomcat 的 DefaultServlet）时，POST 请求也会被当作取文件处理，照样返回 200 和同一份页面，这不能证明服务端接收并处理了表单数据。GET 与 POST 的差异应当从访问日志的请求行（GET 带查询字符串、POST 只带资源路径）和请求正文观察，结论只写到静态资源这一层；没有服务端程序时不要写成“服务器已经处理了 POST 参数”。
