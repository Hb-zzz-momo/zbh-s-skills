# 端到端代做流程

用于用户要求“直接把这次实验做完”的场景。与带练的区别只在对话形态：可以不分批讲解、不中途提问，但材料核对、执行方案、逐步验证、证据采集、按模板成稿一个都不能省。默认交付两份产物：

1. **小白教学手册**：让本人看懂“做了什么、为什么这样做、结果说明什么、逻辑链怎么接”，可复现；
2. **正式实验报告**：按课程模板与语体要求撰写，只写已核验内容。

## 0. 可追溯性硬规则

- 每条材料、命令、报错、结果和结论都要能指向真实文件路径、命令输出、日志或证据编号；做不到就写“未核验/待确认”，不编造版本号、路径、报错原文、耗时和成绩。
- 材料来源写“真实路径或可定位来源”，不写“教材上说的”。查不到就标注 `【待确认：……】`。
- 手册中的生活例子必须标注为类比，不能把类比当实现细节；报告不出现“你现在”“小白理解”等带练口吻。

## 0.1 执行纪律：完成已授权工作，真实阻塞即时交接

普通操作由用户授权的执行者完成，持续推进并逐步核验。只在缺少真正的前置条件、必须由本人处理身份或授权、或独立排查仍无法满足必做要求时暂停依赖步骤并询问用户；不把这些条件统一留到最后，也不为避免提问擅自降级完成。不依赖缺口的工作继续进行。

交付前完成内容与格式全量核对、未完善项清单、正式语体检查，以及用户要求的全部人工复做差异；所有报告交付默认完成AI声明位置和实际参与核对。真实来源披露不属于应删除的“AI痕迹”。参见下方第0.3节和[报告与证据规则](report-evidence.md)。

## 0.2 产物落盘位置

正式交付物放在课程自己的文件夹里，不留在临时会话工作区：

1. 先确认该课程的材料根目录（用户指定过就直接用；没指定时按“课程名/实验名”在用户的课程资料目录下定位或新建）。
2. 提交目录、文件名与压缩层级以教师原文和截图示例为准；内部工作目录已有结构优先保留。课程未规定时才采用 `experiment/`、`evidence/`、`report/` 与说明文件，不把工作目录方案当作教师提交格式。
3. 会话工作区（含 ChatGPT 工作区）只放草稿与生成脚本；任务收尾时把最终文件回写课程文件夹，并重新打开回写后的文件确认可用（页数、插图数、字体、边框与工作区一致），不能只做复制不验证。
4. 回写完成后在交付说明里写明课程文件夹路径与文件名，让用户直接去那里取文件。

## 0.3 执行交接与最终来源核对

1. **实际软件与执行者。**用户授权代执行时，普通界面操作由代理在真实课程软件中完成；不把“人工步骤”自动解释为每次都要本人点击。本人明确要求亲手完成的动作以及课程规定本人执行的考核动作保留本人操作。逐步记录本人操作、代理界面操作、脚本执行或外部人工标签来源，不追溯改写旧执行者。
2. **即时交接条件。**只有确实无法代办的本人身份、登录、授权、验证码、许可证或外部材料等前提，才停止依赖步骤，显示具体页面、目标、操作和成功标志，等待本人完成后实时核验。已提供的信息和已有有效会话不重复索取；本人操作期间停止对该窗口输入，防止相互干扰。独立工作可以继续。
3. **排查无解时的边界。**先检查实际配置、日志和输入，采用最小可回退修复；需要外部资料时查对应版本的官方来源。仍无解时说明失败证据、已尝试方法、受影响的讲义编号以及需要本人提供的条件，再询问用户。不得擅自跳过必做项、降验收标准、换训练数据或用演示/单任务代替完整流程；未解决事项保持未完成状态。用户明确授权改变范围时记录新范围与课程要求的差异，不声称教师已认可。
4. **最终全量差异核对。**从全部原教程按编号拆子步骤反查，逐条记录原操作、实际实现、执行者、本人重新做时的差异、验证条件、证据批次、最终报告页码/图表号和补做状态。普通GUI代操作与本人执行方式相同但执行者不同，也要如实列明；程序替代GUI、公开标签替代课内描边等覆盖不等价的差异不得隐藏。
5. **本人复做带练。**按差异清单使用可用的 Computer Use 展示真实界面和指导，再由本人操作；本人反馈与代理实时观察分别登记，核验后再推进下一步。复做留新证据，不把旧代理操作或截图改成本人执行。
6. **AI位置全量披露（每次报告交付必做）。**交付两类完整清单：报告内显式AI声明以及结合上下文可确认的恢复、交接、指导、补绘保存等间接AI参与表述的位置与原文，注明类型并另列否定使用说明；以及实际AI起草、代码修改、运行、分析和排版的位置与证据。按[位置核对规则](report-evidence.md#8-ai-report-与真实参与来源)登记最终文件摘要、PDF页码、章节、段落和图表号，有显式声明或间接暗示时生成带编号红框的独立核对预览，最终回复展示位置。无声明须明确“正文显式声明0处”并继续核对实际参与和随附披露；关键词搜索不能替代逐段来源检查。
7. **报告与产物同步。**正文按实验过程自然叙述，不逐句区分“本人/代理”或照搬交接流水账；末尾集中披露实际分工与完整位置索引，必要的来源事实及操作日志仍保留。正式语体与来源真实同时满足；按教师模板保留固定栏目及强制披露，无对应栏目时按报告与证据规则第8.0节，在允许的总结末段或随附末页集中披露并给出末尾索引，不擅改母版。表格使用原生可编辑表格，执行过程使用真实终端或应用截图；用户要求红框时圈关键操作或结果，原截图单独保存，不重绘、拼造或隐藏失败。定稿删除填写指导和占位，保留固定栏目与教师明确要求保留的文字。规则变更后保留旧批次、重跑受影响流程，同步日志、截图、报告、PDF和提交包，最后分别核验执行、文档和包。

## 1. 阶段一：实验开始前——解析任务

先把材料收集齐再动手：实验题目、指导书、教师 PPT/PDF/Word、报告模板、数据集、源码、压缩包、软件与版本要求、操作系统要求、课堂补充要求、提交时间与提交格式。落成[任务卡](../assets/task-card.md)，并填写六类信息。

| 项目 | 需要确定的内容 |
|---|---|
| 实验目标 | 最终要完成什么 |
| 实验环境 | 操作系统、软件、版本 |
| 输入 | 数据、代码、配置文件 |
| 操作任务 | 安装、配置、编程、测试等 |
| 输出 | 文件、运行结果、页面、数据 |
| 验收标准 | 什么现象说明实验成功 |

不确定的项写 `【待确认：软件具体版本】` 这样的显式占位，不自行编造。同时按“课程＋实验编号”检索磁盘上的既有材料、既有运行环境（临时目录里的服务、已部署目录）和既有交付物，先判断能复用什么，再决定是否重建。

### 1.1 教程逐项覆盖

1. **先读完整材料。**列明每份材料的实际读取范围；全文读取当前教程、题目和模板，检查数据文件的结构、字段、编码及与要求有关的取值。PDF/PPT逐页查看图中标注、负例、表格、脚注及最后的提交示例；文字提取与目视互补，不能只读标题或搜索命中段。
2. **追读关联教程。**打开影响安装、授权、操作、验收和提交的链接，核对版本、依赖与材料入口。链接失效时检查同一官方来源的对应文档，记录地址、失败现象和实际找到的内容；不能把下载入口存在当作文件已取得，也不把产品全部功能纳入实验。
3. **保留教程编号。**用[任务卡](../assets/task-card.md)按原编号建立覆盖表，独立动作拆为子步骤。每行写来源页码/图中位置、原意、必做/可选/条件及依据、实际操作、验证条件、证据位置与批次、报告章节/页码、交付位置、执行和证据状态；新增要求用可追溯ID，不能替原教程静默重编号。有讲义时执行顺序必须保持原顺序；依赖准备在正式步骤前补充，不能重排原步骤。执行前读取[模板与讲义完整保留规则](template-lecture-fidelity.md)。
4. **区分适用范围。**“也可以”之类可选动作、条件报错后的修复与必做步骤分别记录；用户明确选入范围的选做项按本次必做验收。发布、周期策略、历史查看等独立步骤分别判断，不能因其中一步阻塞将其余步骤一并标未做，也不能用历史查看证明发布成功。
5. **处理冲突与图中规则。**把正反例、图中高亮限制转成判据与边界检查。原文、示例或字段名矛盾时单列各自来源、采用解释、影响和待确认项；无法解决的关键判据不以任意假设放行。验证器须从原材料重新确认判据，不能只复制实现逻辑；两个程序一致、零异常或行数一致仍可能共同漏读一个要求。
6. **读完再报缺口。**先查当前材料和关联教程中的答案，继续全部不依赖缺口的已授权工作。真正缺少许可、材料或外部操作时写确切前置条件、失败证据、受影响步骤与补做方法；保留原要求，不用替代演示冒充完成。

## 2. 阶段二：建立实验工作目录

每次实验单独建目录，材料、代码、结果、截图、问题记录、报告分开放，便于写报告时直接取证据、提交前盘点缺失。

```text
实验三_HDFS基础/
├── 01_实验要求/
├── 02_源代码/
├── 03_数据文件/
├── 04_运行结果/
├── 05_截图/
├── 06_问题记录/
└── 07_实验报告/
```

已有课程仓库时保持原结构，只新增不冲突的记录文件。

## 3. 阶段三：先生成实验执行方案

动手前把实验拆成步骤，每步统一七项，缺项就说明为什么缺。

```text
步骤 X：操作名称
1）操作内容：这一阶段要完成什么
2）操作位置：机器/终端/配置文件/IDE 路径
3）具体命令或点击路径：可复制的命令行或界面路径
4）命令或代码解释：这条命令做什么、参数含义
5）为什么这样做：这一步在整个实验中的作用
6）成功标志：出现什么现象算成功
7）常见错误：路径、权限、环境变量、版本、服务未启动、文件不存在等
```

有明确步骤时方案覆盖全部原步骤、示例及代码，并按原顺序执行，必要分析放在相应原步骤之后。除题目要求自行编写的代码外，默认不增加实验代码、诊断格或额外功能；机器学习允许的纯展示代码按[课程规则](courses/machine-learning.md)处理。只有用户明确允许其他扩展时，才在原实验完成后另列授权范围内的延伸及其验证，不改变原步骤。没有明确步骤时才围绕题目按依赖安排。

## 4. 阶段四：正式实验，边做边记

不做“全部做完再回忆”。采用 **操作一步 → 验证一步 → 截图一步 → 记录一步**，同步写实验日志，日志几乎可以直接转成报告。

```text
步骤1：检查 Java 环境
命令：java -version
结果：成功
截图：截图01

步骤2：检查服务环境
命令：xxx version
结果：第一次失败
错误：xxx: command not found
原因：PATH 未配置
修复：修改环境变量文件
截图：截图02、截图03
```

日志里的时间、版本、端口、路径按实际输出填，不事后凭印象补。

## 5. 阶段五：截图证据链

至少覆盖五类：环境（版本命令输出）、配置（配置文件/环境变量/服务参数）、核心操作（命令执行、代码运行、数据导入、服务启动）、最终结果（能证明题目要求已达成的那张）、问题与修复（错误截图＋修复后成功截图）。结果截图最重要，必须有。

命名用序号＋含义，不用“截图1.png”：

```text
01_操作系统版本.png
02_Java版本.png
03_服务启动成功.png
04_核心功能运行.png
05_实验最终结果.png
```

每张截图保留上下文：用户名、命令、输出、窗口标题、文件名，不只截一个孤立数字。Web 原图尽量保留浏览器地址上下文；若工具仅能截取页面内容，同时保存实际URL、时间与操作记录。报告可裁去无关外壳，但须保留任务标识和证据对应关系，不得伪造地址栏。原图留存，脱敏副本另存；不用绘图或合成页面制造“运行截图”。

## 6. 阶段六：排错闭环

遇到问题不删除、不掩盖，按固定链路记录：

```text
现象：执行了什么，出现了什么错误（附报错原文）
定位：用哪些检查命令缩小范围（不靠猜）
原因：已证实原因，或候选原因与待验证条件
修复：最小修改，含作用范围与回退办法
验证：重新执行原失败用例，预期与实际结果、证据位置
```

没有真实问题记录时写“本次未出现可核验的问题”，不虚构经历；只有建议时写“建议操作，尚未执行”。

### 6.1 判定规则修订后的重跑

1. 改规则、代码或配置前保存旧版本、输入/基线、日志、证据与报告快照，记录修订原因和新批次；旧记录标明适用版本，不改写历史输出。
2. 从新判据列出受影响作业、验证和下游产物，在本人的环境中重新执行必要作业。新验证检查实际写入结果与原材料边界例；不能只更新校验脚本，或把旧截图配给新数字。
3. 对保留基线做新的只读复核时，注明基线来源、等同性依据和复核时间，不声称旧运行已经执行新规则。不要为了重新统计而盲目重跑覆盖式同步，抹掉已处理的结果；必要覆盖须先保留可恢复数据并在授权范围内执行。
4. 重新采集受影响步骤的最终状态证据，记录作业标识、阶段、时间和版本；加载中页面不证明成功。未变化的证据仅在核验仍适用后保留，并注明来源阶段。
5. 同步校验数字、结果表、图注、正文、复现说明与交付包，重新打开最终文件及压缩包核对。重跑失败就保留失败/阻塞状态，不能沿用旧成功声明。

## 7. 阶段七：实验完成后整理结果

重新打开原教程逐条复核，回填阶段一的全部子步骤；报告和验证脚本不能充当原要求的替身：

| 教程编号/子步骤 | 材料页码与原意 | 类型/适用依据 | 实际操作/代码 | 验证条件 | 证据位置/批次 | 报告位置 | 交付位置 | 执行/证据状态 |
|---|---|---|---|---|---|---|---|---|
| 原步骤X.a | | 必做/可选/条件触发 | | | | | | |

同时复核输入、数据规则及图中正反例；未通过、未复核和缺失项单列。表里每项“有记录”不等于每项“已完成”，可选未执行、条件未触发与必做阻塞分别汇总。

## 8. 阶段八：按模板成稿并交付两份产物

**小白教学手册**：按模块组织，每模块包含生活例子与工程定位、执行上下文、可复制命令或完整代码、逐步解释与逻辑链路（上一模块输入 → 本模块处理 → 输出 → 下一模块用途）、成功标志、常见错误、知识点与一道自测；所有示例数据标注为示例，所有真实结果标注来源文件或证据编号。

**正式报告**：以课程模板为母版，保留固定栏目、编号与命名要求；正文写实验目的、环境、实现方法、关键命令或代码、真实结果与分析。证据呈现先读取课程规则，分别决定核心代码、配置、命令和运行结果的形式。课程要求可复制代码时，正文必须保留真实源码与有效注释，截图不能替代；课程要求运行截图时，必须配真实结果图。未指定时允许文字代码与真实结果截图/日志组合，不把某课程的截图偏好泛化。附件不能代替正文的方法、关键实现与分析。没有证据的结论不写，缺失材料集中列出并标注“待补充版”。

模板要求“写清搭建步骤”时，在原栏目中写实际前置条件、执行位置、安装/配置/导入操作和验证结果；不能用软件版本表或“见某脚本”替代。等效操作须标明与教程原操作的对应及未覆盖部分，不把教程命令写成本次执行记录。

**交付前自查**：手册能否让本人从零复现；报告每个结论能否找到证据；两份产物中的版本、端口、路径、姓名学号是否一致；模板栏目、页眉页脚、图表编号是否被破坏；文件能否打开；AI 使用是否按[报告与证据规则](report-evidence.md)第 8 节如实披露。

先按[执行输出与完成声明规则](verification-completion.md)检查全部原生输出及完整日志，逐条处理警告、异常和未解释stderr；结果来源与正确性分别验收。最终包中每个正式入口、复验文件及别名与当前版本比对，不能只凭零异常、ZIP可打开或CRC通过声明完成。

交付时按[报告与证据规则](report-evidence.md)第 8、11、12 节执行五件必做动作，缺一项不算完成：

1. **全量自检表**：逐条列出“要求 → 状态 → 产物或章节位置 → 证据 → 说明”，覆盖必做项、两份产物和模板栏目，不用一句“已完成”代替明细。
2. **未完善项清单**：把所有未提供的材料、未核验的信息、未覆盖的目标和待确认规则列出来，并给出影响与补齐办法。
3. **内容正确性与去 AI 痕迹核查**：核对数字、版本、端口、路径、图题与结论是否一致；正式报告按 11.2 的清单改写文风，但不得改动事实、删掉真实踩坑记录或隐瞒 AI 参与。
4. **格式全量自检**：按第 12 节版式清单逐项实测并给出数值（版心与文字边界、封面字段是否单行、图片宽度与居中、表格是否超出正文框、图表编号、空白页与页面利用率、页眉页脚、残留占位标记、文件能否打开与导出）。内容自检通过不等于排版可交。

5. **AI声明位置与实际参与核对**：以最终报告为准，交付全量位置表与必要的标注预览，在最终回复展示声明位置及原文；区分“正文未声明”与“实际无参与”，记录校对/复做状态，报告改字或分页后重做定位。

另按教师提交示例检查最终目录与压缩层级、报告和源码相对位置、文件名及必需依赖。需要交付的校验/复现程序须随包提供，移除凭据后仍有可用的参数与运行说明；重新解包核对文件可读及相对路径，核验身份、批注、元数据和截图来源。分别报告实验符合要求、报告事实与渲染、交付包完整性；三类检查及全部本次必做项闭环才可宣称全量完成。平台未上传与必做项阻塞单独说明。
