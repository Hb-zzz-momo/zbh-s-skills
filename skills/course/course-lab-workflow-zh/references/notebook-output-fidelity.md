# Notebook 逐格执行、原始输出与正式正文

用于所有以 Jupyter Notebook、其 HTML 或 Markdown 导出件为模板的课程实验。正式正文服从本课模板，执行事实服从真实 Jupyter 内核；本规则同时约束新报告与旧报告修订。

## 执行与保存

1. 从本实验原模板提取全部单元并编号，保留原代码、单元类型及相对顺序。填空在原空格完成；所有有明确实验步骤的课程默认不增加代码、诊断格或输出表达式。机器学习按[课程规则](courses/machine-learning.md)允许并尽可能在对应原格之后添加纯展示单元，保留原单元边界和相对顺序；除此之外，只有用户明确允许扩展时，才在完成原实验后单独增加授权范围内的扩展单元，不改变原单元。不能用一段独立 Python 脚本的结果冒充原 Notebook 各格输出。
2. 启动干净的 Jupyter 内核，从第一格向下逐格执行全部代码，直到最后一格。可使用 Jupyter 界面或 `nbclient` / `nbconvert --execute` 驱动真实内核；记录实际方式，不把自动逐格执行说成在界面逐格点击。用户明确要求界面操作时，才必须用界面执行并保留相应证据。
3. 保留已执行 `.ipynb`、每格输入、连续执行编号、内核时间戳、全部 `outputs`、stdout/stderr、报错、依赖与运行目录。执行后先保存未经后处理的原始 Notebook 快照，再导出正文。记录每格输入与输出的哈希，完整保留 MIME 数据及原始图片字节。
4. 任何代码修改，包括注释、`print()`、诊断表达式和参数修改，都重新从干净内核运行并保存新批次。只改输出之外的分析文字或排版时可保留原输出，但仍需复核正文代码与快照完全对应。保留旧批次，不倒填新结果到旧记录。

## 输出展示

- 代码有输出，就紧跟代码展示该格真实输出；没有输出，就不添加输出区、说明句或占位值。“已执行”“当前单元无显示输出”“执行成功”只能放在证据台账，不能为无输出单元加到正文。
- 输出区直接采用 Jupyter 的原生显示或 `nbconvert` 原生导出，包括流文本、模型表示、表格、数组、精度、训练日志、警告、异常和图片。不能手工录入、改写、摘要代替、重新排版成另一份计算结果，也不能先写预期结果再填回输出。
- 原生显示会按 MIME 选择相应表示；已执行 Notebook 必须完整保留全部 MIME 数据。HTML 中显示的表示与原生导出一致，不能用自己写的 HTML 表格替换 DataFrame 输出、自己绘图替换内核生成图。
- 实验分析可单独撰写，数字从真实输出计算或引用，并标明依据；分析段、图题和排版说明不得插入原始输出块或修改其内容。
- 讲义旧输出保留在不可改动的原件与备份中。默认正式报告用当前逐格实测输出替换旧输出；仅在课程明确要求对比历史示例时才在正文单列示例，不能混充当前运行。用户要求删除对照提示时同步移出旧示例展示区，原件和证据继续保留。
- 所有有明确实验步骤的课程，没有显示输出的原步骤只按原代码执行，默认不追加显示表达式、指标或诊断单元；机器学习例外允许并尽可能添加 `.head()`、`shape`、已有结果切片或 `print(已有结果)` 等纯展示代码，不增加其他计算或改变状态。原作业要求自行编写时，只完成题目所需代码。用户明确允许的扩展单元单独记录授权并真实执行，仍采用原生输出。

## 正式报告的措辞

正文写实验方法、代码、真实输出和结果分析。删除面向用户的制作/带练提示及占位注释，例如“保留仅供对照”“PS：如果想了解……”“原注释单元保留；按讲义提示补充……”“补充代码与结果”“实际执行结果”。有效的算法、参数、边界和设计原因注释继续保留，不能把去提示语扩大成删实验步骤、考核要求、理论或原代码。

上述提示来自原模板时，清理完成版的提示文字，保留原件、单元位置与删除记录；正文中不另加“已删除提示”之类解释。用户要求的这项清理优先于旧的“所有模板提示、旧示例输出都要出现在完成版”建议。其余“本课模板、全代码、全步骤、原顺序”要求继续执行。

机器学习代码不新增或保留AI制作、解释性注释；只保留教师原有有效技术注释和作业明确要求的必要注释，具体遵守[机器学习规则](courses/machine-learning.md)。有本实验专属skill时按其规定优先处理，本通用规则只补充未规定事项，本次用户明确要求仍优先。

## 验收

先按[执行输出与完成声明规则](verification-completion.md)扫描所有格的原生输出、完整 stdout/stderr 及驱动/导出日志。警告类型、原因、影响、处理及复验分别记录；不能只统计 `output_type=error`。保留原生警告不等于验收通过，不能通过过滤或删除警告来生成“干净”报告。

逐格核对 `原模板 → 实际执行源 → 原始 Notebook 快照 → 导出正文`：

1. 原代码和相对顺序一致，填空及提示清理在台账中逐项说明，正文代码与实际执行源一致；新增机器学习展示格符合课程允许范围并有来源与用途记录；其他新增扩展单元有用户明确授权，未替代原实验。
2. 所有代码格都执行，执行编号连续；输入与输出哈希与执行时记录一致，快照输出未被后处理改写。
3. 每个有输出的格，其输出块与同份快照的 Jupyter 原生导出逐项一致；每个无输出的格，正文没有输出块或占位文字；所有图片字节相同。
4. 从实际数据和预测对象独立复算指标；输出来源核对与数学正确性核对分别通过。编号连续或哈希一致本身不证明计算正确，也不能证明用户在界面亲手操作。
5. 扫描正文、补填代码注释、Markdown 和图片题注中的制作提示；再按本课模板核对步骤、要求与图片。最后检查最终版本渲染；未完成视觉复核须如实说明。
6. 机器学习须核验最终交付HTML的真实Jupyter执行链路；有教师HTML评测脚本则实际使用，未取得时从最终HTML输入区取回全部代码（含新增展示格），保留原单元边界与相对顺序及展示格位置，建立复验Notebook，在干净Jupyter内核从头执行。核对全部代码一致、连续执行、无未解决异常、真实输出及全部图片。导出源Notebook跑通或构建脚本退出成功不能替代此复验，未用教师脚本不能声称官方评测通过。随机过程保持教师原设置，合法波动不通过追加种子、挑最好结果或改输出消除。
