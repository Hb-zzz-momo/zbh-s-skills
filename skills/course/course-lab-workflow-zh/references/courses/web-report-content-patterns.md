# Web课程：从优秀正文迁移写作方法

来源：2026-09-20实际阅读用户提供的七份实验一优秀报告正文；独立于评语分析。参考学生：周煜博、黄贵崇、何慧茹、杜钰漩、程思瑾、杨靖婷、邹琪航。具体样例、定位与本次迁移记录保存在课程目录“实验/实验一/优秀报告正文对照与迁移结论.md”。这些是写作案例，不是教师新增硬性要求。

## 所有Web实验共有的任务组织

在教师“结果与分析”固定栏目内按小任务组织：任务目标/入口 → 实际操作 → 带有效注释的核心代码 → 真实运行观察 → 原因与结论。操作、代码、截图、分析应就近对应；不要将所有步骤集中开头、所有分析集中末尾，让读者跨页重组同一任务。长任务可分小节，保留局部结构。

黄贵崇的任务内“步骤—结果—效果说明—分析”、程思瑾的“代码—结果—分析”适合结构参考；杜钰漩分别验证列表、跳转、播放，杨靖婷展示具体控件状态，适合检查粒度参考。不能把这些同学的故障和心得当作本人的经历。

说明必须落到本次对象：具体路径或入口、参数、状态、字段、行数、错误信息。把关键输入与输出放在正文，附件只保存完整日志。表格用于比较真正并列的状态；不要用表格重新罗列所有文字。总结使用本次两三个具体结果，解释认识、检查方法及仍未覆盖的扩展，不补编个人学习行为。

## 按实验类型路由

- **HTML/CSS**：区分结构、计算样式、资源加载和交互；控件列出实际输入、提交键值和重置值；媒体区分封面、就绪与播放；静态表单不可声称完成后台筛选或保存。有效注释说明选择器范围、布局关系、name/value、默认值和素材路径。
- **JavaScript**：用操作序列比较状态与DOM，例如0→1→0同时检查按钮disabled；刷新比较稳定字段与变化字段，说明计时的读取时机；鼠标进入和离开分别验证。避免只有最终截图，没有触发过程。
- **Maven/Spring**：分别记录工具配置、依赖解析、构建、启动、HTTP与页面结果。IDE集成须有IDE证据。相同输入比较GET/表单POST/JSON的参数位置与实际绑定；状态行、响应头、正文分开说明。三层按文件/接口/页面对照同一批数据。
- **SQL/CRUD**：逐题SQL与结果相邻；解释空集、NULL、聚合分母、分组过滤、排序分页。CRUD以相同契约验证不同实现，列出真实主键、影响行数、修改后回读、删除后不存在与反向用例；区分测试方法数与操作数。构建依赖失败不能写成SQL失败。

## 不应迁移的内容

不模仿页数、重复样式、宽大空白和截图数量；不因A+标签照抄不严谨的HTTP安全/长度概括；不复制他人的身份、IP、数据和个人故障经历。正文结构改善与注释覆盖是不同检查项，都不能替代真实功能验证。只给可验证的验收结论，不虚构精确评分。

## 实测基线（2026-09-21）

参照对象：七份【A+】实验一报告正文，正文文字量6,705—35,605字，图片8—30张，中位数为11,041字、21张。本人实验2—5最终正文文字量依次为11,384、9,105、16,052、19,679，图片为3、5、9、26张。

篇幅不用页数或截图数量判断，而用覆盖判断：每个必做小题是否有操作说明、可复制的关键代码、真实结果与结果解释；每个结论是否至少有一张真实截图；同一状态是否被重复占版面。报告明显短于同课程同类实验时，先检查是否缺“操作描述—观察值—机制解释—验证方法”四段，再决定补内容。不要用重复截图或通用套话凑长度，也不要把不同批次的旧截图混进当前结论：数值或浏览器不一致时，要么标明批次，要么不用。

## 版式硬约束：课程模板内的嵌套表格会断

“实验结果与分析”位于模板单元格内，嵌套在该层级的对照表会被Word跨页拆分，而且 cantSplit、keepNext、pageBreakBefore 在这一层级都不生效，续页也不会重复表头。处理顺序：先把对照表控制在三行以内并尽量排在页面上部；实际导出PDF后仍出现断表，就改成分行列出（每行一条“对象：事实—说明”），不要交付没有表头的续页。检查方法是导出PDF后用文本层确认表题所在页包含全部单元格文字，不能只靠Word界面目视。

## 长页面与多步骤实验的截图分配

一个页面只交一张顶部截图不足以支撑“段落缩进”“图片加载”“视频状态”等分别写在要求里的小项。做法是按处理后的状态分段：标题与来源一段、正文与配图各段、媒体播放状态一段、表单与表格各一段；同一批捕获按1280像素视口整页截图后只做纵向裁切，不修改像素内容。捕获要记录浏览器版本、访问地址、时间与文件哈希，写进证据目录。不同批次（例如浏览器版本、耗时数值）变化时，要么在正文说明批次，要么不放进当前结论。
