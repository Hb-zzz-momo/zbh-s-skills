# Web 应用开发课程规则

适用来源：用户提供《实验前先阅读》实验注意事项、当前报告模板、实验指导书、本人实验1的B级评阅记录及7份A+评阅记录（2026-09-20核对）。这些规则不是所有课程的通则；新通知到来须重新核对。

## 正文与证据

用户要求参考优秀报告、认为正文简短或分析不足时，先读[优秀正文迁移与分实验规则](web-report-content-patterns.md)。参考其任务组织与观察方法，独立核对事实；不能只从教师评语、篇幅或注释比例反推报告内容。

- 文件名按通知为“学号_姓名_实验x”；不从旧下载样例的加号推导改名。
- 保留目的、环境、步骤、核心代码、运行结果、心得六个逻辑要素。在原模板栏目内按任务安排操作、代码、结果、分析，使同一任务就近闭合；不要重排教师固定栏目，也不要把全部步骤和全部讨论分别堆在两端。
- 核心HTML/CSS/JS/Java/SQL/配置以可复制文字放正文，取自交付源文件；保留模块、边界、设计理由等有效注释。注明文件与节选范围，关键调用链必须完整。程序输出不能伪装成源码注释。
- 运行效果配真实截图与具体判据。代码截图仅作补充。附源工程供复现，但不能让正文仅有截图和路径。
- 截图的覆盖、分段、批次、来源与可读性逐条要求见 [证据链与截图](../report-evidence.md) 的“截图逐条要求”；本课程的长页面分段做法见 [优秀正文迁移与分实验规则](web-report-content-patterns.md)。
- 心得超过80字，解释具体知识、验证、局限与改进，不编造个人操作时长、错误、学习感受。通知提到注释比例奖励，但不据此堆注释；代码质量还应检查命名、职责、格式、边界与资源管理。

### 注释必须在正文中核验
当前通知明确注释比例超过5%开始加分，20%左右拿满此档。实施时保留原文依据，统计最终Word正文代码的非空行和含注释行，说明采用的口径并声明不是教师评分器。语言注释采用Java/JS的//或/* */、HTML/XML的<!-- -->、SQL的--、配置文件的#。不能把代码外解释段落算作代码注释。
逐模块查缺口：CSS选择器及关键属性、JS状态与事件、HTTP绑定与响应、三层职责与错误传播、JDBC参数与资源、Mapper映射、CRUD反向断言与清理、24条SQL的条件含义。所有核心测试也须有有效注释。短SQL一行一句可能自然高于20%，不要拿它的高比例掩盖其他模块。对重复HTML记录不逐行复述标签来凑数；相同口径的前后对照用于发现问题，不作为自动满分证明。复制源码入Word后再校核，防止截取和格式化吞掉注释。

## 模板

从当前教师空白模板复制填写；保留页边距、标题颜色、自动编号、表格网格/列宽、红色提示、教师评语栏。只清空占位与旧答案，不用旧已填样例覆盖新要求。自动编号需要结合numPr和渲染检查，不能按纯文字误判漏号。
Word/PDF逐页检查：代码可读且可复制、截图等比例、图注不分离、无裁切与无意义空页。页数不设奖励；不能为了压页数损失正文。

## 评分反馈的使用

已见评阅维度：功能30、代码质量30、实验深度10、结果15、结构10、心得5。本人实验1为25/22.5/7.3/15/10/4.2，共84；7份A+为95—98.9。由此仅能推断优先补功能、代码质量、深度，不能还原教师/程序的精确算法，也不能保证后续实验沿用同一权重。
内部复核逐维度列证据、缺口和扣分风险，正式分数待教师评阅。没有原评分算法及标定依据时，不再凭观感给95.5等精确总分，也不把“自评达到95”当作A+通过条件。未完成必做操作、只有旧截图、源码未回归、注释未核对到正文、版式未渲染任何一项都阻止宣布完成。完成有证据支持的修订后停止无依据刷分。

## 执行顺序

通知/指导书/模板版本核对 → 逐小题覆盖表 → 源码和真实操作补缺 → 正常与边界测试 → 原始证据留存 → 带注释源码入正文 → 按固定栏目分析 → 逐小题截图覆盖核对（有图或列入例外清单） → 渲染检查 → 评分风险复核 → 更新课程目录交付包。
