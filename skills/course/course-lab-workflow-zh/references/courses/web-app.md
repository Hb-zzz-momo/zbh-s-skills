### 心得协作方式：AI先起草，本人再修改（2026-10-13最新授权）

用户明确允许按教师要求先生成一版完整心得，再结合本人的想法修改。这替代此前“没有本人文字只能给提纲、不能起草心得”的执行限制，仅改变心得协作方式，不删除教师原文及真实性、具体细节、字数和原创要求。

## 正文与证据

用户要求参考优秀报告、认为正文简短或分析不足时，先读[优秀正文迁移与分实验规则](web-report-content-patterns.md)。参考其任务组织与观察方法，独立核对事实；不能只从教师评语、篇幅或注释比例反推报告内容。

- 文件名按通知为“学号_姓名_实验x”；不从旧下载样例的加号推导改名。
- 保留目的、环境、步骤、核心代码、运行结果、心得六个逻辑要素。在原模板栏目内按任务安排操作、代码、结果、分析，使同一任务就近闭合；不要重排教师固定栏目，也不要把全部步骤和全部讨论分别堆在两端。
- 核心HTML/CSS/JS/Java/SQL/配置以可复制文字放正文，取自交付源文件；保留模块、边界、设计理由等有效注释。注明文件与节选范围，关键调用链必须完整。程序输出不能伪装成源码注释。
- 运行效果配真实截图与具体判据。代码截图仅作补充。附源工程供复现，但不能让正文仅有截图和路径。
- 截图的覆盖、分段、批次、来源与可读性逐条要求见 [证据链与截图](../report-evidence.md) 的“截图逐条要求”；本课程的长页面分段做法见 [优秀正文迁移与分实验规则](web-report-content-patterns.md)。
- 心得按最新授权及W-N07—13、W-N16—17先生成至少80字、具有真实细节的完整草稿，再由本人结合想法修改；起草与修改状态记内部记录，修改后重新核验事实、字数与来源。尚待本人修改不阻断其他已授权实验交付，不编造个人时长、错误、学习感受。注释比例奖励与命名、职责、格式、边界和资源管理分别检查。

### 注释必须在正文中核验
已核对的《实验前先阅读》规定注释比例超过5%开始加分，20%左右拿满此档；本学期重新核对原文，有更新以当前通知为准，不能把此阈值当作所有课程的通用要求。这里是代码“注释率”，不等同于Word“批注率”；如教师另有批注要求，另列条款验收。未知计分算法不得推算精确总分。

正文定稿后，按“交付源码”和“最终Word正文”分别统计，并逐语言/模块列出：文件/正文代码块位置、非空代码行数N、含语法注释的行数C、C/N比例、教师阈值及来源、有效性缺口。默认诊断口径为非空源码行作分母，含行内注释或块注释的行每行最多计一次；空行、代码外分析、程序输出、截图、模板提示和Word批注不计入。教师指定其他口径时同时保留教师口径与诊断口径，明确差异，不能悄悄换分母。

语言注释采用Java/JS/CSS的//或/* */（CSS仅/* */）、HTML/XML的<!-- -->、SQL的--、配置及PowerShell的#。必须识别字符串、URL和注释边界，不能把字符串中的//算成注释；无代码块的报告不能据零分母推定合格。统计总比例还必须展示逐模块值，复制源码入Word后重算并核对注释与后续语句是否丢失、错位或被裁切。
逐模块查缺口：CSS选择器及关键属性、JS状态与事件、HTTP绑定与响应、三层职责与错误传播、JDBC参数与资源、Mapper映射、CRUD反向断言与清理、24条SQL的条件含义。所有核心测试也须有有效注释。短SQL一行一句可能自然高于20%，不要拿它的高比例掩盖其他模块。对重复HTML记录不逐行复述标签来凑数；相同口径的前后对照用于发现问题，不作为自动满分证明。复制源码入Word后再校核，防止截取和格式化吞掉注释。

优先补能解释参数语义、执行顺序、状态边界、职责、资源关闭和设计理由的注释；禁止重复标签释义、复制同一句、空注释或无关长段凑比例。统计值达阈值但关键模块解释不足时，代码质量项仍有缺口；教师原代码完整保留与课程允许修改边界继续适用，不为加分擅改原逻辑或增加未授权功能。

### 各维度分别验收

- 功能：原题每个独立动作都实际操作；正常、初始、边界和错误状态有具体判据，截图与读到的DOM/API/数据库值对应。
- 代码质量：正文代码可复制且与最终源码一致；注释数量与有效性分开核验，另看命名、职责、类型转换、异常与资源管理。
- 实验深度：回答指导书全部问题，解释输入→机制→输出及边界；有证据才写故障与解决，不用空泛总结或未授权扩展补“深度”。
- 结果与分析：每小题就近列操作、实现、真实截图和观察解释；IDE集成与应用界面要求用相应软件证据，命令行成功不能替代。
- 结构与心得：保留本学期模板、编号和教师栏，逐页查看字体、比例、代码可读性、图注及分页；心得按当前要求字数检查并结合本次结果，不移植他人经历。
- 提交与来源：逐项核对文件名、目录、最终包成员及哈希；按[全局叙述口径](../report-evidence.md#8-报告叙述归属与措辞)清理AI说明/间接说明与状态元叙述，未提交平台单列。

## 模板

## 评分反馈的使用

已见评阅维度：功能30、代码质量30、实验深度10、结果15、结构10、心得5。本人实验1为25/22.5/7.3/15/10/4.2，共84；7份A+为95—98.9。由此仅能推断优先补功能、代码质量、深度，不能还原教师/程序的精确算法，也不能保证后续实验沿用同一权重。
用户于2026-10-30提供的两次不同实验报告批改，均把结果15分拆为结果呈现10分、图表说明5分；其余为功能30、代码质量30、技术广度与深度10、结构10、心得5。以下以该反馈提炼共同自检项，不将两份样本拟合成评分公式，也不据最初的实验编号描述改写课程实验对应关系。

| 代码质量/30 | 代码行数、注释率、规范特征数 | 最终正文放可复制的真实代码，注释按上文双份、逐模块核验；检查命名、缩进、职责、输入处理等实际适用项。识别器的“规范特征”定义未知，内部核查项不冒充其词表，不复制代码或堆注释凑数 |
| 技术广度与深度/10 | 前端特征、进阶写法，或HTML标签种类、CSS技巧种类 | 分实验类型盘点原任务已用技术及其机制，按下文展示实际用法、理由和效果；不同类型不能横比特征数。未授权不新增框架、标签、技巧、功能或改教师代码来刷特征 |
| 结果呈现/10 | 截图数 | 以必做功能和不同状态覆盖安排真实截图，清晰、相关且批次一致；8张和14张均满分，不能推出固定张数门槛或无限加图有收益 |
| 图表说明/5 | 有说明图数/总图数 | 逐图配图号、证明对象、触发操作/输入、可见结果与解释；已有图号或“运行成功”不算充分说明。表格同样说明字段、口径和结论，不只满足形式上的说明覆盖 |
| 结构完整性/10 | 目的、环境、步骤、代码、结果、总结六块 | 在原模板内用可识别标题及实质内容覆盖六块并保留顺序；标题齐全不能掩盖正文缺项 |
| 心得体会质量/5 | 字数、具体细节、命名实体、个人动作 | 按下文充分展开并逐段核对对象、动作、观察及认识；字数和计数作诊断，不虚构教师分数或自动满分条件 |

### 技术深度写进对应任务

从本次真实代码建立“技术点 → 文件/代码块 → 机制和选用理由 → 输入或触发 → 实测效果/边界 → 报告位置”的对照。HTML/CSS说明实际标签的作用、选择器范围、布局与关键属性的配合；JavaScript说明事件、状态、DOM更新、类型转换及已有边界处理；后端按本题说明参数绑定、分层、依赖注入或数据访问，不拿前端标签数替代后端深度。

“进阶写法0个”先检查已实现的内容是否在正文缺失、截断或未解释；没有就如实记录，不把讲原理等同于被评分器识别为进阶。允许且有独立授权的扩展在原题完成后另列，并真实执行验证；仅拟议的改进明确用建议语气。两个样本不能确定哪些写法算进阶或其得分函数，不能承诺只改解释就涨分。

### 心得充分展开：多写真实内容，增加不同对象与动作

用户于2026-10-30明确偏好心得尽量写长，具体细节、命名实体及个人动作尽量丰富。将这一偏好落实为：在教师字数上限、模板、真实性和本人写作要求内，尽量覆盖本次各主要任务及有依据的比较、认识与改进，不在达到80字或某个历史字数后提前收笔；没有上限时不自行设置统一字数封顶。每增加一段都应增加新的对象、观察、机制解释或有依据的认识；只有重复、套话或臆造可补时停止。教师明确要求简短或有上限时优先遵从，不挪到其他章节规避。

按真实记录选用“具体对象和起点 → 实际动作或比较 → 可核验的变化/结果 → 原因与认识 → 有依据的改进”串成自然段，不强迫每段套同一句式。没有故障也可写正常状态差异、原实现的边界和验证方法，不编排错误经历。尽量从不同任务、不同状态取材，不能只把步骤全文复制进心得。

- **具体细节**：优先实际参数、属性、输入值、前后状态、输出字段、真实错误及修复复验；说明这些细节支持什么认识。不同细节尽量多覆盖，同一数值换句重复不算新增细节；时间、次数、版本无来源不填。
- **命名实体/具体名称**：写出本次真正使用的文件名、类/方法/函数、DOM元素或选择器、CSS属性、事件、注解、配置项及工具名，并解释其在本次过程中的作用；例如只有实际用到才写 `addEventListener`、`disabled`、`display: flex`。这是本地“具体名称”检查，未知评分器是否把这些都算命名实体，不能冒报其识别数量。两份反馈均为命名实体0个但心得仍有4.7/5和5/5，不将非零数量捏造成满分必需项。
- **个人动作**：尽量覆盖有依据的不同动作，如检查、定位、修改、对比、验证、复测；每个动作关联具体对象、原因和观察结果。本人确实做过且有明确确认时自然写“我将……”“比较……后发现……”；代理执行未获本人复现确认时使用客观过程说明，并将需本人补充的体验记内部待办，不能靠添“我”伪造动作。未做的改进写计划，不能改为已完成。
- **学习认识**：解释本次结果改变或澄清了什么理解，怎样检查同类问题及适用边界；未经本人确认的主观感受不冒写，心得仍按“AI完整草稿→本人结合想法修改→重新核验”处理。不能用增加篇幅取消本人修改或课程要求的AI披露。

定稿后在现有内部自检记录列：心得位置、字数与计数范围（只算心得正文，排除标题/代码/图注及制作记录）、各不重复细节/具体名称/动作的原句位置及来源、本人确认范围、事实或归属缺口。没有官方识别器时把人工盘点标为“本地诊断”，与教师识别值分列；不为未知算法杜撰“至少N个”硬阈值。修改后比较是否增加新信息、是否仍自然可读；数量上升但重复或失实则退回修订。

两份反馈中的心得为1174字/4.7分和1830字/5分，细节6/7处、个人动作1/2处；字数、细节与动作同时变化，且不是同一实验的受控对比，不能证明越长必然越高分。7%注释率得30分、16%得29.7分，同样不能推断低注释率更优或取消原通知的注释条款。优先充分表达和真实覆盖，不用堆字、重复名称、虚构动作、冗余代码/图片或擅改实验来追求计数。

内部复核逐维度列证据、缺口和扣分风险，正式分数待教师评阅。没有原评分算法及标定依据时，不再凭观感给95.5等精确总分，也不把“自评达到95”当作A+通过条件。未完成必做操作、只有旧截图、源码未回归、注释未核对到正文、版式未渲染任何一项都阻止宣布完成。完成有证据支持的修订后停止无依据刷分。

## 执行顺序

当前通知/指导书/模板及同题样例核对 → 全部教师踩分点与原编号覆盖表 → 按原步骤实际执行和取证 → 正常/边界/错误路径验证 → 逐模块补有效注释并核验源码 → 在原模板内就近写操作、代码、结果、问题回答和分析 → 逐小题截图覆盖及逐图说明核对 → 统计最终源码与Word正文的逐模块注释率及质量 → 按类型盘点已有技术深度、充分展开心得并记录字数/具体细节/名称/真实动作 → 内容审校与逐页渲染修复 → 当前七项反馈维度及其他教师条款逐条反查原文、证据与最终页码 → 定稿后措辞归属与自然度自检 → 更新课程目录交付包并重开核验 → 最终回复展示踩分缺口与注释实测。

有必做踩分点未执行/未核验、关键代码缺正文、注释统计不覆盖最终正文、样例对照未按授权完成、措辞自检未完成或版本错配时，保留具体缺口，不称全部完成或A+；只有旧证据时核验其仍适用并标日期，不能冒充新执行。加分条款完成与教师实际评分分别说明。
