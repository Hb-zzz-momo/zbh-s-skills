# Web 应用开发课程规则

适用来源：用户提供《实验前先阅读》实验注意事项、当前报告模板、实验指导书、本人实验1的B级评阅记录及7份A+评阅记录（2026-09-20核对）。这些规则不是所有课程的通则；新通知到来须重新核对。

## 教师踩分点先形成验收表

开工前全文、逐页读取本学期通知、指导书、讲义、报告模板和课堂补充要求，把所有任务、图中限制、模板提示、必答问题、加分和扣分条款拆成可检查条目。按教师原编号执行，用户额外要求另列来源与ID；原材料未知的分值、注释阈值和认可状态不得自行补定。

功能与边界、代码质量及有效注释、实验深度与问题回答、运行结果与截图、模板结构与排版、心得、命名与提交分别列项；只在当前材料有要求时采用具体权重。每个条目须回填“实际做了什么、看到什么、为什么满足判据”，不能用“全部完成”“有截图”或一个阶段概括覆盖多条要求。条件加分项注明是否满足，未满足不能写已获分；用户明确选入的可选项按本次必做验收。

用户要求参考学长报告时，优先完整读取已提供的同题报告，定位正文的操作、代码、观察值、解释与排版，建立“值得借鉴/技术断言需复核/不可移植”的对照记录。仅沿用实验一优秀报告的通用写法或只读教师评语，必须如实说明，不能宣称已完成本次同题报告对照。

## 正文与证据

用户要求参考优秀报告、认为正文简短或分析不足时，先读[优秀正文迁移与分实验规则](web-report-content-patterns.md)。参考其任务组织与观察方法，独立核对事实；不能只从教师评语、篇幅或注释比例反推报告内容。

- 文件名按通知为“学号_姓名_实验x”；不从旧下载样例的加号推导改名。
- 保留目的、环境、步骤、核心代码、运行结果、心得六个逻辑要素。在原模板栏目内按任务安排操作、代码、结果、分析，使同一任务就近闭合；不要重排教师固定栏目，也不要把全部步骤和全部讨论分别堆在两端。
- 核心HTML/CSS/JS/Java/SQL/配置以可复制文字放正文，取自交付源文件；保留模块、边界、设计理由等有效注释。注明文件与节选范围，关键调用链必须完整。程序输出不能伪装成源码注释。
- 运行效果配真实截图与具体判据。代码截图仅作补充。附源工程供复现，但不能让正文仅有截图和路径。
- 截图的覆盖、分段、批次、来源与可读性逐条要求见 [证据链与截图](../report-evidence.md) 的“截图逐条要求”；本课程的长页面分段做法见 [优秀正文迁移与分实验规则](web-report-content-patterns.md)。
- 心得超过80字，解释具体知识、验证、局限与改进，不编造个人操作时长、错误、学习感受。通知提到注释比例奖励，但不据此堆注释；代码质量还应检查命名、职责、格式、边界与资源管理。

### 注释必须在正文中核验
已核对的《实验前先阅读》规定注释比例超过5%开始加分，20%左右拿满此档；本学期重新核对原文，有更新以当前通知为准，不能把此阈值当作所有课程的通用要求。这里是代码“注释率”，不等同于Word“批注率”；如教师另有批注要求，另列条款验收。未知计分算法不得推算精确总分。

正文定稿后，按“交付源码”和“最终Word正文”分别统计，并逐语言/模块列出：文件/正文代码块位置、非空代码行数N、含语法注释的行数C、C/N比例、教师阈值及来源、有效性缺口。默认诊断口径为非空源码行作分母，含行内注释或块注释的行每行最多计一次；空行、代码外分析、程序输出、截图、模板提示和Word批注不计入。教师指定其他口径时同时保留教师口径与诊断口径，明确差异，不能悄悄换分母。

语言注释采用Java/JS/CSS的//或/* */（CSS仅/* */）、HTML/XML的<!-- -->、SQL的--、配置及PowerShell的#。必须识别字符串、URL和注释边界，不能把字符串中的//算成注释；无代码块的报告不能据零分母推定合格。统计总比例还必须展示逐模块值，复制源码入Word后重算并核对注释与后续语句是否丢失、错位或被裁切。
逐模块查缺口：CSS选择器及关键属性、JS状态与事件、HTTP绑定与响应、三层职责与错误传播、JDBC参数与资源、Mapper映射、CRUD反向断言与清理、24条SQL的条件含义。所有核心测试也须有有效注释。短SQL一行一句可能自然高于20%，不要拿它的高比例掩盖其他模块。对重复HTML记录不逐行复述标签来凑数；相同口径的前后对照用于发现问题，不作为自动满分证明。复制源码入Word后再校核，防止截取和格式化吞掉注释。

优先补能解释参数语义、执行顺序、状态边界、职责、资源关闭和设计理由的注释；禁止重复标签释义、复制同一句、空注释或无关长段凑比例。统计值达阈值但关键模块解释不足时，代码质量项仍有缺口；教师原代码完整保留与课程允许修改边界继续适用，不为加分擅改原逻辑或增加未授权功能。

### 各维度分别验收

- 功能：原题每个独立动作都实际操作；正常、初始、边界和错误状态有具体判据，截图与读到的DOM/API/数据库值对应。
- 代码质量：正文代码可复制且与最终源码一致；注释数量与有效性分开核验，另看命名、职责、类型转换、异常与资源管理。
- 实验深度：回答指导书全部问题，解释输入→机制→输出及边界；有证据才写故障与解决，不用空泛总结或未授权扩展补“深度”。
- 结果与分析：每小题就近列操作、实现、真实截图和观察解释；IDE集成与应用界面要求用相应软件证据，命令行成功不能替代。
- 结构与心得：保留本学期模板、编号和教师栏，逐页查看字体、比例、代码可读性、图注及分页；心得按当前要求字数检查并结合本次结果，不移植他人经历。
- 提交与来源：逐项核对文件名、目录、最终包成员及哈希；按[全局AI位置核对](../report-evidence.md#8-ai-report-与真实参与来源)列全声明和实际参与、标注核对预览，未提交平台单列。

## 模板

从当前教师空白模板复制填写；保留页边距、标题颜色、自动编号、表格网格/列宽、红色提示、教师评语栏。只清空占位与旧答案，不用旧已填样例覆盖新要求。自动编号需要结合numPr和渲染检查，不能按纯文字误判漏号。
Word/PDF逐页检查：代码可读且可复制、截图等比例、图注不分离、无裁切与无意义空页。页数不设奖励；不能为了压页数损失正文。

## 评分反馈的使用

已见评阅维度：功能30、代码质量30、实验深度10、结果15、结构10、心得5。本人实验1为25/22.5/7.3/15/10/4.2，共84；7份A+为95—98.9。由此仅能推断优先补功能、代码质量、深度，不能还原教师/程序的精确算法，也不能保证后续实验沿用同一权重。
内部复核逐维度列证据、缺口和扣分风险，正式分数待教师评阅。没有原评分算法及标定依据时，不再凭观感给95.5等精确总分，也不把“自评达到95”当作A+通过条件。未完成必做操作、只有旧截图、源码未回归、注释未核对到正文、版式未渲染任何一项都阻止宣布完成。完成有证据支持的修订后停止无依据刷分。

## 执行顺序

当前通知/指导书/模板及同题样例核对 → 全部教师踩分点与原编号覆盖表 → 按原步骤实际执行和取证 → 正常/边界/错误路径验证 → 逐模块补有效注释并核验源码 → 在原模板内就近写操作、代码、结果、问题回答和分析 → 逐小题截图覆盖核对 → 统计最终源码与Word正文的逐模块注释率及质量 → 内容审校与逐页渲染修复 → 六类评分维度逐条反查原文、证据与最终页码 → 定稿后AI声明/实际参与位置核对及标注预览 → 更新课程目录交付包并重开核验 → 最终回复展示踩分缺口、注释实测与AI声明位置。

有必做踩分点未执行/未核验、关键代码缺正文、注释统计不覆盖最终正文、样例对照未按授权完成、声明位置清单缺失或版本错配时，保留具体缺口，不称全部完成或A+；只有旧证据时核验其仍适用并标日期，不能冒充新执行。加分条款完成与教师实际评分分别说明。
