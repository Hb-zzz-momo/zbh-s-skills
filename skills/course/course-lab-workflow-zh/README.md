# 通用实验课 Skill · course-lab-workflow-zh

版本：1.0.3｜整理日期：2026-09-15｜修订：2026-09-18（P0 模式与课程规则、内容全量自检、去 AI 痕迹、格式全量自检）｜默认语言：中文

## 1. 用于什么

把课程实验组织为：

**材料核对 → 环境适配 → 分模块带练 → 证据验收 → 按模板成稿。**

同一套规则支持从零教学、命令与源码解释、环境排错、截图规划、实验报告生成、指定章节修改和实验复盘。只执行本次需要的阶段；单点问题不强制展开全部流程。

核心是三个对应关系：实验要求与操作对应，操作与真实证据对应，真实证据与报告结论对应。教学保留生活例子、语法拆解、知识点和逻辑链路；正式报告继承本课程母版，不混入教程口吻。

## 2. 适配的课程类型

| 类型 | 特别处理 |
|---|---|
| Linux、权限与网络实验 | 明确本地/远程、账号和目录；环境替代覆盖边界；多机证据；最小权限 |
| RUCBase / 数据库内核 | 源码和接口定位；执行器树；控制与数据链路；功能验证与评测区分 |
| NoSQL 与 Java 数据访问 | 服务端、客户端、驱动、认证、数据库与集合/键的边界；写入后回读 |
| Hadoop 生态与大数据组件 | 课程版本约束、依赖次序、分布式角色、数据流和端到端验证 |
| Python 日志分析与可视化 | 输入路径、字段、清洗、统计、图表解释和数据校验 |
| OpenDigger / OpenRank 类课程项目 | 数据获取—清洗—存储—指标—接口—展示链路；实现与运行分离 |
| Web 应用开发 | 保留 Web 原模板；页面效果、交互、关键代码和个人任务标识对应 |

这些规则根据本次可检索的课程材料、报告规范及历史项目记录整理。部分课程只有历史记录，未获得全部原始指导书、源码或评分记录；不能据此认定全部历史实验已经核验或重新运行。具体依据见[项目依据与迁移](references/project-basis.md)。

## 4. 放入客户端

解压后保留**整个 `course-lab-workflow-zh` 文件夹**。主文件使用相对路径读取配套规则，单独复制 `SKILL.md` 不会自动包含其他文件。

截至本次核对，下面是两个客户端的个人技能目录：

| 客户端 | 放置后主文件所在位置 |
|---|---|
| Codex | `~/.agents/skills/course-lab-workflow-zh/SKILL.md` |
| Claude Code | `~/.claude/skills/course-lab-workflow-zh/SKILL.md` |

仅对某个代码仓库使用时，可分别放到仓库的 `.agents/skills/course-lab-workflow-zh/` 或 `.claude/skills/course-lab-workflow-zh/`。`~` 表示**运行客户端所在环境**的用户目录；本机 Windows、WSL 和远程 Linux 的用户目录不是同一个位置。

使用文件管理器复制到对应位置即可；已经存在同名目录时先比较并备份，不直接覆盖。放置文件后按客户端方式确认技能已被发现。此交付仅生成文件包，未修改或安装到用户设备，也不代表所有聊天产品都会自动加载该目录。

客户端目录依据于 2026-09-15 核对的官方说明，未来变化以客户端文档为准：

```text
Agent Skills 文件规范：https://agentskills.io/specification
按需加载原则：https://agentskills.io/skill-creation/best-practices
Codex 官方技能说明：https://developers.openai.com/codex/skills/

```

## 5. 可直接复用的调用语句

已有上下文中明确的信息直接沿用，不必重复填写；未知项保留“待核验”。

```text
使用 course-lab-workflow-zh。

课程与实验：{课程名称＋实验编号/名称}
本次目标：{从零带练／排错／生成报告／只修改指定章节／复盘}
已有材料：{实验要求、指导书、原模板、源码、数据、截图与日志}
当前环境与进度：{机器、终端、工作目录、已完成步骤、阻塞问题}
输出与修改边界：{需要的文件类型、指定母版、允许修改的范围}

先读取材料，建立“要求—操作—验证—证据—报告位置”的对应关系。
教学按模块给生活例子、可执行步骤、验证方法、知识点和前后逻辑链路。
有明确关联时对照过去项目解释共同原理，但不迁移旧实验的运行结果。
报告保留本课程原模板；只写真实操作与结果，缺失证据集中标注。
```

调用后可能只输出当前模块、修复步骤或指定章节，而不是每次生成全部交付物。这是按当前任务缩小范围，不是漏做完整工作流。

## 6. 建议的实际用法

首次做新实验，复制[任务卡](assets/task-card.md)整理材料与验收要求；带练时沿用[模块模板](assets/tutorial-module.md)；边执行边填写[实验记录](assets/lab-record.md)，记录真实输出、截图和问题。

需要 Word 时提供本课程原始模板，并注明其他报告仅供内容还是视觉参考。证据不完整时生成待补充版，不让格式完整掩盖实验缺口。

多人服务器、数据库删除、权限变更和评测提交等操作必须先明确权限与范围。只有本人有权限执行的动作才进入实际步骤。AI Report 记录真实参与，不用统一“仅润色”替代实际情况。

具体命令见[测试说明](tests/README.md)，本次实际检查记录见[验证记录](VALIDATION.md)。主文件约定、引用完整性、检查脚本单元测试、模型行为测试和用户实验验收分别记录，不能互相替代。
