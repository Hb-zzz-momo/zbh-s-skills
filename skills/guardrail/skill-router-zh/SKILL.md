# 任务分流与按需辅助

只管理通用分流，领域主Skill负责执行和交付。当前采用用户已采纳的方案B；不是每个新任务都联网。已有直接领域入口仍有效，不为补一次路由重新开工。

## 一次分流

1. 读适用规则和当前材料，确定真实项目、目标、交付物、验收与授权。聊天临时目录不自动等于目标项目。课程先按课程、实验编号、版本查专属Skill，读取正文后以它为主；通用技能只补未规定事项，当前用户指令优先。
2. 选一个当前阶段主Skill，按下表加载必要正文；轻量稳定问答、给定文本或机械操作可直接处理。标准任务用领域流程，项目任务分阶段推进；复杂程度、风险、评审要求分别判断。
3. 按下一节补背景和辅助，已有同版本完整正文、已核来源和答案在当前上下文中就复用。版本不明、压缩丢失、变化或冲突时定向重读；不只凭“以前看过”跳读，也不全盘扫描。辅助返回当前主线，不回调整套通用路由。
4. 执行必要领域验证和独立评价后交付。每阶段通常1主＋0至2辅助是软预算，必选步骤超过预算时分阶段安排，不能省掉要求。短任务也不能跳过身份、授权或高风险检查。

复杂任务沿用现有锚点，保留目标与验收、主Skill、背景/来源、约束变化、未决项和验证即可；小任务留当前上下文，不强制新建运行状态文件或记忆库。开始只简述选定主线和必要辅助，不要求机械输出未加载清单。

## 辅助触发及交接

| 触发 | 执行与返回 |
|---|---|
| 涉及已有项目、历史决定、失败经验或恢复 | 读取 `three-layer-project-memory-zh`；根规则→manifest→当前总览→相关records→必要原件，返回现行事实、相关历史/经验、来源与缺口。核实当前材料；只读不init/put/seal。无库用现有材料，不自动建库；已配置经验库按身份/范围定向查 |
| 外部缺口、易变事实、当前版本/价格/规则、需直接引用或用户明确要求搜索/找Skill | 用 `pre-task-research-zh` 定向补证；先本地已有能力，再查必要原始资料。纯调研直接以 `info-evidence-chain-zh` 为主，不重复做完整前置调研 |
| 科研创新、gap、novelty、强基线或胜负判断 | 按科研主Skill完成文献、反例、原始结果和适用审计，不能以B或轻量分档跳过。更高优先级及领域强制检索照用 |
| 用户明确不联网/仅用给定材料 | 遵从，披露影响结论的证据缺口，不假称已核实；推进不依赖缺口的工作 |
| 会改变路线的时间、资源、能力或验收条件未知 | 用 `task-constraint-discovery-zh` 只补关键未知，不重复问已有答案 |
| 多阶段、反复修订、跨上下文或明确跟进 | 领域执行前接入 `automation-error-learning-zh`；复用同一锚点、事件ID、写入者和阶段检查点，关键事件/阶段增量记录，不后台监听、不每次工具调用复盘 |
| 实际需要质量评审、评分、候选比较或交付验收 | 按持续授权用 `multi-agent-evaluation-zh`；真实执行者和独立评审分离，重要/复杂追加复核。课程三agent及轮数等专属要求保留；纯问答/翻译/机械操作不虚构评分，评审者不递归派评审 |
| 长任务出现重复读取成本 | 按需用 `context-budget-guard-zh`，小任务不建地图；缓存不替代动态事实核验/测试 |
| 新建或重组持久化文件树 | 用 `project-structure-architect` 先核规则、职责和唯一位置，必要时结构审计；已有唯一目标的纯内容编辑不重复调用 |

同任务续做只补新增问题、变化或丢失上下文。联网止于关键问题有可定位证据、适用条件明确、冲突已处理且验证路径可行；不以站点类型/链接数凑量。找不到合适Skill仍继续完成主任务。

评价体系能力或建议新增前，按能力与别名定位并实际读取相关候选Skill及入口；区分可见、已读、已调用、效果已验证。未读/不可访问是未核实；已存在未接入、未执行与查证范围内缺失不能混称。独立评审收到相关既有组件，不能只审新文件自洽。

## 领域主入口

| 任务 | 主线与条件细则 |
|---|---|
| 普通知识问答、数据库/后端常规开发排错 | `project-dev-zh`；代码变化按必要增量、测试与审查；复杂工程/架构/多方案改用 `engineering-skill-flow-zh` |
| 课程实验、报告 | 本课程本实验专属Skill优先；无专属时课程规则＋`course-lab-workflow-zh`，带练可用 `lab-report-coach-zh`；教师模板、完整原步骤、身份、真实输出/截图、披露、渲染和必选独立评价均保留 |
| Web新建/改版/视觉方向 | `web-design-workflow-zh`；局部UI交互/bug用 `frontend-ui-engineering`，必要真实浏览器验证 |
| 科研创新或多候选 | `research-skill-flow-zh`；实验运营用 `research-experiment-ops-zh`，formal/冻结/论文claim加 `decisive-result-audit-zh` |
| 资料调研 | `info-evidence-chain-zh`；不重复进入research全套开工 |
| 论文/翻译 | `paper-writing-zh` / `translation-zh`；排版用 `paper-format-fixer-zh`，不编造结果 |
| 宣传、黑客松须知 | `publicity-content-workflow-zh` / `hackathon-content-workflow-zh`；按载体与局改分支，事实先核验 |
| PPT/软著 | `ppt-workflow-orchestrator-zh` / `software-copyright-zh`；仅故事线用 `ppt-story-design-zh` |
| 其他领域、工具建议、CI、考试、运维、结构、沉淀 | 在[已有领域索引](../../SKILL_ROUTING.zh-CN.md)定位对应行，不默认全文加载 |

选定领域后，仅在相关分支需要时读[路由细则](references/dispatch-details.md)对应小节：高风险动作读“统一硬门槛模板”；工具建议读“四层”；固定计划、工程、科研、Web、PPT/软著等保留各自专属门槛。无新领域问题不重查索引。

执行或制品验收在完成声明前按[执行输出与完成声明规则](../../course/course-lab-workflow-zh/references/verification-completion.md)检查完整日志：未分类诊断阻断声明；运行、正确性、必要视觉和最终包分开判断。规则文本/格式校验/隔离试点不能冒充真实业务或长期效果。Skill批次完成检查和必要评审后按现有授权窄提交推送并核远端，保留并行修改。
