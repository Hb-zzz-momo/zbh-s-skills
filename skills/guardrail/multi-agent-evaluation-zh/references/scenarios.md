# 场景与边界

| 请求 | 分工与评价依据 | 必须避免 |
|---|---|---|
| 按课程模板做实验报告 | A 实验和写作；B 审查；C 独立评分。沿用课程规则、教师细则及现有轮次；查原始日志/截图与渲染页 | 模拟三 agent；内部估分填入教师成绩栏；平均分掩盖缺实验 |
| 交付项目或模块 | A 实现和验证；B 对需求、真实入口、失败路径和最终包验收；复杂边界加 C | 仅凭作者测试摘要评分；用审查意见代替运行证据 |
| 撰写文档或论文 | A 写作；B 对来源、论证、完整性和必要版式核验；重要论证加 C | 把结构合格当事实成立；忽略渲染后裁切；评审者修稿后自验该段 |
| 从三个科研思路中选一个 | A 提候选和资源约束；B 独立按问题证据、机制与可证伪性评价；重要选择由 C 独立复核 | 先选喜欢的候选再调权重；把假设评分当实测性能或已证实创新 |
| 验收科研结果 | A 整理 raw/config/metric/summary；B 独立重算/检查复现；C 复核关键统计与 claim，回领域决定性审计 | 多数同意就称优于基线；无效指标因均分较高而通过 |
| 优化或新增全局 skill | A 修改；B 独立试用现实请求、找路由冲突；重大跨领域规则加 C | 仅凭格式校验通过就宣称行为可靠；测试时暗示正确结论 |
| 翻译一句话或改一个错字 | 主代理完成，不为机械操作虚构质量门槛；用户明确要求独立评价时再启用 | 所有短问答都强制多 agent 和打分 |
| 用户要求这次只用一个 agent | 遵从当前指令；需要评价时明确为作者自检及独立性限制 | 以持续授权为由无视用户禁用 |
| 工具故障，只能主代理工作 | 继续已授权准备与验证，保留“独立评价未完成” | 换角色名捏造独立评分或宣称独立验收完成 |

评分示例：教师已有 100 分细则且原图缺失，记录该项无法核验及其门槛，不能假设满分；内部部分分数必须同时显示实际覆盖的分母。科研排序若有两个代理给出相反顺序，应定位到证据与权重差异，必要时补检索/小样验证，不直接投票。
