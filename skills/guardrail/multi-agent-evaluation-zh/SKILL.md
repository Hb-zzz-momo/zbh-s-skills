# 多 agent 独立评价

## 触发与授权

用户已于 2026-10-15 持续授权：凡任务需要评价指标、质量评审、候选比较或交付验收，默认调用独立子代理，不必每次再问。包括项目/模块、实验报告、文档、科研思路和科研结果；本次用户明确要求单代理或停止委派时优先遵从。

触发依据是实际评价或验收需求，不能为了调用本技能给简单任务虚构评分。普通检查可由主代理先做，但不得当作独立评价。代理权限只覆盖当前任务；不额外授权发布、提交平台、联系他人、付费或修改无关文件。

本技能管理评价，领域主技能管理执行；调度细节由 [subagent-orchestration-zh](../subagent-orchestration-zh/SKILL.md) 补充。已有专属规则规定三 agent、轮数或评分细则时保留要求，不用这里的默认值削弱它们。课程报告继续遵守 [独立报告审查规则](../../course/course-lab-workflow-zh/references/independent-report-review.md)。

## 角色与独立性

| 角色 | 职责 | 边界 |
|---|---|---|
| 执行者 A | 做实验、实现模块、写文档或提出候选，提供原始证据并修订 | 自检结果不能冒充独立评分 |
| 评审者 B | 独立读取标准、产物和原始证据，提出问题并给出评价 | 不修改被评对象，不为自己写过的部分作最终独立验收 |
| 复核者 C（按需） | 独立评分、核验关键证据或裁决事实分歧 | 初评完成前不看 B 的结论；不能只给已有评分背书 |

普通评价至少 A+B；复杂、重要或有争议的评价使用 A+B+C，或遵从专属规则指定的人数。数量以运行时可用槽位为限，可串行运行；不把增加 agent 数量当作质量保证。

同一交付的评价由主代理统一调度。评审者完成自己的任务卡，不因“评价本身也是交付”递归创建评审者；需要额外专长或第三方裁决时，向主代理提出有范围的请求，由主代理按现有槽位安排。

B、C 必须是真实且不同的代理身份。优先使用不继承作者推理历史的独立上下文，例如可用时设置 `fork_turns="none"`；给必要输入，不给作者期望分数、预设结论或其他评审的初评分。遵守当前会话的模型选择规则，不为了独立性擅自更换模型。

同一轮先各自形成判断，再交流分歧。可以使用同一个模型，但要说明共享模型和共同输入仍可能造成共同盲点；独立评价减少自评偏差，不能保证消除误差。

## 执行闭环

1. **先定标准。** 从题面、教师细则、用户需求、模板或领域规范提取评价维度、证据要求、门槛和阻断项。有现成标准就照用；没有时标注为“内部拟定标准”，先记录再评，关键含糊项才向用户澄清。候选排序原则在比较前确定，不因偏爱某个候选改标准。
2. **准备可审版本。** 明确本轮产物、范围和版本；对文件记录提交号或摘要，对文稿/候选记录固定快照。评审期间不改被评版本，可在隔离副本准备修订。评审者读取原始材料、代码、数据、日志、实际渲染页等，不只读取作者摘要。
3. **独立派工。** 给每个评审者下方任务卡，指定只读范围和单独的评价记录位置。必要验证可以执行，但会改数据或生成文件时使用隔离目录，不能污染冻结输入。让评审者先报证据缺口，再给分或结论。
4. **证据评价。** 每项发现定位到文件/行、页/图、数据/日志或候选假设，区分已核实、待核实和未验证。给出影响、最小修订和复验方法；证据不足不猜分、不编结果。
5. **处理与复验。** A 逐项接受、凭证据反驳或记录待办，不得改写评审原始结论。修订后交 B/C 检查受影响项及必要回归，最终分数必须对应最终版本；旧分数不能直接沿用到新版本。
6. **收口。** 同时报告独立评价结论、分数性质、主要修订、证据缺口和最终版本。任何必选项未闭环仍按领域规则阻断验收；主代理负责集成和如实交付，不能凭自己的决定覆盖未解决的独立阻断项。

## 指标、评分与分歧

- 优先使用领域原有指标；适合打分时才给数值。代码可按验收项和缺陷严重性，文档按内容与版式，科研思路按问题证据、机制、可证伪性和资源可行性，科研结果按原始数据、指标实现、统计与复现评价。不硬套统一百分制。
- 数值评分列出维度、满分/权重、得分、证据和扣分原因，权重合计须一致。未知项明确留空并列为未验证，不能静默按满分计入；确需部分总分时标注覆盖范围和分母，不冒称完整总分。
- 多人使用相同标准时保留各自分项、总分和分歧；仅在事先定义了汇总方法时计算汇总分。不同维度、不同量表不直接平均；阻断项不能被均分、投票或其他高分抵消。
- 分歧先回到原始证据和标准；事实可重跑/重算，主观判断注明理由。必要时让 C 做独立复核，之后再对照讨论。无法解决时保留异议并给 CAUTION/BLOCK，不挑最高分、不反复换评审刷到通过。
- 机器测试、领域审计、人工确认各自提供证据。评审一致不能替代真实实验、真实页面检查或 formal/论文 claim 审计。内部建议分不是教师成绩、平台验收或正式论文认可。

## 轮次与停止条件

首轮发现问题后修订并复验，重点覆盖受影响项；领域规定固定轮数时照办。没有专属规定时，以必选项与证据是否闭环决定停止，不为了“多轮”重复空评。

同一阻断连续两次复验无新证据时，停止重复派同类评审，改查根因或补前置条件；已授权的独立工作继续做。只有缺用户输入或外部条件才请求介入，不无限循环刷分，也不把未解决任务宣布完成。

缺真实子代理工具、槽位或执行失败时，可继续准备产物和作者自检；明确标记“独立评价未完成”，待工具可用再补。不得模拟多个 agent 或把作者自评分写成独立通过。

## 最小任务卡与记录

小任务记录可直接留在对话中；正式交付在已有证据/修订目录下保存，不新造平行产物树。多文件放置依现有项目结构规则。

```text
评价任务：用户目标、当前范围与禁止扩大项。
角色与身份：作者 / 独立评审 / 独立复核；真实 agent ID。
输入版本：文件清单、提交号/摘要或固定快照；原始证据位置。
评价标准：来源、维度、权重/量表（如适用）、门槛、阻断项。
权限：被评对象只读；可用工具；唯一记录/临时输出目录。
输出：逐项结论；证据定位；问题及严重性；分数及性质（如适用）；
      最小修订、复验方式、未验证项；PASS / CAUTION / BLOCK 及理由。
独立性：初评前不读取作者预期评分或其他评审结论。
停止：只完成本轮评价，不改被评对象、不提交、不发布。
```

记录评审输入版本、真实代理身份、原始意见、作者处理、复验结论和最终产物版本。能力可用性与缺口也要记录，不能只留“通过”两个字。
