# 已有图片复现工作流

## 适用场景

用于复现用户给出的截图、image2 生成图、论文图、架构图、流程图、机制图或已有 SVG/PNG/PDF。目标不是“生成一张差不多的图”，而是产出可审稿、可说明边界、可继续编辑或稳定插入文档的图形资产。

## 先锁定两个目标

复现前必须分别确认：

- **视觉目标**：是像素级接近、结构接近、风格接近，还是只要内容等价。
- **编辑目标**：需要逐元素可编辑、只需文字可改、只需能插入 WPS/论文，还是只需 PNG/PDF 稳定输出。

如果用户   同时要求“精准复现”和“完全可编辑”，要说明这通常是两条交付轨道：稳定视觉文件负责像，原生可编辑文件负责后续改；二者可能不能 100% 同时满足。

## 交付等级

| 等级                | 交付物                                      | 适合                                 | 必须说明                                       |
| ------------------- | ------------------------------------------- | ------------------------------------ | ---------------------------------------------- |
| L0 视觉稳定版       | PNG/SVG/PDF                                 | 论文、汇报、WPS 插入、最终展示       | 不一定可逐元素编辑                             |
| L1 固定背景可打开版 | `.drawio` 或 WPS 文件中嵌入稳定 SVG/PNG   | draw.io/WPS 中查看、加批注、轻量标注 | 背景整体不可拆成原生形状                       |
| L2 半可编辑版       | 模块、文字、箭头可编辑，复杂图标用 SVG 组合 | 后续小改文字和布局                   | 图标可能是组合或嵌入 SVG                       |
| L3 全原生可编辑版   | draw.io/WPS 原生形状、文字、箭头、表格      | 需要长期维护的结构图                 | 必须真实打开检查，成本最高，像素一致性可能下降 |

不得把 L1 固定背景文件描述为 L3 全原生可编辑文件。

## 推荐 MCP 组合

| 图型               | 主力                    | 辅助                           | 说明                                                               |
| ------------------ | ----------------------- | ------------------------------ | ------------------------------------------------------------------ |
| 系统架构图、流程图 | `drawio`              | Inkscape、真实 SVG 图标库、WPS | draw.io 负责结构，Inkscape 负责最终 SVG/PDF，WPS 负责文档/演示插入 |
| 真实数据图         | `local_python_figure` | Inkscape                       | 数据几何必须来自真实表格或代码，Inkscape 只做版式                  |
| 生物医学机制图     | BioRender               | draw.io、Inkscape              | BioRender 用于图标和模板，不替代事实核对                           |
| image2/截图复现    | draw.io + Inkscape      | 图标库、WPS                    | 先做视觉稳定版，再按需要做可编辑版                                 |

## 执行流程

1. **拆解参考图**：列出主面板、标题、标签、箭头、图标、表格、图例、颜色、字体和尺寸。
2. **建立元素清单**：区分文本、形状、箭头、真实图标、数据图、装饰元素和不确定 OCR 内容。
3. **选择交付等级**：明确 L0/L1/L2/L3，必要时双轨交付。
4. **选资产来源**：优先使用 draw.io 图标库、Lucide、Font Awesome、Material Symbols、BioRender 或手工 SVG；禁止用字母占位符冒充图标。
5. **生成源文件**：结构图优先 `.drawio`/SVG，数据图优先 Python 脚本，最终输出 PNG/SVG/PDF。
6. **目标软件验收**：在 draw.io/WPS/Inkscape 或目标查看器中真实打开；文件可解析不等于布局可用。
7. **全图审稿式裁剪**：按主面板、连接区、嵌套流程、表格组、能力区、图例区分别裁剪检查。
8. **缺陷泛化复修**：任何局部问题必须执行 `defect-generalization-protocol.md`。
9. **记录交付边界**：在 `check.md` 写清交付等级、可编辑范围、已验收文件、残余风险。

## 禁止做法

- 只用代码画矩形、文字和箭头就声称精准复现。
- 原图有图标但复现图只用 `API`、`DB`、`USR` 等字母占位。
- draw.io/WPS 打开后布局混乱仍交付为可编辑文件。
- 只检查用户指出的局部，不扫描全图同类缺陷。
- 修了 SVG/PNG 但忘记刷新 PDF、draw.io 或 WPS 交付文件。
