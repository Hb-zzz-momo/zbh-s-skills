# 缺陷类型泛化协议

## 触发条件

只要出现以下任一情况，就必须执行本协议：

- 用户指出任一局部视觉问题。
- 自检、截图、裁剪图或目标软件打开后发现任一局部问题。
- MCP、XML、SVG、PDF 或 draw.io/WPS 渲染结果与预期不一致。

## 核心原则

局部缺陷默认不是孤立坐标问题，而是同类结构的规则缺陷。只有完成全图同类扫描并留下证据后，才能把它判定为单点问题。

## 必须流程

1. **局部症状归类**：把用户指出的问题归入明确缺陷类型，例如文字溢出、图标压字、表格行越界、连接标签贴边、嵌套小流程拥挤、目标软件重排错位。
2. **全图同类枚举**：列出所有同类元素，不能只列用户截图中的模块。例如一个数据库表行溢出，必须同时检查 API 表、指标表、能力表、外部数据表等重复行结构。
3. **全局规则修复**：优先改统一布局函数、卡片尺寸、padding、字号、换行规则、箭头避让规则或导出链路；只有确认确属单例，才允许单点坐标修复。
4. **同类审计证据**：为所有同类元素生成局部裁剪图、contact sheet、几何审计 JSON 或目标软件截图。全图缩略图不能替代局部证据。
5. **下游产物刷新**：修复后重新导出最终 PNG/SVG/PDF/draw.io/WPS 可编辑或背景版文件，避免源文件已修但交付文件仍旧。
6. **审计记录闭环**：在 `check.md`、`full-figure-review.md` 或同级审计文件中写明“报告问题 -> 缺陷类型 -> 全图扫描范围 -> 修复策略 -> 证据文件 -> 残余风险”。

## 缺陷类型映射表

| 局部症状 | 必须升级为 | 全图扫描对象 |
|---|---|---|
| 某个卡片文字溢出 | 文字适配规则缺陷 | 所有带文字卡片、按钮、能力项、API 行、数据库行 |
| 图标压住文字 | 图标-文字安全间距缺陷 | 所有 icon + label 组合、表格行、能力卡片、列表项 |
| 图标缺失或用字母占位 | 图标资产缺陷 | 所有软件、数据库、用户、浏览器、GitHub、医学/机制图标 |
| 表格行压住边框或图标 | 重复行布局缺陷 | API 表、数据库表、指标表、外部数据源表、metric ingestion 表 |
| 连接标签贴边或嵌入模块 | 连接标签避让缺陷 | 所有模块间箭头标签、双向虚线标签、返回流标签 |
| 小流程里的文字/箭头/图标相互挤压 | 嵌套流程间距缺陷 | 所有迷你流程、子流程盒、底部 callout、图标串联说明 |
| draw.io 或 WPS 打开后错位 | 目标软件渲染兼容缺陷 | 原生可编辑文件、固定背景文件、导出 PDF/SVG/PNG |
| 固定背景被描述为完全可编辑 | 交付边界缺陷 | 所有 draw.io/WPS/Office 可编辑性说明 |

## 禁止做法

- 只修改用户截图里的坐标或字号。
- 用 `ok:true`、XML 可解析、SVG 能打开、PDF 能导出代替视觉验收。
- 只看整图缩略图，不看局部裁剪。
- 修复源文件后不刷新最终交付文件。
- 没有记录全图同类元素扫描范围就声称已经放行。
- 未声明交付等级就声称“可编辑”。
