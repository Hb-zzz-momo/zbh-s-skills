# 信息证据链技能
<!-- project-structure-architect:gate:v1:start -->
## Project structure gate / 文件树结构门禁

只要本工作流将初始化或重组项目，或新建、移动应用、服务、包、模块、页面、API、研究步骤、实验、流水线、测试、文档或多文件产物树，必须先使用 `project-structure-architect`。

1. 开始前：读取适用的 `AGENTS.md`、`PROJECT_STRUCTURE.md`、`.project-structure.yaml` 和现有文件树，锁定项目类型、蓝图及唯一合理路径。
2. 运行中：每次新增或移动文件前先判断职责、所有者、复用范围和对应测试；禁止同义目录、根目录堆放、跨层混放及无关重组。
3. 阶段收口：纵向切片或阶段完成后检查结构漂移；新项目或重大重组更新结构文档，最终运行结构审计。出现 `BLOCK` 时停止结构性写入并先修正或询问用户。

纯内容编辑且目标路径已由用户或现有规范唯一确定时，可不重复调用。

## 目标

让用户能判断信息是否可靠、方案是否适用。搜索命中只得到候选；读原文核实事实，再按当前需求判断适配。来源可靠、结论成立、适合用户是不同判断。

简单事实查询直接给必要来源和答案；只有推荐、选型或重要对比才展开候选筛选。不为每次搜索强制评分、多代理、表格、文件或全套调研；领域检索与独立评价要求仍保留。

## 工作流

1. **确定查什么。** 从当前请求和已给材料确认研究对象、用途与验收；区分用户事实、临时假设和未决项。“当前方案”等指代若会改变研究方向，先澄清，只推进不依赖答案的检索，不先投入一条猜定路线。复用已确认条件；关键现实限制缺失时按需用 `task-constraint-discovery-zh`，不另发长问卷。
2. **先定目标与路线，再找候选。** 区分用户要达到的效果与提出的产品/实现方式；保留明确限定的品牌、方法和范围，不擅自改题。复用已给资产与条件，明确必选、偏好和会改变路线的未知；内部拟定标准须标明。按适用性检查复用/不新增、单一方案、模块组合或分阶段实施，不机械凑数，也不默认组合更好。按不同解法、术语及别名找候选，必要时跨语言检索；热度只作发现线索。
3. **读原始证据并按缺口补搜。** 实际打开支撑关键事实的正文，核对版本、日期、平台、依赖、许可和成本中会影响选择的部分；搜索摘要和目录站用于发现。厂商说明可支持所宣称功能，不能单独证明实际效果；对效果、兼容或可靠性的关键判断，按需查独立测试、问题记录及反例。多个转载不算独立来源。发现矛盾就追原件、调整查询，不能只收支持首选的材料。
4. **比较完整方案并执行下方关口。** 区分事实、适配推断和待验证项；主要候选按同一组用户条件比较。检查同时工作路径、共享资源与总成本（含配件、订阅、部署/携带/维护负担），不能只比单品参数或各模块分别可用。不同层的方法、软件和服务先说明替代/组合关系；评分须有合理量表和证据。
5. **给可行动结论与适度验证。** 推荐说明适用条件、选择依据、主要替代及最短使用路线；重要或仍不确定的选择，提出并在已授权范围做有代表性的小样。公开资料核验、已安装、实际运行及完整效果分别报告，不能把文档阅读当产品实测。搜索不自动授权安装、付费、上传私有资料或发布。

关键来源和适用条件已有依据、主要替代与影响选择的反例已处理，且继续检索不再改变判断时停止；关键未知仍可能改变选择则补证或给条件式建议。按任务调整深度，不凑来源数量、不宣称穷尽全网或全局最优；底层搜索服务的召回与排序未知时不编造其算法。

## 推荐前执行关口

采购、工具或技术路线选型在形成首选前，必须在已有任务记录或回答中留下简短决策依据；最终回答可以先给结论、随后展示依据，不强制表格或另建文件。单纯解释事实不触发；用户已锁定方案时，只检查其范围内的适配与取舍。

- **目标与约束**：本次解决什么、已有资产是什么，哪些是用户必选、偏好或关键未知。未要求的能力不能临时升为淘汰条件。
- **路线与必要性**：实际适用的实现路线及保留/排除的具体理由。只写“已比较”或列多个同类SKU不算检查了替代路线；无合格替代时说明原因，不强凑。
- **整套可用性**：关键工作路径及总成本是否成立；未知不计作满足，非必选缺项不作硬否决。组合须满足相同约束，不能靠放宽用户要求胜出。
- **取舍与反证**：存在合格替代时，说明其最强优势、首选的代价及什么条件会改变选择；尚无可行首选时，明确缺哪项证据，不先造首选完成清单。

缺少足以支撑上述判断的依据时，补最短必要检查或给条件式建议，不输出无条件“首选/最优”。加载Skill、就绪READY、搜索命中和检查表打勾都不能代替已完成的决策依据。收到会改变目标或约束的纠正后，复核依赖旧条件的候选、推荐及实施步骤，撤回失效结论，不只修改局部措辞。

## 最小交付

先回答用户问题，再提供足以核查的依据。小任务可留在对话；复杂调研沿用真实主题的现有记录，不为留痕创建平行资料库。

- 事实查询：答案、直接支持它的来源与必要的时效/适用边界。
- 方案筛选：推荐及条件；主要候选的保留/淘汰/待确认理由；关键来源；实际验证与缺口。并列比较确实有帮助时用表格，不重复展开所有过程。
- 用户要求改进流程并验证时，先冻结任务、输入版本和评价标准，用真实任务观察行为；需要前后对照时让独立执行者使用同题同条件，不给预期答案。单例与形式校验不能证明普遍性能提升，结果相同或变差也须如实报告。

## 约束

- 需要最新信息时必须联网核验。
- 不要给无链接的强结论。
- 来源的权威性按具体主张判断；单一来源不足以支持的强结论须补证或降为有条件判断。
- 引用材料时避免长段复制，优先摘要。
- 对过时、低可信或无法验证的信息标注风险。
