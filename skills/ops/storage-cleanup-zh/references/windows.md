# Windows 盘点、清理与卸载

主流程　确认范围 → **扫描和分类** → **按授权清理或卸载** → 复测。先确定要释放的盘符，再确认实际占用来自哪种对象。

## 1. 量占用与归属

- 查看目标卷空闲和总容量。PowerShell 可用 `Get-Volume -DriveLetter C`，其中 `SizeRemaining` 是可用字节。分层查用户目录和隐藏项、`AppData`、软件安装目录、`ProgramData`、系统对象和虚拟磁盘，记录只读扫描的拒绝访问项。
- 文件大小合计适合排序。有条件时查文件分配大小和硬链接身份。同一卷上多个硬链接仍引用同一份数据，只有最后一个链接移除后才可能释放数据块。避免让同一份空间同时计入应用、缓存和父目录。没有可靠清理量时写「需复测」。
- 用文件类型、路径、产品元数据、最近写入与当前消费者交叉确认用途。随机名、旧日期、`Temp` 或 `Cache` 字样只能定位候选。只看元数据即可判定时，避免读会话、账号、报告或私人文件的内容。
- AI 分开查模型库、推理运行时、桌面安装和项目数据。先查模型或缓存配置指向的位置，再确认轨迹、大小和占用卷。虚拟机、Docker 或 WSL 查实际注册的数据路径和镜像所在盘，避免把活跃盘和旧目录混为一项。遇到未知镜像、发行版、容器卷或自训练权重，补证据后再分类。

## 2. 清理已证实的纯垃圾或用户选中的项目

- 首批优先考虑已确认无留存用途的诊断日志与 `.etl`、不再用于排障的 `.dmp`、已完成更新的安装暂存及已结束的测试浏览器配置。复核进程与维护状态。例：从 `feedback.exe` 确认所有者之后，还需核实目录确属已结束的安装暂存，且没有需要留存的成员。存在运行依赖、恢复价值或用途未知时，提交审阅。
- Windows Update、传递优化等系统清理用 Windows「设置 → 系统 → 存储 → 临时文件」或官方维护工具。按明确范围核对界面选项，下载、回收站、更新回退文件等单列。`WinSxS`、`Windows\Installer`、驱动仓库、应用正式包缓存和受管理系统目录走各自维护入口。分页和休眠由 Windows 配置管理，先报告用途和代价，由用户明确选择是否调整。
- 缓存优先用软件支持的命令或界面。`uv cache prune` 可移除一部分暂时不需的缓存，`uv cache clean` 清理范围更广。先核对运行的 `uv`、`uvx` 和依赖它们的工作流，处理重建所需网络及离线场景。类似地，区分当前 Codex 运行时、历史安装暂存、回退目录、会话库和项目临时成果。
- 处理本地文件前用冻结清单中的精确路径。核对解析后的绝对路径和卷，检查祖先目录、对象型态和重解析点。整个清理目录须查完整子树，排除链接、未知对象、运行中或已变化的成员。按路径精确执行，遇占用、权限不足或策略拒绝记录并跳过。发生部分清理时，复测并重新验证剩余对象。

## 3. 用产品自带的卸载入口

- 通过「已安装的应用」、应用管理器或系统登记的卸载器识别产品和安装路径，核对精确名称、版本、安装范围和同品牌产品。例：夸克浏览器与网盘是两项，Office 套件和独立 OneNote 可共享安装位置，桌面 AI 客户端与 CLI、模型库、历史数据各有用途。卸载前核对原生入口会移除的产品或组件，确认共享依赖和独立产品可保留；影响范围不明时暂停该项，包括管理员确认。按明确范围选择整套或组件，例如 Unity Hub 的 WebGL 模块或 Visual Studio Installer 的工作负载。
- 卸载前确认相关工作流、未保存内容和子进程能安全收口，再正常关闭客户端。退出桌面应用可能中断关联 CLI 或后台任务，影响不清楚时保留该项，继续其余已授权项。默认保留资料、书签、账号和工作区数据。使用登记的静默参数或可核对的界面控件，避开清除个人数据、重启、提交问卷或删除独立产品等超范围选项。已有卸载流程悬停时，先核对当前状态再续办，避免重复启动。
- 卸载器退出后，复查注册项和产品专属程序或组件；涉及共用位置时核对需要保留的产品仍可用，文件夹是否存在只能辅助判断。管理员确认窗口、待重启、旧安装残留和已卸载分别记录。残留目录按类型重新评估，原卸载授权只覆盖产品管理器处理的范围。

## 4. 交付证据

对每项写清「处理结果、核对证据、待处理原因」。重新测同一卷剩余空间，用前后差值报告全卷净变化。只有各组独立测量且能排除并发写入时，才把净变化归因给某组。记录前后采样时间。
