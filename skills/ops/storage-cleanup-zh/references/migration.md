# 换盘、迁服务器与恢复

主流程　确认范围 → 只读盘点 → **验证迁移候选** → **复制与验证** → **按授权切换和复测**。判断依据是用户现在怎样用它、以后怎样打开或运行，以及这一步能释放哪个卷。

## 1. 判断可迁范围

| 对象 | 优先处理 | 判断依据 |
| --- | --- | --- |
| 可重建模型、素材缓存、生成物 | 按用途清理、让工具在目标新建，或只迁需要保留的文件 | 核版本、配置、生成成本、网络和本机离线调用。保留自训练权重、唯一素材和支撑结果的证据。 |
| 训练、批量推理、视频生成、基准或大数据计算 | 让服务器承担重任务，本机保留需要的编辑和查看入口 | 核操作系统、架构、CPU/GPU、显存、磁盘、运行时、许可和结果回传。源盘本来没有对应副本时，收益记在计算，源盘释放量记零。 |
| 需本机接口、Windows 图形工具或离线使用的项目 | 优先评估换到本机有空间的盘、官方重装或迁数据组件 | 核绝对路径、虚拟环境、工具链、插件和断网场景。远程桌面、网络挂载和云端按需文件会引入网络依赖。 |
| 公开可复现的归档副本 | 核具体版本、来源、文件完整性、本机引用及离线需求，再保留合适位置 | Git 忽略、名字像旧版或远端能看到同名目录只是线索。保留唯一归档和独立恢复副本。 |
| 私有、敏感或受管数据 | 先确定数据和目标的授权、访问与恢复条件 | 凭据、学生数据、第三方录屏、应用会话、正式证据、恢复库及云同步根都有独立用途和边界，按各自留存规则处理。 |

Git 项目核工作树、暂存、未跟踪资料、提交与分支、远端和大文件内容。看见远端同名仓库或本地跟踪引用不足以证明全部内容可恢复。涉及普通资料的权威位置和版本，用项目原有规则确认当前入口、独立备份及证据。

## 2. 只读验证目的地及影响

1. 用已配置的连接读取实际主机或卷、目标路径权限、配额、可用空间、必要工具及软硬件依赖。只读阶段用权限元数据核准范围。远端有副本时核提交、清单或内容校验，逐一解释差异。登录成功只是连接证据。
2. 把用途拆成本机与目标两端。说明迁后本机启动入口、编辑和离线访问情况，目标如何运行，结果如何回来。能满足全部已知用途才进入「保留本机用法」。仅能换到远程用法的候选，写出受影响用途。
3. 确认数据可传输及目标路径获准，核写入权限、命名碰撞、保留期限和恢复路径。云盘处理遵循该账户和服务的授权边界。WPS 云盘根目录的整体迁移须另获明确授权，并说明同步影响和恢复办法。

## 3. 先复制，验过再切换

1. 生成源→目标清单，包含相对路径、大小、必要的哈希、保留的本机部分和恢复入口。确认正式目标为空或内容一致。发现同名异内容时保留双方并暂停该项，改路径或覆盖另核授权。分段复制时在获准范围内使用独立暂存位置；断线后只续传能用清单和已有内容验证归属的暂存，保留源。
2. 在目的地核对文件数、关键内容或哈希，并实际回读。暂存校验通过后，以目标平台支持的排他创建或无覆盖方式提交到正式位置，再核对最终路径。仅授权复制时以正式目标回读通过、源仍在为完成证据，释放量记零。
3. 迁计算时测试远端运行和结果回传。要求本机无影响时，用原入口实测代表性启动、编辑或读取，按实际用途验证离线和恢复路径。若断网会中断当前连接，用隔离方式复测或保留该项待验证。虚拟机和容器的活跃磁盘用平台支持的迁移、导出或导入入口。
4. 所需验证通过后，仅在切换及释放源的授权范围内操作。确认本机所需入口可用、目标可取回，再复测源卷空闲。失败时用保留的源恢复入口，或按清单从已验副本恢复。

**只释放本地云副本。** 先核实绑定账号、同步、云端回读及离线需求，再使用服务原生的「释放空间」或同等入口。同步目录里的普通删除可能传到其他端。以文件状态与本地卷变化验收。 [OneDrive 按需文件](https://support.microsoft.com/en-gb/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows)

**典型结论。** 如果本地 Ollama 没有大模型、WSL 镜像已在其他盘、4090D 上有项目但未核到同版，那么应优先清本卷已核实的残留，服务器只列计算卸载或待验证归档，源盘可回收量暂不计。
