# 清存储

用户只需指定磁盘、要腾出的空间或要处理的项目。示例 `使用 $storage-cleanup-zh 盘点 C 盘，把可清理、可卸载、可迁往 4090D 的项目按顺序列出。`

**主流程**　确认范围 → 只读盘点 → 分级 → 清理纯垃圾／提交其余项目供审阅 → 执行获准项 → 复测。

## 1. 确认范围

- 「盘点」「列出」「设计方案」进入只读模式。用户要求清理时，授权范围内已证实的纯垃圾可自行清理，无需逐项询问。用户明确限定「只做这些」时，仅处理指定对象。
- 有可能有用的文件、文件夹或软件带上第 3 节的审阅信息，等用户选定动作和项目后才处理。已有明确选择或标注时复用，不重复确认。只选桌面客户端时，范围是应用本体，浏览资料、账号、会话、CLI、工作目录和云盘是独立对象。
- 按动作保存授权范围。迁移时分别核对目标位置、传输范围和切换或释放源副本的授权。可用现有授权直接执行适用步骤。影响用途、需要扩大范围或出现全新不可逆操作时，保留该项并说明需要的决定。

## 2. 只读盘点

- 先量目标卷的可用空间并记录时间。盘接近满时先查少数大户和明确的临时文件，尽快给用户一批高置信候选。再按实际卷、目录和大文件下钻，识别目录的所有者、类型、活跃进程和恢复用途。
- 跳过跨卷联接、符号链接和不明重解析点，发现后只记录其实际目标。对云占位文件只看元数据，避免触发下载。标明拒绝访问、扫描范围和测量口径。分页文件、磁盘可用空间与内存占用分别判断。
- 报表分开显示文件大小合计、可获得的磁盘实占和预计可回收量。父目录和子项不重复相加。硬链接、稀疏文件、压缩和云占位会影响占用，另一个卷上的大文件不计入本卷收益。

## 3. 按顺序给三张清单

| 顺序 | 列入条件 | 用户需要看到 |
| --- | --- | --- |
| 1. 确认是纯垃圾 | 已核实归属和内容，相关任务已结束，清理不会损失数据、恢复能力或本机使用能力 | 路径、占用、判定依据。执行后报清理结果和释放情况 |
| 2. 可选删除、卸载或释放 | 可能仍有用途，或涉及软件、组件、运行时、模型、工作数据、受管理本地副本以及用途不明的对象 | 提交项目审阅，说明推荐动作及依据 |
| 3. 可迁移且保留本机用法 | 已核实源确实占用待释放的本机卷，目的地可用，本机使用和恢复条件有证据支持 | 提交项目审阅，附源与目标、保留部分、验证和回滚方法、可释放的卷 |

纯垃圾可包括已经结束的安装或测试暂存、已确认无需留作排障的日志等。旧日期、随机名、`Temp`/`Cache` 名称和可重新下载只提供线索。用途未确认、可能需要离线重建、排障或回退时，提交审阅。

### 每个待审阅项目固定给出七项

| 字段 | 填写要求 |
| --- | --- |
| 项目名 | 写可辨认的真实项目、软件、组件或目录用途。可独立处置的产品分别列出。 |
| 项目位置 | 写完整本机路径和盘符。已知联接、云端或实际卷时标明，迁移意向另写明确目的地。 |
| 项目占用 | 写实测大小和口径。已核实实际占盘或可回收量时分别列出，父目录和子项避免重复。 |
| 项目有什么用 | 说明它服务的功能、工作流或数据角色，以及用到它的程序或项目。 |
| 最近是否有使用 | 给出正在使用、最近一次有证据的使用日期或「未核实」，并写明证据。以进程、任务运行或应用记录等判断。仅有修改时间或没看到进程时，如实写证据局限。 |
| 卸载或删除以后有什么影响 | 明确会失去哪项功能、依赖、数据、离线能力或恢复入口，以及恢复方式。有多种动作时分别说明。 |
| 迁移对项目运行本身有什么影响 | 说明迁往拟议位置后能否用原入口启动、编辑、构建或运行，是否需改路径、重建环境或依赖网络。明确当前可验证的影响和仍待核实的条件。 |

字段缺证据时填「未核实」和具体缺口。某种动作确实不适用时说明原因，仍保留该字段。用户可按项目名选择具体动作，审阅期间保留原对象。迁移条件只差部分证据时列「条件候选」，允许确认可无影响迁移的清单为空。系统文件、应用数据、备份、正式证据及活跃环境的保护理由放在对应项旁。

## 4. 执行并复测

- Windows 盘点、清理和卸载读 [Windows 操作](references/windows.md)。本机换盘、服务器迁移和云盘释放读 [迁移与恢复](references/migration.md)。只有只读请求时，给出盘点和建议即交付。
- 执行前复算目标路径、卷和成员，核对当前使用情况。发现对象变化或新的用途证据时重新分类，再按用户选中的范围和已经证实的纯垃圾清单分组处理。任务受阻时记录工具错误和未处理对象，继续独立且已授权的项。遇入口缺失或普通故障，可用另一个受支持的入口。工具策略拒绝某动作时停止该动作，避免通过其他命令、API 或界面绕过拒绝。管理员确认只由有权限的用户完成。
- 支持同次复试时检查状态后只续做未完成项。每批记录目标卷前后空闲、文件和软件实际状态、保留的数据以及失败或跳过的项。全盘净变化可受后台活动影响。迁移还须给出目标回读和本机代表性用法的结果。以真实前后状态收口，退出码、快捷方式或命令启动只能作辅助证据。
- 需要暂存或日志时遵守本机既有存储配置，提前查可用空间和实际写入卷。将可能增长的扫描清单、下载、解包和日志放在允许的卷，避免占用待清卷。对反复增长的项目，先定位写入者，再按授权用应用自带设置改存放位置，复查原卷和目标行为。
