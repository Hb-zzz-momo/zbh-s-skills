# 清存储

用户只需指定磁盘、要腾出的空间或要处理的项目。示例 `使用 $storage-cleanup-zh 盘点 C 盘，把可清理、可卸载、可迁往 4090D 的项目按顺序列出。`

**主流程**　确认范围 → 只读盘点 → 三类建议 → 执行已授权项 → 按结果复测。

## 1. 确认范围

- 「盘点」「列出」「设计方案」进入只读模式。明确要求执行某些条目或通过标注选中时，复用该授权和排除条件，无需再次确认。只选桌面客户端时，范围是应用本体，浏览资料、账号、会话、CLI、工作目录和云盘是独立对象。
- 按动作保存授权范围。迁移时分别核对目标位置、传输范围和切换或释放源副本的授权。可用现有授权直接执行适用步骤。影响用途、需要扩大范围或出现全新不可逆操作时，保留该项并说明需要的决定。

## 2. 只读盘点

- 先量目标卷的可用空间并记录时间。盘接近满时先查少数大户和明确的临时文件，尽快给用户一批高置信候选。再按实际卷、目录和大文件下钻，识别目录的所有者、类型、活跃进程和恢复用途。
- 跳过跨卷联接、符号链接和不明重解析点，发现后只记录其实际目标。对云占位文件只看元数据，避免触发下载。标明拒绝访问、扫描范围和测量口径。分页文件、磁盘可用空间与内存占用分别判断。
- 报表分开显示文件大小合计、可获得的磁盘实占和预计可回收量。父目录和子项不重复相加。硬链接、稀疏文件、压缩和云占位会影响占用，另一个卷上的大文件不计入本卷收益。

## 3. 按顺序给三张清单

| 顺序 | 列入条件 | 用户需要看到 |
| --- | --- | --- |
| 1. 可优先清理 | 已识别的旧日志、崩溃转储、旧暂存或已验证可重建缓存，具备对应停用条件 | 路径、体量、用途、何时可清、清后影响 |
| 2. 可选卸载或释放 | 软件、组件、运行时、模型、依赖或受管理的本地副本，清理会改变某项能力或需要重建 | 软件或数据的精确身份、收益、会失去什么、官方入口或恢复方式 |
| 3. 可迁移且保留本机用法 | 已核实源确实占用待释放的本机卷，目的地可用，本机使用和恢复条件有证据支持 | 源与目标、留在本机的部分、验证和回滚方法、实际能释放哪个卷 |

迁移条件只差部分证据时列「条件候选」，说明缺口。允许确认可无影响迁移的清单为空。盘点的技术结论与执行授权是两个步骤，实际传输沿用第 1 节的授权范围。涉及系统文件、应用数据、备份、正式证据或活跃环境时，把保护理由放到有关条目旁。

## 4. 执行并复测

- Windows 盘点、清理和卸载读 [Windows 操作](references/windows.md)。本机换盘、服务器迁移和云盘释放读 [迁移与恢复](references/migration.md)。只有只读请求时，给出盘点和建议即交付。
- 执行前复算目标路径、卷和成员，核对当前使用情况。确认用户选中范围未变后按组处理。任务受阻时记录工具错误和未处理对象，继续独立且已授权的项。遇入口缺失或普通故障，可用另一个受支持的入口。工具策略拒绝某动作时停止该动作，避免通过其他命令、API 或界面绕过拒绝。管理员确认只由有权限的用户完成。
- 支持同次复试时检查状态后只续做未完成项。每批记录目标卷前后空闲、文件和软件实际状态、保留的数据以及失败或跳过的项。全盘净变化可受后台活动影响。迁移还须给出目标回读和本机代表性用法的结果。以真实前后状态收口，退出码、快捷方式或命令启动只能作辅助证据。
- 需要暂存或日志时遵守本机既有存储配置，提前查可用空间和实际写入卷。将可能增长的扫描清单、下载、解包和日志放在允许的卷，避免占用待清卷。对反复增长的项目，先定位写入者，再按授权用应用自带设置改存放位置，复查原卷和目标行为。
