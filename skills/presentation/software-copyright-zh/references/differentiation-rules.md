# 材料差异化规则

差异化来自真实项目证据，不来自随机改词、换标题或套用另一套模板。

## 操作手册

- 先根据业务理解中的页面、流程、对象和用户动作设计章节，不固定复制旧项目骨架。
- 每章围绕一个真实页面或核心流程，写明当前软件特有的入口、控件、状态、限制、异常和反馈。
- 相邻模块不得只替换名称；若证据无法说明差异，应合并模块或补读源码。
- 删除不能映射到 `source-evidence-map.json` 的空泛价值、通用优势和行业套话。
- 通过段落相似度和人工复核发现高度重复段落；重复时回到证据而不是做同义改写。

## 代码材料

- 优先选择能共同证明核心业务闭环的入口、路由、页面、服务、数据模型和算法。
- 不用框架样板、通用 CRUD、配置、依赖、生成文件或静态资源制造差异。
- 每个代码文件关联具体功能证据和选择理由；同一代码不得重复凑页。
- 不为追求“看起来独特”修改真实源码或打乱连续语义。

## 截图与字段

- 截图覆盖当前软件真实导航、页面状态和核心操作，不复制样例图布局。
- 行业、用途、主要功能和技术特点来自已确认业务理解，不沿用上一次申请材料。
- 差异化检查不能替代名称、版本、来源、页数和官方字段核验。
