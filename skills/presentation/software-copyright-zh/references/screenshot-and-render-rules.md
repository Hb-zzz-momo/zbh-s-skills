# 截图与 DOCX 渲染规则

## 截图方式门禁

用户必须选择一种方式并写入状态文件：

- `browser`：真实浏览器自动截图；先验证浏览器工具、服务和测试数据。
- `desktop`：真实桌面软件自动操作截图；先验证桌面控制能力。
- `user`：用户自行截图；按计划核对文件和页面。
- `skip`：只允许草稿或未完成材料，最终状态为 `BLOCK`。

## 截图清单

每张截图单独一行记录：截图文件、对应页面、访问路径、前置数据、操作动作、证明的功能、采集方式、采集时间、证据 ID、敏感信息和 SHA-256。采集时间必须为 ISO-8601，哈希必须匹配当前字节；图片至少 320×200。截图必须来自真实运行软件，不得使用 AI 生成图、设计稿、手工伪造状态或隐瞒数据修改。

截图中出现账号、手机号、证件号、密钥、内部地址或真实业务数据时先脱敏；脱敏动作和范围写入清单，不得改变所证明的功能。

每张确认截图的当前字节必须通过 DOCX 关系实际嵌入正式操作手册；只把图片放在目录、写文件名或放入孤立 media 项均不算闭环。

## 渲染检查

正式 DOCX 生成后优先转换为 PDF 或逐页图片，检查：

- 页眉页脚、页码与分页。
- 代码是否截断、重复或越出页面。
- 字体、颜色、乱码、蓝色超链接和模板残留。
- 空白页、标题孤行、页数和占位文字。
- 图片清晰度、裁切、拉伸和图文对应。
- 软件名称、版本和代码页眉是否与申请字段一致。

`render-report.md` 至少记录逐项结果、问题页和修复复验，并包含以下机器可读头：

```text
status: PASS
visual_validation: completed
repair_rounds: 1
```

每个正式 DOCX 必须至少有一条单行 `render_record`，冒号后是合法 JSON 对象：

```text
render_record: {"input":"03-正式资料/软件全称_操作手册.docx","input_sha256":"当前DOCX的64位SHA-256","artifact":"04-校验报告/rendered/软件全称_操作手册.pdf","page_count":12,"renderer":"LibreOffice 25.2","command":"soffice --headless --convert-to pdf ...","rendered_at":"2026-07-12T20:30:00+08:00"}
```

字段契约：

- `input`：相对材料根的正式 DOCX 路径，且必须对应 `03-正式资料/` 中实际存在的操作手册或代码鉴别材料。
- `input_sha256`：该 DOCX 当前文件内容的 SHA-256；修改 DOCX 后必须重新渲染并更新记录。
- `artifact`：相对材料根的唯一渲染产物路径，不得被另一条记录复用。当前校验器接受结构有效的 PDF、PNG 或 JPEG；多页 DOCX 优先用一个唯一 PDF，单页逐页图可记录为 PNG/JPEG。
- `page_count`：正整数，必须等于校验器从 PDF 解析出的实际页数；PNG/JPEG 单个文件按 1 页计算。
- `renderer`、`command`：非空渲染器名称/版本和可复现命令，不得只写“已渲染”。
- `rendered_at`：可由 ISO-8601 解析的时间，建议含时区。

每个正式 DOCX 都必须被当前哈希的记录覆盖，渲染产物必须位于材料根内、非空、文件签名和内部结构有效；不同记录的 `artifact` 必须唯一。`repair_rounds` 至少为 `1`，表示发现问题后已完成至少一轮修复并重新渲染复验。只打开 DOCX、只写一行 `PASS`、只列文件路径或只检查存在不等于视觉验收。

环境不支持渲染时写明：

```text
状态：未完成 DOCX 视觉校验
```

此时最终状态最高为 `CAUTION`；若用户要求可直接提交，则必须为 `BLOCK`，不得声称材料已完全验收。
