# 源码鉴别材料规则

## 真实性

所有代码必须来自已确认项目根内的真实源文件。禁止 AI 新生成代码充当申请代码、修改后冒充原项目、重复代码凑页、越界读取、删除关键逻辑或截取不存在的行段。

每个 manifest 条目至少包含：

```json
{
  "path": "",
  "language": "",
  "line_count": 0,
  "sha256": "",
  "category": "",
  "is_third_party": false,
  "selection_reason": ""
}
```

正式材料生成前后复算源文件 SHA-256。源文件变化时使代码选择和后续阶段失效，不得把旧材料标为已验证。

## 候选优先顺序

按真实技术栈调整，通常从应用入口、路由、核心页面、核心组件、接口封装、状态管理、核心业务服务、数据处理、数据模型、核心算法中选择。排序只是候选建议，不能替代模型阅读和用户确认。

候选清单必须记录路径、行数、模块职责、对应功能、第三方状态、推荐状态、理由和预计页数贡献。

## 默认排除

`node_modules/`、`.venv/`、`venv/`、`dist/`、`build/`、`coverage/`、`vendor/`、第三方 SDK、锁文件、纯静态资源、二进制、自动生成文件、压缩/映射文件、测试快照、密钥、环境变量、真实账号密码和个人隐私。

配置文件、构建脚本和测试代码可作为项目证据，但不能作为主要代码鉴别材料，除非它们本身体现申请软件的核心功能且用户明确确认。

## 五种量必须分开

1. 项目全部源程序量。
2. 候选源代码行数。
3. 用户确认入选的源代码行数。
4. Word 排版后的实际页数。
5. 当前官方鉴别材料页数要求。

不得把“核心代码必须少于 3000 行”作为通用规则。不得用项目总行数直接推断 Word 页数。

当前已核验法规一般规则为：源程序前后各连续 30 页，不足 60 页提交全部；除特定情况外程序每页不少于 50 行。例外交存必须单独核对《计算机软件著作权登记办法》第十二条并由用户确认，不能由脚本自动选择。

## 人工确认与抽取边界

- 先运行 `collect_source_manifest.py` 和 `propose_code_selection.py`。
- 用户确认 `代码文件选择.json` 中的路径和可选行段；顶层记录 `confirmed_at`，每个入选项必须有 `user_confirmed=true`、manifest SHA-256 和所选连续字节的 `selected_content_sha256`。重建 manifest、源码哈希变化或确认哈希冲突会使旧选择失效。
- 用户确认后至少必须有一个 `selected=true` 的真实源码文件或连续行段；零选择直接 `BLOCK`，不得生成空白或仅模板化的代码鉴别材料。
- 路径解析后必须仍位于项目根，起止行必须存在且连续。
- `is_third_party=true` 的文件一律阻断。
- 正式材料完成后验证路径、行段、哈希、重复片段和敏感信息；代码 DOCX 必须包含每个用户确认行段的全部非空源码行，缺行、改写或用其他内容替代均为 `BLOCK`。
