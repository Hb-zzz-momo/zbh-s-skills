# 质量门禁

## 统一状态

- `PASS`：要求、实现、验证和证据全部闭环。
- `CAUTION`：存在非阻断风险，只允许降级表述或补验证。
- `BLOCK`：任一必选事实、确认、来源、测试或复现证据缺失；停止正式交付。

## 阶段门禁

| Gate | 必须检查 | `BLOCK` 示例 |
| --- | --- | --- |
| 项目 | 唯一根目录、可运行入口、核心闭环、权属/许可证 | 多候选未选、空壳、第三方占比不明 |
| 既有材料审计 | 原件逐字节备份、源/备份 SHA-256、只读属性、不可变基线；修复有授权 ledger、前后哈希和复验 | 未授权改动、ledger 哈希不一致、占位或不可读 DOCX |
| 准备度 | 实际启动、核心流程、测试日志及项目内证据文件；双份 readiness 报告 | 只有端口/口头说明、缺核心流程、正式生成仍被授权 |
| 业务 | 定位、行业、用户、功能、流程、排除功能；每个 confirmed 功能闭合到 manifest 内且用户入选的源码、真实截图和正式材料 | 模型只凭关键词生成业务结论；功能证据未闭环 |
| 字段 | 必填、来源、日期、枚举、用户确认、敏感信息 | 猜测权利人、日期或证件号 |
| 代码 | manifest、SHA-256、候选、第三方、行段和确认；至少一项真实源码入选；代码 DOCX 包含每个确认行段的全部非空行 | 零选择、依赖/生成文件入选、哈希变化、确认行段未完整进入 DOCX |
| 截图 | 真实运行、逐图 11 列元数据、SHA-256、合理尺寸、脱敏及正式手册嵌图 | AI 图、1×1 占位图、弱元数据、未嵌图、跳过却标为完整 |
| 草稿 | 功能证据、完整 manual_modules、名称/版本、结构化人工自检、无虚构、一次整体确认 | unsupported 功能、空手册模块、浅内容或占位未登记 |
| 正式生成 | 用户授权、私有路径、无占位 | 未确认便生成 DOCX/TXT |
| 渲染 | PDF/逐页图、页数、截断、乱码、图像和修复复验 | 仅文件存在或无法渲染却声称 PASS |
| 最终 | consistency/provenance/render/checklist/output manifest | 任一报告缺失或仍有 error |

## 自动校验最小集合

1. 软件全称在申请字段、文件名、手册、代码页眉和截图标题中一致。
2. 版本在申请字段、手册、代码页眉和文件名中一致。
3. 每个 confirmed 功能都必须同时闭合到 source manifest 内且已入选的源码、真实存在的截图和正式材料；任何一端缺失均为 `BLOCK`。
4. 正式代码来自至少一项用户确认的真实文件/行段，SHA-256 一致，无第三方、重复、密钥或隐私；零选择直接 `BLOCK`，代码 DOCX 必须包含每个确认行段的全部非空行。
5. 必填字段、日期、枚举、源程序量和发表逻辑合法。
6. 正式材料没有占位词、模板残留或敏感信息。
7. 每个 DOCX 都有真实 PDF/逐页图片渲染产物，且完成至少一轮问题修复复验；无法渲染时降级。
