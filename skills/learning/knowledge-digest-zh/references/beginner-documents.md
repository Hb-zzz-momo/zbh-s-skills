# 知识沉淀文档：先看全链路，逐模块解释与交接

适用：面向用户阅读的知识库文章、经验笔记、SOP、教程、复盘与交接说明。生成或修订前读取；领域主Skill继续负责事实、执行和验收。不把这套阅读版式塞进原始日志、机器契约或教师/机构固定提交模板；其配套阅读说明仍适用。已有文档按本次变化维护，不自动批量改写历史库。

## 先确定读者要做什么

按读者当前任务组织同一篇文档：先交代目标、必要前提和成功画面，再给任务全貌与首次配置/完整步骤；熟悉后的最短操作可另设入口，仍复用同一事实与配置。按需放字段参考、解释、故障与恢复。教程帮助第一次做成，SOP帮助再次办成，参考用于查字段，解释帮助理解原因。它们是阅读职责，不要求新建四套文件夹或复制四份正文。复用真实主题、现有入口和版本角色。

## 多环节文档：完整主链贯穿首尾和各模块

用于多步骤、多环节的学习手册、操作指南，以及确有流程的经验/SOP/交接说明；不把短问答、单个表达式、独立数据字典、纯比较或原始记录强排成流程。没有线性流程时用真实的关系或并行条件说明，不编造上下游。正式课程/论文模板和机构指定结构优先，必要时另给配套阅读说明。

1. **先展示全部主要环节。** 开头先说要完成什么、怎样知道完成，再给覆盖到最终结果的完整主链。不是只画起点终点，也不是等读完才补全图；完整指主要职责与交接齐全，不是一次塞入全部底层组件和缩写。
2. **每个实质模块保留全图与定位。** 章节或独立任务模块沿用同一主链和编号，以文字/加粗标出当前位置及本环贡献，不只靠颜色。说明接住什么条件、为什么还要这一环、怎样处理、交出什么，以及哪个后续环节使用它。原子命令和每个小标题不必各复制一张图；地图不能替代正文衔接。
3. **按真实关系连接。** 箭头注明输入输出、依赖或实际传递，区分控制信息和业务数据、准备条件和执行动作、依赖图和真实时序。并行前提说明共同服务的目标，互斥方案画为分支；复用已有链路时标明复用哪部分、本节请求的功能与结果，不能沿用不适用的原终点。
4. **沿同一案例展开并返回全局。** 对象名、示例值与位置保持稳定。每节从上一状态/前提进入，指出尚缺条件，在局部解释后明确“本节解决什么、后续还缺什么”；概念归入它服务的环节，替代路线和额外知识按需展开，不顺手发展成脱离主任务的词条清单。
5. **结尾完整回看。** 用同一例子重走主链，把各环交付与最终验证对应起来。学习主线、实际操作和应用复用互相指向，不能让图、正文和验收对当前任务承诺不同结果。

完整主链和各模块的重复地图均可按阅读器能力收纳；首图默认展开，模块框标题直接写当前位置与贡献，结尾保留完整回看。重复地图收起后，本节最低因果、上下游条件、动作、成功信号与限制仍须可见；不支持折叠时用可导航的图文块，不假装可点击。

## 术语、字段与前置条件在需要之前交代

- 图示、命令、字段表和说明首次使用必要术语时，就近先说“本任务里它是什么、负责什么”，再给准确名称；首图也遵守。不能先抛一串缩写，再让读者后翻找解释。两个同名或相似对象要说明位置、职责或层次差异。
- 学习手册先给目标和任务全貌，字段/参数在首次使用点解释；独立表格或指标分析先说明分析目标，再解释影响判断的字段、单位与取值后计算。用户指定的数据字典可直接按字段组织，不把任何一种顺序强加给所有文档。
- 操作依赖的服务、账户、权限、环境与输入先准备或确认，再测试和使用；必要条件不能只在失败处理里首次出现。每次成功只证明相应层次，安装、登记、路径、服务、账户和应用结果分别判断。

## 每一步、每一模块的写法

每个有实质内容的步骤/模块都附对应小白解析，包括正常步骤；不能只在全文开头放总比喻、只解释错误，或把全部术语堆到最后。

| 直接看见 | 具体写什么 |
| --- | --- |
| 这步干什么 | 一句话目标；在哪台机器/应用/目录做 |
| 位于哪里、接什么 | 对应完整主链中的位置；上游结果或独立前提是什么，本环为什么必需 |
| 怎么做 | 一条主路线：点击入口、准确文件与修改位置，或必要短命令；标出需替换的参数 |
| 怎么知道完成 | 预期界面、输出/状态或可检查结果；别把预期写成实测 |
| 交给谁、还缺什么 | 本环产出怎样供后续使用；不能用本环成功代替全程完成 |
| 必要条件与后果 | 影响范围、保存/重启、已知风险、必要失败出口；不能藏在折叠里 |
| 一句话小白理解 | 先用日常话说清本步作用，细讲可展开 |

详细解析就近附在该步下面，可用一个折叠块：说清“它是什么 → 为什么要做 → 贴近任务的例子 → 对应实际对象 → 常见误解/边界”。对没有操作的概念模块，用“概念 → 场景 → 关系/判断”替代命令栏。解释深度以读者能判断下一步为准，不设压缩详解的硬行数，也不为凑模板编故事。

类比沿同一任务使用同一场景，明确本机/远端、输入/输出、前后关系。例子解释机制，不证明根因；未知项仍写可能及区分方法。详细解释保留在正文或就近链接的唯一解释块，不用“需要再问我”替代。

## 简化的是操作成本

有等效路线时，先比较真实入口、持久性、作用账户/范围、权限、版本、依赖、重启需要和结果验证，再比较操作数。

- 优先使用已安装应用的可点击设置、可直接打开的配置文件或已有快捷入口；说明“打开哪里 → 改哪个块/字段 → 保存 → 是否重启”。本地文件可以给真实绝对链接；远端文件须写“VS Code远程文件树/远程打开文件”及远端路径，不伪造本地可点击链接。
- 短CLI更直接或GUI无法表达相同配置时，选短CLI；主线只教一个推荐方式，其他方式放可选分支。不要把GUI/CLI优劣定成绝对规则。
- 已有持久配置必须保留持久效果，不能用每次临时export/-m替代。新设置应合并，不用整文件覆盖其他Host/字段。必需状态验证、备份和安全限制不能为少一步被删掉。
- 先使用现有文件和原生功能，不为缩短展示而额外制造一键脚本、安装新工具或隐藏状态变化。长脚本确实必要时，解释用途、输入、会改什么、成功信号与恢复；不把自动化内部诊断全部变成用户操作。
- 命令尽量单用途、可复制，分清PowerShell/Bash/其他终端；不带提示符、不让秘密进入示例。不要把许多复杂操作用分号或一行脚本伪装成“短命令”。

## 表格和命令说明

字段、配置或多对象关系适合用短表格，列“名称/当前或示例值/白话含义/在哪里生效”。命令就近说明“命令或参数片段/意思/为什么要它/能否改”。解释每个影响行为的参数及占位符，不逐字讲引号、空格等无关语法。普通叙述不硬做成表格；避免横向塞满宽表。

读者无需在参数表里寻找必做动作；动作仍在主线。重复概念可链接首次完整解释，但每个后续模块仍有一句本步理解，不能只留“见前文”。

## 折叠与阅读器兼容

Markdown阅读器支持时，长解释使用标准details/summary，标题说清展开能知道什么，例如“小白解析：为什么两个127.0.0.1不一样”。保留空行和围栏；避免多层折叠。不把标题、前提、主操作、成功信号、风险或必选分支放进默认收起区域。

读者理解本步必需的关键解释保持可见；折叠除更详细的版本，也可承载已有主链的重复定位图，但不能把必要衔接只藏在图里。是否折叠由目标阅读器实际能力决定，不因用户允许收纳就强制隐藏。阅读器不支持时改为本步下“小白解析”子标题；Word/PDF用同页解释框或可导航附录，不显示失效HTML或丢弃解释。未经目标阅读器验证，不声称已验证折叠/手机版或PDF呈现。

Typora的HTML块不能有空行，块内不会解析Markdown。需要在Typora收纳表格/段落时，将整个details块内部转成完整HTML（p/table等），去掉标签间空白行；不要只用HTML起止标签包Markdown表格。代码与流程图的pre内容必须保留换行，单行HTML可用 `&#10;` 等合适编码，不能删除换行再声称图示保留。生成后实际展开/收起并检查表格、代码与多行图；维护源稿可保留Markdown形式在制作记录中，不增加第二份当前正文。此差异依据[Typora HTML支持说明](https://support.typora.io/HTML/)，其他阅读器仍按自身能力选择。

示例（操作与关键限制在折叠外）：

~~~markdown
### 第2步：保存普通登录入口

位置：本机VS Code，打开已确认的SSH配置文件，合并指定Host块后保存。
成功信号：连接列表出现该别名；仍需实际登录验证。不要覆盖其他Host。
小白理解：这是给服务器起一个便于找到的通讯录名字，保存通讯录还不等于电话接通。

<details>
<summary>小白解析：别名和真实地址各负责什么</summary>

Host是通讯录名字，HostName是真正拨打的地址；User决定用哪个账户敲门。同一机器可有不同用途别名。配置里没有自动启动SSH的功能。

| 项目 | 白话说明 | 改动边界 |
| --- | --- | --- |
| Host | 以后选择的名字 | 与教程后续命令一致 |
| HostName | 实际服务器地址 | 使用自己的可信地址 |

</details>
~~~

## 研究与采用

设计或显著调整知识库/SOP的组织、表达与交互形式时，检索并打开原始文档/设计指南，结合已知阅读习惯写出“采用规则、为什么适配、没采用的限制、实际验证”。普通内容更新复用已核查的规则与来源，只补新格式、易变事实或失效兼容性，不每次重新搜索整个互联网。用户要求联网时执行；仅用材料时遵从并注明必要缺口。

当前依据（2026-11-06核对，概括转述，不复制整篇）：

| 原始来源 | 支持的规则与本地适配 |
| --- | --- |
| [Diátaxis](https://diataxis.fr/) | 区分操作、学习、参考与解释；本规范在一篇中分清职责，不据此批量造目录 |
| [Google：编写操作步骤](https://developers.google.com/style/procedures) | 先交代操作位置、给可完成任务的步骤；等效时选短路线，其他方式分开 |
| [GOV.UK：Details](https://design-system.service.gov.uk/components/details/) | 折叠用于部分读者才需的补充，不隐藏多数读者必看内容；每步关键解释外露，详解可展开 |
| [NN/G：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | 主层呈现常用内容，次层呈现更多细节；清楚标注展开内容，不追求多层折叠 |

这些指南不直接证明某用户学习更快、某阅读器可折叠或某命令运行成功；用户明确的阅读偏好与领域真实验证优先。

2026-11-12 全链路写法根据实际试读反馈采用：逐步详解已有，但读者仍需自行拼接全程；经修订示范获用户认可后，补充首尾全链、逐模块定位与交接。它是对应多环节文档的阅读偏好，不是研究证明所有短回答都应重复地图。

## 交付检查

逐个主要步骤和概念模块检查：是否有对应解析、是否区分执行位置和前后关系、类比是否准确；不得靠标题或“已加小白版”的自述代替正文。

对多环节文档，先查首尾完整主链、每个实质模块的全图/位置/贡献，再沿同一例子检查隐藏前提、首用术语、准备顺序、真实交接和分支结果；不能只数箭头或收纳框。关闭重复地图和详解后正文仍应接得上，展开后才能查到完整细节；从旧文迁移时核对原步骤、参数、限制和证据是否仍有明确位置。

文字结构、技术内容、页面交互、实际操作和真实学习效果分别记录。独立代理可走查材料中的断链与歧义，不能充当真人首次学习测试。真实试读可保留一条原始复述与一道变式题，缺数据就标未测，不承诺只读一遍或节约百分比。

用“只看主线能否做成”和“展开后能否解释为什么”两种方式审读。覆盖首次配置与日常复用、密码/密钥或其他可选分支；跳过可选步骤后，必需配置仍须存在。比较精简前后是否保持持久性、作用范围与验收。分别记录事实正确性、操作有效性和目标阅读器呈现；静态格式检查不冒充学习效果或业务测试。
