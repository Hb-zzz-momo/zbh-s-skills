# 黑客松推文与参赛须知总控

共用一份事实依据，分别服务“潜在选手是否参加”和“已报名选手如何完成比赛”。本Skill负责14阶段的选择、衔接与验收；[publicity-content-workflow-zh](../publicity-content-workflow-zh/SKILL.md)负责通用事实、文稿和载体方法，[活动手册检查](../publicity-content-workflow-zh/references/event-handbook.md)提供领域细查。进入通用能力后直接执行所需步骤，不从其入口再次回调本总控。

## 先分支再加载

从现有资料提取目标、当前活动阶段、受众、权威输入和要交付的真实载体；仅追问会影响执行的缺口，不让用户重复填表。按需读[14阶段表](references/stage-map.md)：

| 任务 | 执行范围 |
| --- | --- |
| 从零写推文/须知，或多材料对齐 | S01—S14；S07推文、S08手册按实际交付选择，不强制同时写两稿；无参考时S05记不适用 |
| 借用其他城市格式重组手册 | S01—S06、S08—S14；逐条保留本地有效信息，不扩大成推文改写 |
| 仅校对官网与当前文稿 | S01—S03、S09、S11；输出具体位置/依据/影响/建议；用户未要求修订时不改文件 |
| 指定页眉、时间或段落的局改 | S02确认当前源与范围、S14定点修改及受影响显示核查；涉及事实变化才回S03/S09/S11，不启动整套写作 |

源不可读时说明读取缺口，先完成不依赖它的部分；不能按文件名猜当前版本。默认只输出本轮指定载体，日期、人数、赛道/天数、奖励和服务全部参数化，不搬用历史活动常量。

## 阶段衔接与关键门槛

1. **S01—S06：输入与结构。** 定用途、冻结来源、统一事实并补齐选手行动路径；参考只借结构，用旧条款→新章节映射检查保留情况，再冻结各模块必提点。用户明确的信息是依据，外地范文不是本地承诺。
2. **S07/S08—S09：写作与语义。** 推文讲参与价值和下一步，手册按参赛顺序讲动作/规则；保持整稿连贯。先审奖励单位及条件范围、排名集合、个人参赛口径、时态与品牌名称，再进入排版。不得用“以通知为准”代替已知规则或掩盖关键冲突。
3. **S10—S12：载体、一致性与独立评审。** 对照本轮授权的官网/表单/通知与文稿，记录字段及具体章节、条款、表格行/页眉位置。确定错误、来源冲突、待确认和样式建议分开；关键冲突未解阻断相应确定表述。内容稳定后冻结候选和实际预览，再由真实独立读者检查并闭环修订；机械小改不额外造评分。
4. **S13—S14：真实交付与后续变更。** 核对最终交付与验收为同一版本；区分本地文件、云端创建/写入、链接可访问和已发布。变更绑定事项与影响范围，检查该改的已改及其他内容保持；保留未同步项、原因未知和未验证层级。

## 按阶段使用能力

- 事实/撰写/手册细查：复用通用宣传Skill及其模板，不再生成第二份事实母版。
- 当前网页、登录页或云文档：在实际需要时使用可用浏览器/连接工具，核验读取范围与权限。没有真实写入/回读证据就不能称飞书等云文档已完成；需要登录时保留本地候选并准确说明待完成项。
- DOCX/PDF：按实际载体调用可用的文档/PDF技能，检查正文、表格、页眉及真实分页；Markdown不能代替Word显示验收。需要桌面交互时按当前观察操作，失败原文和根因判断分开。
- 质量评审：复用 `multi-agent-evaluation-zh`，普通完整交付至少作者与真实独立评审；正式发布仍需用户授权。文案任务不自动发消息、发布或改官网。
- 多阶段任务：复用已有三层记忆/`automation-error-learning-zh`锚点，在事实变化、结构冻结、候选验收和交付处记录检查点；不递归重启或另建同义日志。

每阶段只加载当时需要的能力。仅写作任务不启动网站开发、运营布场或整套工程流程。

## 交付与验收

完整任务交付本轮要求的整稿/文件，以及必要的事实冲突、旧新映射、交叉校对、独立修订与完成状态记录；复用已有记录，不为凑表重复造文件。局改仅记录当前源标识、允许改动、实际差异和受影响检查。

读者应能找到参与资格、报名/咨询入口、关键签到义务、提交事项和评审条件；缺项写明，不编造账号、供餐覆盖、住宿或处罚。格式参考不得带入外地事实，获奖条件不得扩展到其他奖励或赛道。

收尾直接给一段本次经验/流程沉淀总结及可学习点，说明哪些做法已采用、哪些只是候选、哪里尚未验证。Skill已创建、隔离用例通过、真实业务/发布完成和长期效果分别表述。行为用例见[evals/evals.json](evals/evals.json)，用例数据仅用于隔离模拟。
