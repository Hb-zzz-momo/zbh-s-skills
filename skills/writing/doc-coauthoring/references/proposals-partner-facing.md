# 面向合作方的策划案

当文档内容是赛事、活动或项目策划案，且主要读者包含高校、赞助方、资金或场地支持单位、协办方时，使用本参考。

## 先锁定合作决策

起草前确认：

- 读者需要决定参与、出资、提供资源、审批还是签约。
- 读者需要由谁在何时确认什么，以及通过哪个联系人反馈。
- 不同合作方可获得什么、需要投入什么、明确不承担什么。
- 哪些名称、金额、日期、权益和规则已经确认，哪些仍待书面确认。
- 文档是沟通稿、内部执行稿、正式规则还是合同附件；不得混用承诺强度。

缺少关键事实时保留明确的待确认项，不猜测金额、权益、名次、授权或责任。

## 按受众排序信息

| 读者 | 优先回答 |
| --- | --- |
| 高校 | 为什么值得参与；需要组织什么；学生获得什么；是否承担审核、评审、争议处理或费用。 |
| 赞助或支持单位 | 赛事规模与时间；投入金额、场地和资源；品牌展示；成果反馈；是否参与评审或取得作品权利。 |
| 协办或执行方 | 责任边界、时间节点、交付物、审批链、异常处理和联络机制。 |
| 参赛者 | 资格、技术与内容要求、提交材料、评审、奖项、版权、申诉和数据处理。 |

同一文档面向多类读者时，先给合作方摘要，再按角色拆分责任；不要让读者从参赛细则中反推合作条件。
合作沟通稿正文只保留影响合作决策的规则；详细参赛细则进入附件或《参赛手册》。

## 使用“总结词 + 短正文”

- 每个段落先用粗体短语给结论，再用一至两句解释原因或动作。
- 每条只表达一个决定、要求、责任或风险。
- 用动词开头：确认、提供、组织、审核、提交、公布、复核。
- 用数字替代模糊程度词：队伍数、日期、时点、金额、比例、名额和页数。
- 把长说明拆成清单；把重复字段、角色映射和时间阶段改成表格。
- 将例外、递补、资格取消和未确认事项放入独立提示块，不埋在正文中。

## 推荐结构

1. 标题与文档状态：年份、名称、版本、日期、主办方和适用对象。
2. 合作方摘要：一句定位、规模、时间、资金、成果和需要对方决定的事项。
3. 项目目的：技术、教育、生态、社会或传播价值，每项使用“总结词 + 短正文”。
4. 项目概况与形式：对象、周期、线上线下形式、组队或参与方式。
5. 合作价值与边界：按高校、赞助方、协办方分别列价值、投入和不承担事项。
6. 内容、技术与提交要求：只保留可审核、可执行的标准。
7. 流程与赛程：按阶段列时间、责任主体、核心动作和产物。
8. 评审与奖励：写明评分来源、权重、奖项、叠加、递补和取消资格规则。
9. 资金与资源：资金来源、技术支持、场地、宣传、物料和预算口径。
10. 风险预案：使用“风险 + 触发条件 + 应对措施 + 责任人”。
11. 组织机构：区分主办、承办、协办、赞助、合作和最终审批责任。
12. 待确认事项与权利说明：集中列出未定信息、作品权利、宣传授权、隐私与数据保存。

不要求机械保留全部章节；删除对当前读者无决策价值且不会影响执行或风险判断的内容。

## 版式规则

- 优先使用 A4 单栏和克制的黑白灰视觉；合作沟通稿以 4—8 页为参考，不以压缩页数牺牲可读性。
- 使用一个主标题、编号一级章节、数字二级条目和圆点细项，避免超过三级层级。
- 用水平分隔线、留白和一致间距区分一级章节。
- 使用粗体突出结论、角色、比例和动作，不连续加粗整段。
- 保留页眉中的文档名与日期、页脚页码；特殊规则使用统一提示框。
- 控制段落在三行以内；超过三行时判断能否改成清单或表格。
- 让第一页完成 30 秒扫描：读者能找到目的、规模、时间、投入、回报、责任边界、待确认事项和下一步联系人。

## 表达与承诺门禁

- 区分“目标”“计划”“原则上”“待确认”和“正式承诺”。
- 不把拟邀单位写成已确认单位，不把传播场景写成量化曝光承诺。
- 不因赞助或场地支持默认授予作品版权、源代码使用权或独家运营权。
- 不将“原创”写成禁止合法使用开源组件或授权素材；分别说明原创内容、允许复用和来源披露。
- 同步核对奖金合计、评分权重、日期顺序、名额乘法、角色职责和授权范围。
- 策划案可以列待确认项；正式规则或合同不得留下影响资格、金额、责任或权利的未决项。

## 交付审计

- 陌生高校读者能否在一分钟内说出参与价值、投入和责任边界。
- 陌生赞助方能否说出资金或资源用途、展示场景、成果反馈和权利边界。
- 每个金额、日期、比例、名额和单位状态是否有来源或明确标为待确认。
- 摘要与正文是否一致，角色之间是否存在审批、评审或版权冲突。
- 是否删除空泛口号、重复定义、无动作主体的句子和不影响决策的背景。
