# 活动推文与参赛须知检查

仅处理当前活动已确认的事实。下列是检查问题，不是可直接写入正文的承诺；内容缺失先记录缺口，不补造规则。

## 1. 事实与变更

- 将官网、组织者确认、当前手册逐项对照；登记来源位置、获取时间、适用活动/赛道、冲突与确认依据。外地手册只作结构参考。
- 日期必须绑定事项，例如报名、组队、最终提交；替换某日截止时间不能顺带替换其他事项的同一时刻。先列命中位置，再核对实际改动。
- 奖励分别写清现金、算力/Token、实物的单位与口径；条件贴近对应奖励。名次必须写明比较范围，例如某工具参赛作品内排名，不能推成所有等级奖前三名。
- 区分旧错误、新安排、尚未确认与排版建议。对未解决的关键冲突保留两边证据并阻断相应确定表述，不用“以通知为准”掩盖已经明确的规则。

## 2. 内容完整与阅读顺序

推文先回答活动是什么、适合谁、能做什么、何时何地、如何报名；已报名者手册按实际参与顺序组织。按活动需要检查以下内容，不强求每项独立成章：

| 读者问题 | 应核对的信息 |
| --- | --- |
| 我能否参加？ | 对象、个人报名与个人独立参赛是否均允许、组队方式与人数限制 |
| 到哪里获取消息？ | 官网、报名入口、进群途径、咨询联系人；显示名不能替代未经确认的账号或二维码 |
| 何时到场做什么？ | 日期、签到、启动仪式、开发、休息、提交、路演与结束；全员到场义务须有组织者依据，并写在相应签到条款旁 |
| 要交什么？ | 材料清单、格式、入口、截止时间、演示要求及已确认的逾期规则 |
| 怎样评审和获奖？ | 评审流程与公布状态、奖项、资格条件、名次比较范围及有效票/名额顺延规则 |
| 在现场如何安排？ | 餐券适用范围与兑换、茶歇、住宿/留场/交通、网络与用电、插板与自备设备；只写已确认的服务，不从“提供餐券”推断包全部餐次 |

重组时逐条映射原文；合并重复项也记录去向。无对应位置的原条款先查原因，不能为简洁删除规则、联系方式或操作细节。不要把工作人员布场流程写成选手任务。

## 3. 定点修改与载体验收

1. 定位用户本次指定的源文件；记录路径、版本/摘要及修改范围。若源文件在编辑期间变化，先核对变化再继续，不能覆盖并行修改。
2. 只修改获准项及其直接引用；名称检查覆盖指定的标题、正文或页眉范围，不据“改页眉”擅自改文件名、正文和其他载体。
3. 用实际内容差异核对改动，检查正文、表格和页眉等相关位置；保留字体、样式与链接。另存新版本时说明新旧关系。
4. DOCX/网页检查真实显示：标题断行、页眉、表格跨页、页面大块空白及链接；合理留白不等于必须填满。Markdown检查层级、表格、链接和占位文本，不能把MD检查当Word分页验收。
5. 交付时分别说明内容核对、版式检查、本地保存、云端写入和发布的实际状态。导出或渲染失败保留原错误；替代路径成功不能写成原故障已修复。

## 4. 读者验证

完整手册由独立读者在不依赖作者口头解释的情况下，找出报名入口、关键到场义务、提交事项及奖励条件；有歧义时定位原句并修订。仅做局部机械修改时执行差异与版式核对，不因此重新启动整套内容评审。

数量、天数、赛道及服务清单按当前活动增减。案例结论不能代替当前核验，也不能为强调义务自行新增处罚。
