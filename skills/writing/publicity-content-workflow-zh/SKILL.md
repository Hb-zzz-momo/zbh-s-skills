# 多载体宣传内容工作流

目标顺序固定为：**事实可信 → 内容有逻辑 → 载体可读 → 版式稳定 → 发布可追溯**。吸引力、模板和视觉优化不得覆盖事实边界。

## 启动门禁

先确定本次范围；从已有材料提取信息，只有影响执行的缺口才询问，不要求用户重复填表。

- **从零撰写**：明确载体、受众、用途、截止时间与交付形式，执行完整流程；没有事实材料时只整理框架与资料缺口。
- **结构重组**：冻结原文，建立“原条款→新章节”映射后重排；模板只借结构，保留本地有效信息。
- **局部修改**：冻结用户指定的当前文件与目标位置，记录允许修改项，执行定点编辑、差异核对及受影响版式检查；复用已有事实记录，不重写全文、不强制重新调研全部事项或派生其他格式。文字机械替换不额外虚构评分。

活动推文与参赛须知按需读 [活动手册检查](references/event-handbook.md)；用户只改页眉时，只取其中的修改范围与名称检查。日期、金额、人数及赛道数量均来自当前事实，不能套用历史案例常量。

## 主流程

1. **核验事实**：逐条登记时间、地点、人物、事项、过程、结果、数据和引用。每条登记来源、来源位置、发布主体/确认人、发布时间/确认时间、获取时间和状态；未提供的字段如实标未知，不虚构确认。公开来源可按其发布主体与时间核验，不强求不存在的个人确认人。
2. **冻结事实母版**：事实核验后记录版本号、来源时间与适用范围；冻结后的新确认进入变更记录，复验受影响内容。新网页与旧文档冲突时核对发布主体和生效依据，不仅凭更新时间选权威。
3. **定内容逻辑**：先写“受众问题 → 核心信息 → 发生了什么 → 为什么重要 → 结果 → 行动号召”，再列正文必备点和证据位置。
4. **选模板和格式**：模板只决定容器与视觉，不决定事实和逻辑。每种载体单独规定标题层级、字体字号、字重颜色、行距段距、表格、图片、留白、对齐、断行、尺寸适配和禁止项。
5. **填写与适配**：所有载体共用事实母版，分别调整信息密度、标题、正文、二维码、联系方式和行动号召。不得把同一段长文硬塞进海报或易拉宝。
6. **处理不确定性**：关键事实未确认即 `BLOCK`；非关键信息只能标“待确认”并进入文末清单；删除无依据的推测、评价和无法证实的结果。有明确来源的评价/引语按原意归属并核对授权，不冒充客观事实。禁止用模糊措辞制造确定性。
7. **合规检查**：核对版权、图片授权、肖像、隐私、商标、引用、敏感信息、二维码和联系方式。缺证据时阻断发布。
8. **真实渲染检查**：按最终尺寸检查文字溢出、裁切、低对比度、图片变形、表格错位、断行、错字和二维码可用性。本地文件存在不等于验收通过。
9. **独立评价**：执行者、读者视角评审、事实/合规/格式评审职责分离。评审者只读并保留原始意见、证据、严重性、修订记录和复验结果；不得用作者自评覆盖未解决阻断项。
10. **最终冻结与交付**：确认交付物、验收截图和版本记录是同一版本。任何关键事实、图片、二维码、联系方式或结果变化都触发相应复验。创建本地稿不等于已写入云文档；发布、发送和覆盖云端按用户实际授权执行，未执行项如实标明。

## 必须产出

以下为完整任务的交付项；局部修订仅保留当前文件标识、修改前后、实际差异与受影响检查结果。沿用有效记录，不为表单完整重复制造文档。

- 事实母版与来源表；
- 不确定事项表；
- 内容逻辑链路和正文必备点；
- 载体矩阵与视觉规范；
- 合规检查记录；
- 独立评审、修订与复验记录；
- 最终版本号、发布物路径和验收证据。

字段、模板和发布清单见 [references/templates.md](references/templates.md)。

## 异常处理

- 来源冲突：保留各来源、差异和责任人，不自行选一个；关键事实冲突为 `BLOCK`。
- 平台格式丢失：记录平台、丢失样式和真实渲染证据，改为平台支持的等价表达。
- 评审分歧：回到事实来源和验收标准；无法解决时保留异议并维持 `CAUTION/BLOCK`。
- 发布后更正：保留原版本和更正记录，明确更正范围，不静默覆盖。
