# 项目启动规则

## 团队分工流程

1. 找几个人先读题，明确选什么题、解决什么问题、达到什么效果。
2. 搜资料，找可以复用的现成代码、论文、产品或竞品。
3. 从实际需求出发写用户侧应用方案和可行技术栈。
4. 先确定技术选型、前端设计、接口文档、数据库设计。
5. 再开始前端、后端、数据库和模型服务开发。

## 项目链路

常见项目链路：

1. 数据清洗
2. 调用封装好的核心函数
3. 错误识别和异常处理
4. 结果展示和导出

## 启动记忆闭环

项目开始时，不能只留下计划和启动命令，还要同时建立下一位 AI 可继承的记忆入口：

1. 第一层：在 `AGENTS.md` / `CLAUDE.md` / 项目根规则文件中写清启动读取顺序、项目边界、禁止事项和记忆入口路径。
2. 第二层：生成或更新一个单文件启动记忆，建议命名为 `项目启动记忆.md` 或 `docs/project-entry/项目启动记忆.md`。
3. 单文件启动记忆必须包含这些一级标题：`尝试方法`、`计划`、`脚本/命令`、`结果`、`经验`。
4. 长期比赛、科研实验、性能优化或多分支工程，必须再把单文件记忆拆入三层记忆入口：第二层保留短总览或单文件记忆桥，第三层按 `计划/`、`尝试方法/`、`脚本/`、`结果/`、`经验/` 保存完整证据。
5. 新结论如果影响下一次启动判断，必须同步回第一层读取顺序或第二层总览，不能只藏在第三层长文档里。

完成标准：新 AI 只读根规则入口和单文件启动记忆，就能知道当前项目要做什么、已试过什么、下一步怎么跑、已有结果在哪里、哪些经验必须继承。

## 三类核心封装

- 存储类：判断集合是否存在、创建集合、定义对象结构、增删改查、查询逻辑。
- 编码/模型类：数据清洗、结构清洗、核心 encoding/model/client 调用。
- 核心业务类：对接上游 API、封装不同需求的查询、下载和表格构建函数。
