## 2026-04-23 迭代 #1

- **触发反馈**：用户希望把“逐段语法解析 + 业务作用说明 + 展开写法”这种代码教学风格吸收到 `project-dev-zh`。
- **根因**：原 `模式A：代码理解` 更偏逻辑与设计层讲解，缺少面向初学者的显式语法拆解规则，导致对压缩写法和逐行代码导读支持不足。
- **修改内容**：在 `SKILL.md` 的 frontmatter 和模式判定中补充“逐行讲解/语法解释”触发词；在模式A新增“代码教学增强规则”和“代码教学输出模板”。
- **影响范围**：模式A / 代码理解 / 初学者导向讲解

## 2026-04-23 迭代 #2

- **触发反馈**：用户要求今后 `project-dev-zh` 在知识点或语法分析时，都补简单例子帮助理解。
- **根因**：仅有定义、作用和展开写法还不够直观，初学者容易“看懂文字但不会迁移”，缺少最小例子会降低吸收速度。
- **修改内容**：在模式A的“代码教学增强规则”中新增“知识点/术语/语法点都要补简单例子”的硬规则；在代码教学输出模板里为“名词速览”和“语法点”新增“简单例子”字段。
- **影响范围**：模式A / 代码理解 / 语法教学输出

## 2026-04-23 迭代 #3

- **触发反馈**：用户指出“名词速览”不应停留在宽泛定义，而应说明术语在当前函数、当前调用点或当前会话里的具体意义。
- **根因**：此前模板要求了术语解释和简单例子，但没有强制把术语绑定到本地代码语境，导致输出可能退化为通用词典释义。
- **修改内容**：在模式A的“代码教学增强规则”中新增“名词速览必须解释当前代码语境中的具体作用”的硬规则；在输出模板里把“名词速览”改为“通用含义 + 在这里的作用 + 简单例子”。
- **影响范围**：模式A / 名词速览 / 代码教学上下文解释

## 2026-07-19 迭代 #4

- **触发反馈**：用户希望知识性问题按照“一句话结论 → 生活类比 → 术语解释 → 实际状态 → 判断依据 → 更合理做法 → 最终理解”的整体逻辑回答，并以零基础用户能复述为标准。
- **根因**：原技能只在代码教学中要求局部类比和简单例子，没有覆盖 ADR、设计决策、技术概念等非代码知识问答，也没有强制区分文档规定、运行时实现、推理和评价。
- **修改内容**：扩充 frontmatter 触发词；新增模式E“知识性问题小白解析”；加入统一类比、语境化术语、数字口径、事实/推理/评价分离、证据边界、标准模板和质量自检。
- **影响范围**：技术知识问答 / ADR 与设计决策解读 / 项目证据驱动的小白解释

## 2026-07-19 迭代 #5

- **触发反馈**：用户要求在既有小白解析基础上，把工程、架构和项目知识回答改为严密逻辑链，按照“为什么需要 → 解决什么问题 → 产生什么产物 → 如何继续流转”展开，并补充依赖关系、当前优先项和延后项。
- **根因**：迭代 #4 已解决术语语境、类比和证据边界，但标准模板仍可能先讲类比与术语，再补关系，无法保证多个工程概念从同一业务主线自然推导出来。
- **修改内容**：重构模式E的标准顺序；新增业务/数据主线、四问节点、单概念精简链、术语节点化出现、产物流转、依赖与实施顺序规则；保留一句话结论、统一类比、证据分层、数字口径和最终收束。
- **影响范围**：知识性回答逻辑链 / 工程与架构概念解释 / 实施优先级判断

## 2026-07-19 迭代 #6

- **触发反馈**：用户指出 CI 回答虽然列出了 1-9 个环节，但类比出现太晚、各节缺少显式递进，读者读到中段会忘记当前位置和完整链路。
- **根因**：迭代 #5 规定了因果顺序，却没有把因果链设计成持续可见的阅读导航；编号只能表示排列，不能说明上一节产物如何成为下一节输入。
- **修改内容**：要求开头先给贯穿类比与具体实例；全文锁定同一人物、对象和动作；新增链路路标、当前位置高亮、承接上一步/本步产物/交给下一步字段，以及长链路阶段小结；重写模式E输出模板和 CI 回归样例。
- **影响范围**：知识问答开场 / 跨章节衔接 / 长链路阅读导航 / 单一实例一致性

## 2026-07-19 迭代 #7

- **触发反馈**：用户指出重复使用“承接上一步、本步解决、本步产物、交给下一步”容易退化为多组清单；节点缺少单一问题约束；主链没有删除节点测试。
- **根因**：迭代 #6 解决了阅读定位，却把内部依赖检查字段直接暴露成固定输出栏目，仍可能只有形式顺序而没有必要依赖。
- **修改内容**：将重复栏目改为一行路标加连续因果句；强制“一个当前矛盾 → 一个核心动作 → 一个核心产物 → 下一节点必要输入”；新增删除中间/终点节点测试，并把可独立删除的背景、风险、例子和扩展知识移到旁支。
- **影响范围**：主链必要性 / 节点单一职责 / 去填表化表达 / 旁支知识分流

## 2026-07-19 迭代 #8

- **触发反馈**：用户指出真实信息既可能前后依赖，也可能是共同服务于上线目标的并行条件；若 Skill 强制线性化会制造假因果，不强制又会退化成并列清单。用户同时要求整体链与模块例子之间必须显式往返。
- **根因**：迭代 #7 把“上一产物必须成为下一输入”设成通用主链标准，适合流水线说明，却无法正确表达项目状态、判断证据和并行必要条件，也会让删除节点测试误伤证据与前置条件。

- **影响范围**：知识问答关系判定 / 状态主链 / 证据归位 / 并行条件 / 局部与整体衔接 / 解决闭环
