# 普通资料的主题、用途与版本

用于新增普通资料及项目收尾；工程原生依赖、课程模板和科研证据要求继续遵守领域规则。先按真实主题归属，再决定用途和文件角色，不按生成 Skill 或一次运行分桶。

## 先确定四件事

1. **主题**：用户要找的内容，如“活动宣传”“获奖证书”。复用项目现有同职责位置，不猜测项目或新建同义根目录。
2. **用途**：同主题是否有不能互相替代的受众、场次或规格。上午场/下午场、选手版/志愿者版是并列用途，不能因日期、编号较大而相互替代。
3. **角色**：按下表放置；只在有内容时建目录。
4. **当前入口**：每个“主题＋用途＋文件角色”只保留一个明确的日常入口。Word 可编辑源稿、PDF 阅读成品和签发凭证是不同格式或证据角色，可以同时存在；须说明对应关系，不能仅凭扩展名推断同版。

| 目录 | 放什么 | 更新规则 |
| --- | --- | --- |
| `编辑稿/` | 正在维护的源稿、未确认稿及其阅读预览 | 稳定主题名更新原件；状态不明按真实情况标“待确认” |
| `发布快照/` | 有证据确认内部交付、外发或提交的具体版本 | 文件名带版本标识；内容冻结，更正另存新版本，保留交付对象/时间或提交依据 |
| `历史版本/` | 被明确替代的同用途旧稿及必要证据 | 保留原来源、被谁替代及原因；旧快照原有发布身份和证据不能抹去 |
| `制作与核对记录/` | 服务本主题的脚本、QA、渲染页、核对记录 | 最小依赖单元整件保留；不得把日常成品藏在这里 |

“发布快照”包含已确认的内部交付，不强称公开发表。仅有文件名、mtime、哈希或作者估计不足以证明发布/提交；未确认稿留编辑稿并写明缺口，不能用历史区隐藏冲突。当前入口依据内容、采用或修订证据确定，不能自动取最新修改时间。需要保留多个快照时，明确各自交付事实及当前适用版本；被替代内容归历史区，引用路径变化按迁移规则保留映射。

并列用途的快照文件名同时带具体用途和版本标识，例如 `主持稿_上午场_v1.0.pdf`，避免文件离开目录后误用。主题参数不能包含角色目录，“编辑稿”等角色名也不能冒充受众或场次；使用助手路由时分别提供主题、用途与角色。

## 最小目录示例

```text
项目根/
└─ 活动宣传/
   ├─ 编辑稿/活动介绍.docx
   ├─ 发布快照/活动介绍_2026-11-04_v1.0.pdf
   ├─ 历史版本/活动介绍_2026-11-03_v0.9.docx
   ├─ 制作与核对记录/排版核对.md
   └─ 并列用途/
      ├─ 选手版/编辑稿/参赛提醒.docx
      └─ 志愿者版/编辑稿/现场提醒.docx
```

示例各目录仅在有对应内容时创建。主题下共用内容放主题本身的角色目录；仅有并列用途时直接使用 `主题/并列用途/<具体用途>/<角色>/`。同一文件只存一个权威位置，不在共用区及各用途区复制“当前版”。并列用途不能互相进历史区。

整理完成后同样不能留下无内容、无依赖的普通空目录。完整核对子树、隐藏项、零字节文件、现行引用和云端状态；顶层没有文件不等于整树为空。已获授权的旧分类空壳、空制作记录和空的恢复结构，用 `artifact-curator-zh` 的 `scripts/empty_directories.py` 按冻结清单逐个清理，路径账本保留结构信息，不再另存整棵空目录或填占位文件凑非空。工程依赖、运行时约定和真实备份明确保护；无法读取、链接或云端占位状态列未知，不算空，也不声称整个项目已清零。详见该技能的 `references/empty-directories.md`。

优先压缩重复层级；单文件不为凑模板新造版本表。普通小文档用已有 README 中几行说明当前入口、差别和来源即可。确有并列用途时多一层有实际作用，不机械压平；不能把“最多三层”作为删掉用途或角色的理由。已有清晰的等价目录延续，不为套示例整库改名。

## 新增、复核和迁移

- 新增或更新：查所属主题、同用途现有文件及入口，核目标碰撞、文件名和完整路径，再更新受影响的导航/说明。路径已唯一的小改不重跑全项目脚手架或全量盘点；已有 manifest 仍必须有效。
- 迁移或删除：读取全部受影响成员、引用和依赖，冻结旧→新映射及指纹后执行，不把“增量维护”当成略过完整受影响集合核对的理由。
- 完整路径预检须包含项目根，并报告 Windows UTF-16 长度。`>=240` 仅是保守提示阈值，不是 WPS 官方限制；路径通过不证明 WPS 能打开或云端同步完成，需要时分别实测。
- 恢复备份不参与工作目录自动去重。真正独立的备份按已有真实授权另做轮换；同一同步树中的副本不能声称独立恢复备份，不为“安全”再复制一整套工作目录。
- 验收应包含“新文件放哪里、继续编辑哪个源稿、查已确认交付版本、区分并列用途”等真实找文件任务；实际归位优先，不能靠 README 几十条链接掩盖混放。
