# 更新与跨电脑接班

启动：确认项目与身份 → 根规则、manifest、总览 → verify-sync → 按任务检索 → 回读原件和当前环境。

多阶段执行：背景恢复后接入反思Skill，复用同一事件入口和写入者；重要纠正/取舍/失败/有效做法先留最小证据，阶段时再提炼，不复制第二套日志。只读了解背景不因此转为维护。

阶段收工：按事件索引核漏 → 绑定稳定来源 → 有依据地替代同一当前事实/关联候选 → 更新总览和缺口 → 分别check structure/content/evidence → 一致批次seal → verify-sync。snapshot/handoff分开判定，旧接班观察不复用于新snapshot。保留原档案与既有evidence，用指针接入；问答文章不能代替当前状态更新。详情见[持续沉淀映射](continuous-learning.md)。

旧 seal 不一致时先查差异，区分本机修改、同步中与冲突；不能直接生成新 seal 消除报错。seal 覆盖记忆目录、根规则及已存在的引用来源，成员集合不随生效时钟变化；evidence 另查来源与事实绑定。它防意外半同步，不是签名认证或整个实验环境快照。

当前执行批次的预期写入也会让旧seal不一致，此时retrieve阻断是正常保护；按已知原件只读核对并完成该批次，不为每次召回自动重seal。中断后未知差异仍按上段排查，不因需要继续工作就信任未核验记录。

两台 WPS 电脑轮流写；收工一方确认同步完成后另一方接班，核对快照和来源文件。双方并发时保留冲突副本，按来源、范围和生效时间合并，不能按文件时间覆盖。本机锁不是分布式锁。

Skill 仓库只同步方法；个人记忆、身份、报告与日志使用 WPS 或用户指定私有存储，不进入公开 Skill 仓库。机器路径、依赖、内核、字体重新探测。

迁移 v1：保留已有根规则与总览，init 补 manifest/records/index，逐项提炼有证据记录。拆分入口修改 manifest.overviews 与读序即可；project_id 不随目录名改变。

更新 seal 后旧接班观察按 snapshot_id 失效，需重新验证；内容未变化的 seal 仍可使用同批次观察。
