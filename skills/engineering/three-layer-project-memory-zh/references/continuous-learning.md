# 持续沉淀与三层记忆的适配

复用 `automation-error-learning-zh` 的事件捕获、阶段提炼和Skill优化方法；本页只规定它怎样使用三层记忆。CLI与记录schema保持v2，不新增后台触发器，也不假定宿主提供压缩前回调。

## 一处来源、两类职责

| 位置/能力 | 保存什么 | 不承担什么 |
| --- | --- | --- |
| 第一层根规则 | 现有稳定约束和读取入口 | 不因单次错误自动改全局指令/AGENTS |
| 第二层当前总览 | 当前任务/阶段、采用Skill版本、事件/工作项入口、候选与未闭环ID、下一步 | 不复制全部原始过程，不用精简总览删除历史 |
| 第三层原件、records与来源回执 | 事件证据、尝试与否决理由、记录版本、项目经验和方法采用/验证回执 | 不复制整份公共Skill作为另一套权威 |
| 反思Skill | 按依据筛选经验、增量维护对应通用/专用Skill、输出可学习总结 | 不再建同义日志，不扩大记忆写入授权，不回调前置检索/初始化 |

项目原记录存在时追加其检查点和事件索引，records只用摘要/ID和来源定位接入；一个事件不必一张经验卡。没有项目记忆且用户只要求背景了解时，用当前材料说明缺口，不为接入反思自动init。

## 用既有记录表达过程

| 内容 | 既有类型与关联 | 状态/边界 |
| --- | --- | --- |
| 当前目标、阶段、采用的Skill版本 | task/decision；summary说明版本/步骤，来源为实际采用回执 | 只确认有依据的采用，不等于方法已有效 |
| 用户纠正或实际取舍 | decision；同一当前规则key，核验后新id显式supersedes | 保留被替代规则与原授权，不能用助手建议替代用户决定 |
| 失败、恢复、尝试和否决理由 | episode；不同尝试事实用不同key；related_ids连接同事件 | “事件已发生”可confirmed，原因仍未知时必须在摘要中保留未知 |
| 候选经验与未运行改法 | procedure pending，关联episode及提案 | 默认retrieve不返回；总览列ID，阶段时按ID读，不冒充现行方法 |
| 已应用方法和验证回执 | 新procedure/episode，以sources和related_ids连接提案、事件、测试 | confirmed只表示该来源支持的应用/观察，适用条件与未验证层级写进summary |

**逻辑event_id不等于record id。** 同一事件可多次追加回执，但put不允许覆盖id。同事件的不同尝试用不同事实key关联；只有确实替代同一当前状态时用同key和supersedes，不能把每次重试都写成同key的并存confirmed事实。

候选成熟时新增有来源的记录，用related_ids关联原pending；需要退役候选时用status archived并附原因，不把pending直接改成confirmed，也不将未核验pending强行supersede成已核验历史。公共Skill名称/版本/步骤与私有案例的关系可写在本地采用回执中；不往sources塞越界绝对路径，不新增CLI未支持的必填字段。

## 来源与阶段批次

confirmed记录绑定可核对的稳定原件；持续追加的日志整体哈希会变化，不能直接作为许多历史confirmed记录的永久来源。必要时在既有evidence/档案位置保存该事件的最小稳定摘录，注明原位置、观察时间和范围，再绑定相对路径与哈希；日志保留导航。不批量刷新旧hash伪装证据未变，不复制整批材料。

1. 事件发生时保存必要证据与最小候选；阶段内由一个写入者追加records和检查点。候选、来源缺口和未运行改法明确标记，不能将每次事件视为完整接班批次。
2. 阶段结束逐项核对事件去向，更新总览/历史覆盖指针，再检查structure、content、evidence。BLOCK先修；CAUTION保留原因和pending状态，不美化为全通过。
3. 一致批次才能seal，再verify-sync；这只支持本机完整性。新snapshot使旧handoff观察失效，需要接班验收时另测；不要求每条事件都重做完整接班。
4. 已写但未封存或中断时，先只读核差异、证据和写入顺序；retrieve的BLOCK保持。确认是本批预期变更并补齐检查后，才生成新seal，不能用重seal消除不明差异。记录不可写时报告未落盘/恢复缺口，不改权限或无限记录自身错误。

Skill方法已改但采用回执/记忆批次未更新，或反过来，都报partial，列出完成与待补项。写入前核对版本；并行Skill修改保留双方差异。公共Git只同步本轮通用Skill增量，私有记忆/来源/案例不随之上传。

## 恢复和收尾

读取顺序为当前人类要求与根规则→manifest/批次→总览中的检查点和相关ID→records→必要原件与当前对象。按事件索引核对用户纠正、失败/放弃、规则替代、候选去向和Skill变化；默认召回为空不代表历史或候选不存在。缺指针/原件时标未核实，不根据摘要补造根因。

只读恢复不触发写操作，用户要求维护时才更新获准存储。多阶段主任务中的记录按现有授权执行。最后按反思Skill给一段经验/流程总结和可学习点，分开“已记”“已改方法”“已应用”“验证范围”和未闭环项。
