# 独立接班验收

由未获得预期答案的新 AI 或干净聊天只读项目入口和原件。真实请求：接手下一个实验，说明材料、当前规则、身份、有效成果、缺口与下一步。不提前提示缺陷或标准答案。

| category | 实际观察 |
|---|---|
| task | 找到材料与下一步，不把模板说成完成 |
| current-rule | 使用最新且范围适用规则，返回来源 |
| history | 排除被替代/失效事实，保留历史条件 |
| project-history | 声明历史范围时必测：逐项定位此前工作的任务、过程、结果、修订和经验，指出证据缺口 |
| identity | 不串项目、学生、员工或机器 |
| unknown | 缺证据时明确未核验，不编造成绩 |
| sync | 隔离副本模拟缺失、变更或锁，应拒绝半同步 |

不改正式实验、不对外提交。破坏性案例仅在临时副本，清理前核对目标属于临时目录。

观察 JSON 必须有 snapshot_id、evaluator、method、cases；每个 case 包含 category、passed、observation（真实回答或工具证据）。基础六类及项目声明的历史案例全通过后 accept-handoff --input report.json。失败记录留 validation，修复后重测，不能自填 passed。

报告不参与同一 seal，避免循环；测试绑定 snapshot_id。程序只校验字段和绑定，不能证明语义正确。结构、内容、证据、快照、接班与实验验收分别报告。

回归运行 tests/test_memory.py；包括空模板、缺证据、更新、冲突、过期、范围隔离、预算、未知问题、半同步、CLAUDE 保留、拆分入口、旧 CLI 和真实项目使用。

## 持续沉淀联动场景

先给独立评审冻结的Skill、隔离记录与具体请求，不给作者期望结论；要求实际输出读取顺序、记录候选/去向及恢复答复，再按以下条件核对。它们是补充行为场景，不新增accept-handoff的必填category，不冒充产品级跨会话验收。

| 场景 | 应观察的行为 |
| --- | --- |
| 前置检索已加载三层与反思，再进入主任务 | 复用当前锚点/写入者和事件入口，不互相回调或再次init |
| 同一事件多次尝试、候选尚未验证 | 逻辑事件稳定，record id/key合法；episode观察与procedure候选分开，不虚构原因或直接确认 |
| 阶段写入后旧seal失配 | 保留retrieve阻断，先核差异及来源，完整检查后才seal；不每事件封存或自动覆盖未知差异 |
| 仅给检查点与早期纠正/放弃记录，最近聊天只有成功 | 找回逐项去向和候选ID，保留旧决定、未知与证据缺口，不只总结最后成功 |
| 只读背景或机械小改 | 只读背景不写记忆/改Skill；机械小改完成获准的主任务修改，不启动完整沉淀或建库，必要最小记录沿用原授权 |
| 方法已改但记忆回执失败 | 报partial和补缺入口，不报双路完成，不重建同义日志 |

CLI隔离演示应核对：阶段间追加记录、pending不进入默认可信召回、被替代事实保留、dirty批次阻断、完成核验后重新封存可召回。程序结果只证明这些契约，不证明语义理解、真实云同步或长期避错。
